# 多套独立运行

每套是一个调用 `gateway.Run` 的应用进程，加一个独立 core 进程。程序可以用同一个编译产物启动多次；每个进程只调用一次 Run，不需要新的实例管理 API。

## 隔离配置

| 配置 | 第一套 | 第二套 |
| --- | --- | --- |
| `CoreAddress` | `127.0.0.1:8088` | `127.0.0.1:8188` |
| `Core.LoginAddress` | `127.0.0.1:8086` | `127.0.0.1:8186` |
| `Core.DataDir` | 账号 A 已有的固定绝对路径 | 账号 B 独立的固定绝对路径 |
| `DataDir` | 第一套 gateway 缓存 | 第二套 gateway 缓存 |
| `PluginsDir` | 第一套插件与配置 | 第二套插件与配置 |
| `Core.CacheDir` | 第一套下载缓存 | 第二套下载缓存 |

端口已可配置，8086/8088 只是默认值。不同程序自己的 HTTP 管理页面（如果有）也需使用不同端口。设备名称是显示配置，不是账号隔离标识。
已有账号继续使用原目录；只为新账号新建目录。不要复制另一账号的设备/会话文件，也不要同时启动两个 core 使用同一目录。

## 让自己的程序接受配置路径

放在开发者自己的 Go 项目中（we-clay 本身仍是库）：

```go
package main

import (
    "context"
    "flag"
    "log"
    "os"
    "os/signal"
    "syscall"

    "github.com/we-clay/we-clay/gateway"
)

func main() {
    path := flag.String("config", "", "本套程序的 TOML 配置路径")
    flag.Parse()
    cfg, err := gateway.LoadConfig(*path)
    if err != nil { log.Fatal(err) }
    ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
    defer stop()
    err = gateway.Run(ctx, cfg, gateway.WithoutPlugins(), gateway.WithHandlers(gateway.Handlers{
        OnReady: func(ctx context.Context, client *gateway.Client) error {
            log.Println("本套微信已就绪")
            return nil
        },
    }))
    if err != nil { log.Fatal(err) }
}
```

## 第一套：account-a.toml

将 `/absolute/path/...` 替换为本机实际绝对路径。使用 OSS 的说明和只读凭据设置见[私有 OSS 下载](OSS下载.md)。版本必须已经完成发布。

```toml
core_address = "127.0.0.1:8088"
core_token_env = "-" # 独立托管模式为每套生成自己的本机 API 令牌
data_dir = "/absolute/path/account-a/gateway/data"
plugins_dir = "/absolute/path/account-a/gateway/plugins"

[core]
version = "v0.3.3"
keep_alive = true
data_dir = "/absolute/path/existing/account-a/core"
cache_dir = "/absolute/path/account-a/core-bin"
login_address = "127.0.0.1:8086"
# device_name = "机器人 A" # 可选；改变运行中 core 的名称需显式重启

[core.oss]
bucket = "weclay"
region = "cn-beijing"
prefix = "core"
```

## 第二套：account-b.toml

```toml
core_address = "127.0.0.1:8188"
core_token_env = "-"
data_dir = "/absolute/path/account-b/gateway/data"
plugins_dir = "/absolute/path/account-b/gateway/plugins"

[core]
version = "v0.3.3"
keep_alive = true
data_dir = "/absolute/path/account-b/core"
cache_dir = "/absolute/path/account-b/core-bin"
login_address = "127.0.0.1:8186"

[core.oss]
bucket = "weclay"
region = "cn-beijing"
prefix = "core"
```

分别在两个终端启动同一个程序：

```sh
./my-bot -config /absolute/path/account-a.toml
```

```sh
./my-bot -config /absolute/path/account-b.toml
```

分别打开 `http://127.0.0.1:8086` 和 `http://127.0.0.1:8186` 登录对应账号。私有 OSS 凭据只用于下载；本机 API 访问令牌与 OSS 凭据、微信会话均不同。

## 停止与复用

- `KeepAlive: true`：关闭某套应用只断开该套 gateway，core 继续运行；下次使用相同配置复用原进程。
- 要停止 core，使用该套完整配置调用 `gateway.StopCore(ctx, cfg)`；不影响另一套。
- 已有 core 运行时改变版本、下载源或端口，须先用原配置 StopCore，再以新配置启动；数据目录保持原值。
- 使用独立插件时移除 `WithoutPlugins()`，各套 `PluginsDir` 及配置分开。核心消息订阅同一 core 只允许一个消费者。
- 配置文件、运行目录、进程记录和凭据仅保存在本地，不提交 Git。

## 多套运行的授权 Key（we-clay v0.7.0 / core v0.4.0 起）

使用带在线授权的新 core 时，每套配置可指定不同 `Core.AuthKeyEnv`（TOML `core.auth_key_env`），名称指向各自的私有环境变量；默认都读取 `WE_CLAY_AUTH_KEY`。同一个 Key 的并发 core 数不能超过服务端设置。更换运行中的 Key 要先 StopCore 再 Run，保留账号目录。详见[运行授权](运行授权.md)。
