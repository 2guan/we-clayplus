# 附件上传与大小配置

「系统设置 → 附件与传输 → 单个文件大小上限」控制普通文件的上层限制，默认 500 MB，可设置 1–1024 MB 的整数，保存后生效。这里沿用界面 MB 标记，实际按 MiB（1024 × 1024 字节）计算。已有部署自动补入默认值。

**本次只完成上层改造，core 未修改或重启。当前真实文件发送链路仍最多 32 MiB。500 MiB 是上层配置和上传处理能力，不代表当前可以通过微信发送 500 MiB 文件。** 超出底层支持范围时，已知大小的文件在接收正文前拒绝；不调用发送接口、不生成虚假的成功记录。完整大文件发送需要后续独立 core 和传输链路适配。

## 上传方式

- 一次最多选择 8 个附件。图片保持 16 MiB 上限，普通文件按附件设置校验；语音、模型媒体输入和朋友圈图片沿用独立限制。
- 16 MiB 以内保留兼容 JSON 接口；超过 16 MiB 的普通文件经 `POST /api/attachments/send` 二进制请求体直接写入临时文件，文件名和会话通过参数传递，不把文件转换成 Base64。
- 新入口复用控制台登录、同源与会话校验，拒绝空文件、非法文件名、超限、未完整上传及账号切换；没有声明大小的请求也执行读取上限。
- 同一时刻只接收一个大附件；同一批中的大附件按顺序提交，不锁住普通文字发送。其他并发文件请求会明确提示稍后再试。
- 上传最长 30 分钟；中断和超限清除临时文件，不发送半成品。临时文件权限为 0600，完整文件原子移动到受保护媒体目录。

## 发送与重发

完整上传不等于微信发送成功。发送前重新检查配置、账号、会话和底层大小限制；只有有效服务端消息 ID 才标记成功。保留原始 client_id / original_client_id、发送时间和账号，不伪造撤回回执。未知发送不会自动重试。

普通文件重发直接打开可信归档指向的本地文件，不重新编码成 Base64，也不从浏览器接收替换正文或任意文件路径。重发重新检查当前配置与底层大小限制；配置调低后，旧大附件也会被拒绝。已发送或状态未知附件的引用受缓存清理保护。

## 验证边界

离线测试覆盖恰好 500 MiB 的流式写入与大小边界、设置校验、未知长度超限、上传中断、临时文件清理、旧 JSON 入口限制、底层拒绝、真实回执字段传递和取消。Mock 的 500 MiB 成功只证明上层路径；不作为真实 core / 微信大文件验收。没有执行真实账号写入测试。
