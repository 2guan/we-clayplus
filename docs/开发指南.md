# 开发与验证

## 模块边界

- 根目录唯一 go.mod：`github.com/we-clay/we-clay`。
- `gateway/`、`sdk/` 平行放置，示例和生成代码属于同一模块。
- `gateway/` 是公共库入口，内部实现位于 `gateway/internal/`；仅插件教学示例含 `main`。
- SDK 不导入 gateway 实现；gateway 调用 SDK 服务端封装。
- 编译依赖中不含 core。gateway 与 core 统一使用 gRPC；公共协议由本仓库的 `sdk/corewire` 提供，core 单向依赖它。
- 文档使用中文，保留许可证和生成文件的必要原文。

## 离线检查

在仓库根目录运行：

```sh
GOWORK=off go mod tidy
GOWORK=off make test
GOWORK=off make vet
GOWORK=off make build example
```

测试包含模拟 gRPC 服务、文件分块、原始文件名、64 位消息 ID、
业务错误、事件确认、重放、重连及去重；还包含模拟 Release 下载、摘要校验、缓存复用及模拟 core 子进程的启动、登录等待、异常退出和清理。无需登录微信，不会发送真实消息。
合并后的单模块不需要本地 replace，也不需要旧 gateway/sdk 仓库在旁边。

## 重新生成接口代码

正常编译使用已提交的生成代码。修改 proto 后才需要安装生成工具。
本次生成工具版本为 protoc 7.34.1、protoc-gen-go v1.36.11、protoc-gen-go-grpc v1.6.2。

```sh
go install google.golang.org/protobuf/cmd/protoc-gen-go@v1.36.11
go install google.golang.org/grpc/cmd/protoc-gen-go-grpc@v1.6.2
make generate
```

将生成工具安装目录加入 PATH，protoc 需单独安装；也可用 `PROTOC`、`PROTOC_GEN_GO`、
`PROTOC_GEN_GO_GRPC` 指定工具的完整路径。生成脚本使用 Python 3。

- `proto/` → `sdk/`：插件 protobuf 类型及 gRPC 客户端/服务端。
- `gateway/internal/api/*.proto`（各子目录）→ 同目录 Go 类型：现有 core 参数与结果模型（由 gRPC Invoke 携带）。

若已安装 Buf，也可分别在 `proto/` 和 `gateway/internal/` 执行 `buf generate`。
修改 Go 导入路径不应改变 protobuf 的 package、字段编号、类型和 gRPC 服务名。

## 提交

运行配置留在 `runtime/`，不要将实际账号信息写入测试、注释或文档。
提交前检查暂存列表并运行 `make check-secrets`；推送前核对目标仓库与可见性。
本仓库允许公开推送，独立 core 源码仓库保持私有。
具体规则见 [敏感信息管理](../SECURITY.md)。

`proto/corewire/core.proto` → `sdk/corewire` 定义 gateway/core 协议；增加它不改变插件已有服务。
新增协议先发布本模块版本，再更新 core 的版本依赖；仓库 go.mod 中不使用本地 replace。
