# we-clay v0.10.0

本版合入 [PR #21](https://github.com/we-clay/we-clay/pull/21) 的媒体与管理接口，以及 [PR #22](https://github.com/we-clay/we-clay/pull/22) 的设备平台配置。新安装默认配套 core v0.5.0；已有安装保留已保存的 core 版本和账号目录，需要新接口时按下文显式升级 core。

## 媒体与管理接口

- 新增 `client.TranscribeVoice(ctx, msg)`，对已收到的语音请求微信原生转写；插件可调用 `sdk/message.Client.TranscribeVoice`。调用沿用原始消息回执，转写失败返回错误，不自动改用第三方 AI。每次最多等待 120 秒，取消 context 可停止后续步骤；底层单次请求仍受 core 传输超时控制。
- 新增 `client.SetDisplayName(roomID, displayName)`，修改当前账号在指定群的显示名，空字符串表示清除；插件可调用对应的新 gRPC 方法。回执缺少命令状态时补充读回确认，兼容微信清空后省略显示名字段的响应。结果未确认时不会当作成功，也不自动重试。
- 新增 `client.SendVideo(ctx, receiverID, mp4)` 与 `message.PrepareVideo`，从本机 MP4 自动读取时长、生成封面。便利入口需要本机 `ffprobe`、`ffmpeg`，最多接受 40 MiB；缺少工具、解析失败或预处理取消时不发送。原有手动提供封面和时长的发送方式继续可用。AI 视频处理复用该能力，保留原有 16 MiB、10 分钟上限。
- 接通 `CDN.UploadMomentsVideo`、`CDN.DownloadMomentsVideo`，保留完整媒体参数与下载结果；CDN 上传本身不会发布朋友圈。
- 接通 `Favor.GetItem`、`Favor.Delete` 与 core 现有批量协议，校验目标 ID、单项返回状态和不完整回执。删除结果不确定时不自动重试。
- 新增的语音转写、群内显示名、收藏单项及朋友圈视频接口暂不向模型开放自主调用。旧的 `message.Ability`、`chatroom.Ability` 实现无需新增方法；能力目录现有 131 个方法，其中 67 个已接通、64 个保留占位。

调用方式见[直接接入](../直接接入.md)和[语音转文字](../语音转文字.md)。新增接口需要包含相应路由的 core，旧 core 不会因升级 we-clay 自动获得这些能力。

## 设备平台配置

Go 配置 `CoreConfig.DeviceType`、TOML `[core].device_type`、CLI `--device-type` 和两种安装脚本统一支持 `mac`、`win`，默认仍为 `mac`，与宿主系统无关。安装器保存设备类型；后续启动、升级、停止和独立 core 复用均核对该类型，旧记录缺少类型时按 `mac` 兼容。已有安装拒绝切换类型，包括账号目录仍为空的情况。

core v0.5.0 包含 Windows 路径的离线适配，但 **Windows 初轮真机验收未通过**：出现会话失效，用户报告手机主设备退出，实验实例已经停止。后续初始化、长连校验及消息同步修正仅完成离线验证，尚未再次真机测试，不应视为 Windows 登录或业务已可用。详见 [core PR #5](https://github.com/we-clay/core/pull/5)。已有 Mac 档案保持原类型，不要通过更改类型、复制或清空设备文件尝试切换平台。

## 已安装用户升级

先在旧 gateway 的终端按 Ctrl+C，等待它退出。确认 **core v0.5.0 和 we-clay v0.10.0 均已由 GitHub Actions 完成私有 OSS 发布**后，原来使用默认安装目录的 macOS/Linux 用户运行：

```sh
curl -fsSL https://nww.hihfy.com/we-clay-auth/install.sh | bash -s -- \
  --core-version v0.5.0 \
  --restart
```

原来使用自定义安装目录时，必须增加 `--data-dir /absolute/path/to/original-install`，填写**原路径**。安装器沿用保存的授权 Key、设备类型和 core 账号目录；不会默认重建微信设备。不要改用新的账号目录，也不要移动、复制或清空原目录。旧安装曾在运行入口额外指定 core 版本、地址或账号目录时，按[一键安装与升级](../一键安装.md#已安装用户维护)补齐对应的 `--previous-*` 参数，供受控停止原 core 时核对。

PowerShell 用户使用相同的已发布安装入口：

```powershell
$installer = Join-Path $env:TEMP 'we-clay-install.ps1'
Invoke-WebRequest 'https://nww.hihfy.com/we-clay-auth/install.ps1' -OutFile $installer
powershell -NoProfile -ExecutionPolicy Bypass -File $installer -CoreVersion v0.5.0 -Restart
```

自定义过安装目录时继续传原 `-DataDir`；对应的旧参数使用 `-Previous*`。宿主为 Windows 时也默认使用 Mac 设备平台，不需要为普通升级增加 `-DeviceType win`。

只更新 we-clay、继续使用原 core 时，省略 `--core-version` / `-CoreVersion`；已有版本不会自动切换，但不具备新接口的旧 core 仍无法调用这些接口。Go 接入者更新模块后，显式将 `Core.Version` 设为已发布的 `v0.5.0`，保留原固定绝对 `DataDir`。

## 验证与限制

- **Mac 真机记录（2026-10-26）：** 一条已收到语音分别经 core HTTP、SDK/gRPC 得到非空转写结果；当前账号群内显示名分别经 core HTTP、直接 Client/gRPC 完成设置、读回、清空恢复和再次读回。收藏容量查询和空列表同步经 core HTTP 复验成功。
- **尚未验证：** 其他语音格式、群语音、转写质量及外部插件进程没有完整真机验收；收藏单项查询和删除缺少测试条目，仅通过离线回执测试。朋友圈视频上传、下载仅通过离线路由测试，历史上传曾返回 `-5103015`，没有当前版本真实账号成功证据。自动视频预处理便利入口也未新增真机发送验收。
- **Windows 状态：** 初轮失败后的修正尚未真机复测，离线测试和跨平台编译不能证明登录成功或账号安全质询已解决。不要将 Mac 的历史验证结果套用到 Windows 路径。
- 本次发布准备运行受影响的 CLI 测试、安装维护及发布脚本单测；发布流水线继续执行完整 Go 测试、静态检查、原生 PowerShell 解析、六平台编译及私有 OSS 上传回读。该说明不代表流水线已完成，实际构建与发布结果以对应 Actions run 为准。
