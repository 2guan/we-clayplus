# 语音转文字

`client.TranscribeVoice(ctx, msg)` 对已经接收的语音消息请求微信原生转写，返回文字。它需要支持 `/api/message/transcribe/voice` 的新版 core；旧 core 会返回接口不存在或未实现错误。2026-10-26，Mac 测试会话的一条已收到语音经 core HTTP 和 SDK/gRPC 均取得非空结果；其他格式、群语音和结果质量尚未完整验证。插件可调用 `sdk/message.Client.TranscribeVoice`；旧的 `message.Ability` 实现不需要增加方法。

```go
OnMessage: func(ctx context.Context, client *gateway.Client, msg *message.Message) error {
    if msg.GetType().GetCode() != message.TypeVoice.Code {
        return nil
    }
    text, err := client.TranscribeVoice(ctx, msg)
    if err != nil {
        return err
    }
    log.Printf("语音转写：%s", text)
    return nil
},
```

调用使用消息同步回执里的旧消息 ID、新消息 ID 与 `voicemsg.length`，支持 AMR、SPEEX 和 SILK。收到的语音消息没有显式格式时按 SILK 处理。SDK 中的 `Message.Id` 是新消息 ID，旧消息 ID 从 `Message.Raw` 提取；没有旧 ID 时仍可使用新 ID。群语音会附带群 ID。不要使用昵称、时间戳或随意生成的 ID 替代原始回执。

core 先请求 `checkvoicetrans`；服务端要求补传时，从已有消息下载语音，再向 `uploadvoicefortrans` 续传，最后用 `getvoicetransres` 轮询结果。转写不会发送聊天消息；上传步骤仅供微信转写服务使用。每次最多等待 120 秒，取消 `ctx` 可停止后续步骤。底层单次网络请求仍由 core 原有传输超时控制。

转写失败会返回错误，不会自动重发消息或静默改用第三方 AI 识别。SDK 参数校验、core HTTP/gRPC 路由、协议字段和失败路径已用合成消息验证。上述真机测试只记录成功与非空状态，没有保存转写文字；单次成功不代表所有账号、语音格式或风控状态均可用。
