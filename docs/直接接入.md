# 在自己的 Go 程序里使用微信能力

从 v0.5.0 开始，可以在应用中直接收消息、主动发送和操作朋友圈。无需编写独立插件，
也不需要获取 core 源码。gateway 和业务在同一进程，core 由 Run 启动或由你独立管理。

## 先运行起来

在自己的 Go 项目中安装：

```sh
go mod init example.com/my-wechat-bot
go get github.com/we-clay/we-clay@v0.5.5
```

已有 go.mod 时跳过第一行。将 [README 的完整 main.go](../README.md#快速开始) 保存到自己的项目中，然后：

```sh
export WE_CLAY_CORE_VERSION=v0.3.1
# 可选：填写允许自动回复的好友微信 ID 或群 ID，留空不自动回复。
# export WE_CLAY_REPLY_TO='你的测试会话 ID'
go run .
```

首次启动自动下载、校验并启动 core，打开 [登录页面](http://127.0.0.1:8201) 完成 Mac 扫码。
收到“微信已就绪”日志后，在指定会话发 `ping`，程序回复 `pong`。
昵称、备注和微信 ID 是不同的字段；不能把昵称直接传给发送接口。

## Client 从哪里来

`OnReady`、`OnMessage`、`OnEvent` 都会收到同一个 `*gateway.Client`：

```go
gateway.WithHandlers(gateway.Handlers{
    OnReady: func(ctx context.Context, client *gateway.Client) error {
        // 可以在这里主动发送，也可以把 client 交给自己的服务。
        return nil
    },
    OnMessage: func(ctx context.Context, client *gateway.Client, msg *message.Message) error {
        // 这里能使用全部 Client 能力，不限于回复这条消息。
        return nil
    },
})
```

以上为选项片段，作为 `gateway.Run(ctx, cfg, ...)` 的参数使用。
`WithoutPlugins()` 关闭插件加载、目录监听和内置命令；不传时与原有插件机制共存。
无需单独初始化 SDK 的全局 Instance，也不要自己构造 Client 或替换其能力字段。

### 在回调外主动调用

下面是完整的业务函数，可放进自己的 Go 文件。它启动 Run，等待 Client 就绪后主动发一条消息，随后继续接收事件，直到调用方取消 ctx：

```go
package bot

import (
    "context"

    "github.com/we-clay/we-clay/gateway"
)

func RunAndSend(ctx context.Context, cfg gateway.Config, receiver string) error {
    ctx, cancel := context.WithCancel(ctx)
    defer cancel()
    ready := make(chan *gateway.Client, 1)
    done := make(chan error, 1)
    go func() {
        done <- gateway.Run(ctx, cfg, gateway.WithoutPlugins(),
            gateway.WithHandlers(gateway.Handlers{
                OnReady: func(_ context.Context, client *gateway.Client) error {
                    ready <- client
                    return nil
                },
            }))
    }()

    var client *gateway.Client
    select {
    case client = <-ready:
    case err := <-done:
        return err // 下载、登录或订阅失败，不会无限等 OnReady。
    case <-ctx.Done():
        return <-done // 等待 Run 完成资源清理。
    }

    if _, err := client.SendText(receiver, "你好"); err != nil {
        cancel()
        <-done
        return err
    }
    return <-done
}
```

定时任务、管理页面或其他业务服务也可以保存这个 Client。后台任务用 `client.Context().Done()` 停止，
由应用负责等待自己创建的 goroutine 退出。不要在 OnReady 中无限等待，否则事件无法继续处理。

## 收发消息

### 文字与收件人

在已取得 client 的业务函数中：

```go
sent, err := client.SendText(receiverID, "你好")
if err != nil {
    return err
}
// sent.GetNewId() 是发送回执里的 uint64 消息 ID，可用于后续撤回。
_ = sent
```

`receiverID` 可以是好友微信 ID 或 `...@chatroom` 群 ID。联系人缓存支持：

```go
person := client.Contact.Get("remark::你的测试备注")
if person == nil {
    return fmt.Errorf("联系人缓存中未找到该备注")
}
_, err := client.SendText(person.GetUsername(), "你好")
return err
```

昵称和备注可能重复；正式业务应保存并核对微信 ID。`Contact.Get` 查询本地缓存，不会自动搜索所有微信用户。
可通过 `client.Contact.List()` 获取缓存列表，但不要把真实联系人列表写入仓库或公共日志。

在 OnMessage 中，普通私聊回复 `msg.GetSender().GetUsername()`；收到群消息时该字段是群 ID，
具体发言人位于 `msg.GetMember()`。过滤当前账号自己发出的消息，防止回复循环。
同时启用 OnMessage、OnEvent 和插件时，一条消息可能进入多个处理器，请自行分配回复职责。

### 图片和文件

下面两个函数可直接放入业务包，参数 client 来自回调。读取本地文件后沿用 SDK 的消息模型发送：

```go
package bot

import (
    "os"
    "path/filepath"

    "github.com/we-clay/we-clay/gateway"
    "github.com/we-clay/we-clay/sdk/contact"
    "github.com/we-clay/we-clay/sdk/message"
)

func SendImage(client *gateway.Client, receiver, path string) error {
    data, err := os.ReadFile(path)
    if err != nil { return err }
    _, err = client.Message.Send(&message.Message{
        Type: message.TypeImage,
        Receiver: &contact.Contact{Username: receiver},
        Data: &message.Message_Image{Image: &message.ImageData{
            Media: &message.Media{Data: data},
        }},
    })
    return err
}

func SendFile(client *gateway.Client, receiver, path string) error {
    data, err := os.ReadFile(path)
    if err != nil { return err }
    _, err = client.Message.Send(&message.Message{
        Type: message.TypeFile,
        Receiver: &contact.Contact{Username: receiver},
        Data: &message.Message_File{File: &message.FileData{
            Filename: filepath.Base(path), Media: &message.Media{Data: data},
        }},
    })
    return err
}
```

语音、视频、链接、位置等继续使用 `client.Message.Send` 与对应的 SDK 类型；这次新增入口不改变媒体格式要求和上传大小限制。
发送前会复制 Message；调用进行时不要修改传入对象或其媒体字节。

### 转发、撤回和下载

```go
forwarded, err := client.Message.Forward(receivedMessage, receiverID)
revoked, err := client.Message.Revoke(receiverID, sentMessageID)
reader, err := client.Message.Download(receivedMessage)
```

以上是三个独立操作的签名示意。各自检查错误，成功取得下载 reader 后及时 `Close()`。
`sentMessageID` 使用发送回执，不要将接收到的消息 ID 当作自己发送的消息去撤回。

#### 发送后撤回：完整函数

从 **v0.5.1** 起，gateway 保存文字消息的原始数值回执；**v0.7.2 搭配 core v0.4.1** 扩展到媒体的字符串回执和表情包请求元数据。`Revoke(receiver, newID)` 自动取回并传给 core，调用签名不变。仅文字等原有数值路径无需升级 core。

### 拍一拍（实验性）

```go
// 私聊：填写好友微信 ID。不要用昵称直接发送。
resp, err := client.Pat(friendID)
// 群聊：指定群 ID 与被拍成员的微信 ID。
resp, err = client.Message.Pat(roomID, memberID)
_ = resp
_ = err
```

拍一拍要求 core v0.4.4 或更新版本；gateway 通过 gRPC Invoke 传递请求。2026-10-15，Mac 模式下通过 core HTTP 接口分别对一位私聊联系人和一位群成员拍一拍，微信返回明确成功码和回执 ID，手机端均确认显示。SDK/gateway 调用链已通过离线测试，尚未单独真机复验；其他平台与账号组合也未验证。超时或回执不全时先核对聊天记录，不要自动重试。

```go
package bot

import "github.com/we-clay/we-clay/gateway"

func SendAndRevoke(client *gateway.Client, receiver string) error {
    sent, err := client.SendText(receiver, "测试撤回")
    if err != nil { return err }
    _, err = client.Message.Revoke(receiver, sent.GetNewId())
    return err
}
```

- 可立即或稍后调用撤回，但要在**同一次 Run 内**，使用原发送对象的微信 ID / 群 ID 和发送回执的 `NewId`。
- 回执只保存在内存，最多保留最近 4096 条完整回执。退出 Run 会清空；重启后只保存 `NewId` 不足以撤回之前的消息。
- 找不到回执、接收人不匹配，或缺少原始 `client_id` / `create_time` 时，不发送撤回请求，返回 `message.ErrRevokeReceiptUnavailable`。直接调用可用 `errors.Is` 判断。
- 文字、名片、位置沿用数值回执；图片、语音、文件、链接保留微信返回的字符串客户端标识；视频从服务端回显的发送 ID 还原原始时间；动态表情包由 core 返回本次请求的客户端标识。上述类型已在 Mac 模式下逐项发送、撤回并由手机确认。媒体撤回需要同时升级 gateway 与 core，旧版本仍可能返回 `ErrRevokeReceiptUnavailable`。
- 微信内置小表情可作为普通文字发送，例如 `client.SendText(receiver, "[旺柴][破涕为笑]")`；手机端已验证会显示为两个内置表情，并可按文字消息撤回。动态表情包则使用 `TypeEmoji`。
- 发送消息设置 `Message.Timestamp` 时，既有自动撤回也使用完整回执；停止 Run 会取消尚未发出的自动撤回。实际能否撤回仍由微信判定。
- v0.5.0 会把撤回所需的 `client_id` 和 `create_time` 置零，导致 core 返回 400。升级后请重新运行程序，对一条新发送的测试消息验证；旧进程内的回执不会迁移到新进程。


## 朋友圈：查询、点赞与留言

### 查列表取得 ID

```go
// 普通朋友圈时间线：空 MD5、maxID=0 表示开始读取。
page, err := client.Moments.Timeline("", 0)

// 指定好友的朋友圈主页。
friendPage, err := client.Moments.UserPage(friendID, "", 0)
```

分别检查 `err` 和 `BaseResult` 后，从 `page.GetObjectList()` 或 `friendPage.GetObjectList()` 中选择目标。
每条内容的 `GetId()` 返回 uint64；朋友圈 ID 不要转为 float64，以免丢失精度。
后续分页沿用返回的分页字段，不应在循环里持续请求第一页。

### 给指定朋友圈点赞

下面函数可在 OnReady、OnMessage 或主动任务中调用，不依赖插件：

```go
package bot

import (
    "fmt"

    "github.com/we-clay/we-clay/gateway"
)

func LikeMoment(client *gateway.Client, momentID uint64) error {
    result, err := client.Moments.Like(momentID)
    if err != nil { return err }
    if result == nil || result.GetBaseResult() == nil {
        return fmt.Errorf("点赞回执不完整，请先核对朋友圈状态")
    }
    if base := result.GetBaseResult(); base.GetCode() != 0 {
        return fmt.Errorf("点赞未成功，返回码 %d", base.GetCode())
    }
    return nil
}

func UnlikeMoment(client *gateway.Client, momentID uint64) error {
    result, err := client.Moments.Unlike(momentID)
    if err != nil { return err }
    if result == nil || result.GetBaseResult() == nil {
        return fmt.Errorf("取消点赞回执不完整，请先核对朋友圈状态")
    }
    if base := result.GetBaseResult(); base.GetCode() != 0 {
        return fmt.Errorf("取消点赞未成功，返回码 %d", base.GetCode())
    }
    return nil
}
```

用户输入的十进制 ID 可用 `strconv.ParseUint(value, 10, 64)` 解析，处理解析错误后再调用。
发布、详情、媒体上传分别使用 `client.Moments.Post/Detail/Upload`。`Post` 的 content 参数是朋友圈 `TimelineObject` XML，不是普通文案；图片需先上传，使用返回的媒体 URL、尺寸等信息构造 XML，再发布。

### 给指定朋友圈留言或回复

从 v0.5.4 起，`client.Moments.Comment` 已接通现有 core 评论接口，直接 Client 和插件调用均可用，无需新增 proto。当前只完成离线验证，真实微信效果由本次试用确认。`DeleteComment` 仍保留占位。

```go
package bot

import (
    "fmt"

    "github.com/we-clay/we-clay/gateway"
)

// 普通留言传 replyCommentID=0；回复留言传目标评论的 CommentId。
func CommentMoment(client *gateway.Client, momentID uint64, text string, replyCommentID int32) error {
    result, err := client.Moments.Comment(momentID, text, 2, replyCommentID)
    if err != nil {
        return err // 不自动重试；先看手机或读回详情，确认是否已发出。
    }
    if result == nil || result.GetBaseResult() == nil {
        return fmt.Errorf("评论回执不完整，请先核对朋友圈状态")
    }
    if code := result.GetBaseResult().GetCode(); code != 0 {
        return fmt.Errorf("评论未成功，返回码 %d", code)
    }
    return nil
}
```

- `momentID` 从 `Timeline` / `UserPage` / `Detail` 的朋友圈对象取得；正文直接传字符串，保留中文、换行和表情。文字评论 `type=2`，不使用点赞的 `type=1`。
- 普通留言第四个参数填 `0`。回复时，从 `Detail` 返回的 `CommentUserList` 选取原评论，传它的 `GetCommentId()`；不要将 64 位 `CommentId2` 截断成 int32。
- 回执中的 `Object`、评论列表和评论 ID 均按 core 原值返回；对象是可选字段，缺失时不会伪造。收到基础成功回执后，请用手机或 `Detail(momentID)` 核对实际留言，勿因没有返回对象而重复提交。
- 先对自己选定的一条朋友圈执行一次。若放在 `OnReady`，每次新 Run 都会执行；试用结束后移除该调用。若失败不应停止机器人，在 `OnReady` 内记录错误后返回 `nil`，不要直接返回该业务错误。
主动操作可直接从业务调用，不需要伪造一条收到的微信消息来触发它。

## 更多消息类型

下面是独立业务函数，client 来自回调；不需要插件。语音传入已经编码的内容，示例格式值 `4` 对应现有 SILK 路径，时长单位为毫秒；视频时长为秒，缩略图由调用方准备。

```go
package bot

import (
    "github.com/we-clay/we-clay/gateway"
    "github.com/we-clay/we-clay/sdk/contact"
    "github.com/we-clay/we-clay/sdk/message"
)

func SendVoice(client *gateway.Client, receiver string, silk []byte, durationMS uint32) error {
    format := int32(4)
    _, err := client.Message.Send(&message.Message{
        Type: message.TypeVoice,
        Receiver: &contact.Contact{Username: receiver},
        Data: &message.Message_Voice{Voice: &message.VoiceData{
            Media: &message.Media{Data: silk}, Duration: durationMS, Format: &format,
        }},
    })
    return err
}

func SendVideo(client *gateway.Client, receiver string, video, thumbnail []byte, durationSeconds uint32) error {
    _, err := client.Message.Send(&message.Message{
        Type: message.TypeVideo,
        Receiver: &contact.Contact{Username: receiver},
        Data: &message.Message_Video{Video: &message.VideoData{
            Media: &message.Media{Data: video}, Thumb: thumbnail, Duration: durationSeconds,
        }},
    })
    return err
}

func Mention(client *gateway.Client, room, member, text string) error {
    _, err := client.Message.Send(&message.Message{
        Type: message.TypeText,
        Receiver: &contact.Contact{Username: room},
        Data: &message.Message_Text{Text: &message.TextData{
            Content: text, Reminds: []string{member},
        }},
    })
    return err
}
```

其余消息沿用以下模型。使用 `client.Message.Send` 时设置对应 `Type`、`Receiver` 和 `Data`，并检查返回错误：

| 操作 | 参数入口 |
| --- | --- |
| 名片 | `client.SendCard(receiverID, cardUsername, cardNickname, cardAlias)` |
| 链接 | `TypeAppLink` + `Message_App{App: &AppData{Title, Desc, Url}}`；字段值由调用方提供 |
| 位置 | `TypeLocation` + `Message_Location`，内容为 `LocationData{Latitude, Longitude, Scale, PoiName, Label}` |
| 动态表情包 | `TypeEmoji` + `Message_Emoji`，`EmojiData.Media` 携带数据和 MD5；发送与撤回已手机验收 |

## 联系人与群聊

v0.5.2 起，`Search` 结果保留 `V1`、`V2`，供 `AddFriend` 使用；请保持接口所需的来源场景。搜索失败或无结果返回 `nil`，搜索结果也不证明已成为好友。票据不要输出日志或持久化。

```go
package bot

import (
    "fmt"
    "github.com/we-clay/we-clay/gateway"
)

// 仅在用户明确要求添加该联系人时调用。场景由业务提供。
func RequestFriend(client *gateway.Client, keyword, greeting string, fromScene, searchScene uint32, scene int) error {
    found := client.Contact.Search(keyword, fromScene, searchScene)
    if found == nil || found.GetV1() == "" || found.GetV2() == "" {
        return fmt.Errorf("搜索未取得完整的好友申请票据")
    }
    return client.Contact.AddFriend(found.GetV1(), found.GetV2(), greeting, 2, scene)
}
```

调用成功表示申请已被接受处理，好友关系仍需对方确认或通讯录读回。


每个方法都是独立操作，不会因为注册 Client 或消息回调而自动执行。

```go
package bot

import (
    "fmt"
    "github.com/we-clay/we-clay/gateway"
)

func RenameContact(client *gateway.Client, username, remark string) error {
    return client.Contact.SetRemark(username, remark)
}

func CreateTestGroup(client *gateway.Client, friendA, friendB string) (string, error) {
    result, err := client.Chatroom.Create([]string{friendA, friendB})
    if err != nil { return "", err }
    if result == nil || result.GetChatroom() == "" { return "", fmt.Errorf("建群回执缺少群 ID") }
    return result.GetChatroom(), nil
}

func InviteToGroup(client *gateway.Client, room, friend string) error {
    _, err := client.Chatroom.InviteMember(room, []string{friend})
    return err // 发送邀请成功不等于对方已经进群，入群后再读回成员。
}
```

建群历史验证使用当前账号加两名好友；邀请、公告、管理员等操作仍受当前账号在群内的权限限制。
联系人备注、群名等缓存会随 core 同步更新，写调用返回并不保证下一次本地查询立即看到新值。

| 功能 | 调用示意 |
| --- | --- |
| 联系人/群缓存 | `client.Contact.List()`、`client.Contact.Get(username)` |
| 搜索联系人 | `client.Contact.Search(keyword, fromScene, searchScene)`；场景值沿用实际来源 |
| 发好友申请 | `client.Contact.AddFriend(v1, v2, content, operate, scene)` |
| 接受好友申请 | `client.Contact.VerifyFriend(v1, v2, scene)` |
| 群详情/公告 | `client.Chatroom.GetInfo(roomID)`，响应含 `Announcement` |
| 群二维码 | `client.Chatroom.GetQRCode(roomID)` |
| 群名/公告/备注 | `SetName(roomID, name)`、`SetAnnouncement(roomID, text)`、`SetRemark(roomID, remark)` |
| 保存到通讯录 | `client.Chatroom.Save(roomID, true)`；false 取消保存 |
| 设置管理员 | `client.Chatroom.SetAdmin(roomID, []string{memberID})` |
| 成员缓存/详情 | `ListMembers(roomID)`、`GetMember(roomID, memberID)`、`GetMembersDetail(roomID, memberIDs)` |

好友验证所需的 `v1/v2/scene` 来自对应申请或搜索上下文，不可用昵称代替，也不要跨申请重复使用旧票据。
好友申请消息通过 `OnMessage` 提供，类型为 `TypeVerify`；现阶段需要从该消息内容/XML 提取凭证，未提供自动通过所有申请的行为。
群来源添加好友已有历史核心实测；直接 Client 的这条完整链路仍需再次验收。

## 标签、媒体上传及其他查询

### 上传当前账号头像

从 v0.5.3 起，`client.User.UploadAvatar(reader)` 已接通现有 core 接口，不再返回占位错误。传入本地头像图片的二进制 reader，大小为 1 字节至 16 MiB。core 负责分块传输；返回 `Avatar` 中的大小、完成偏移、MD5 和 URL（部分字段可能缺失）。上传失败不自动重试，返回成功后仍应在手机确认实际头像。

**此前的退出原因：** `UploadAvatar` 返回 `ErrNotImplemented`，调用方再从 `OnReady` 返回该错误，Run 按约定结束；若 main 使用 `log.Fatal(err)`，退出码即为 1。非关键的头像上传失败可以这样处理，让机器人继续接收消息：

```go
package bot

import (
    "context"
    "log"
    "os"

    "github.com/we-clay/we-clay/gateway"
)

// 在 gateway.WithHandlers(AvatarHandlers(path)) 中使用。
// 每次新 Run 都会执行；只在这次确实需要修改头像时配置。
func AvatarHandlers(path string) gateway.Handlers {
    return gateway.Handlers{
        OnReady: func(_ context.Context, client *gateway.Client) error {
            file, err := os.Open(path)
            if err != nil {
                log.Printf("读取头像失败，继续运行：%v", err)
                return nil
            }
            defer file.Close()

            if _, err := client.User.UploadAvatar(file); err != nil {
                log.Printf("头像上传失败，未自动重试：%v", err)
                return nil // 已处理此次失败，不要求停止 Run。
            }
            log.Print("已收到头像上传成功回执，请在手机微信确认头像")
            return nil
        },
    }
}
```

如果上传成功是业务继续运行的必要条件，可以返回该错误，让 Run 停止。框架不会统一吞掉回调错误。此接口目前只完成离线验证，未完成当前版本真机验收；账号资料缓存也不保证调用后立即刷新。

### 标签与其他查询

下面的完整函数新增标签并返回 ID。给好友设置标签时，传入业务期望的完整标签集合，避免覆盖已有标签：

```go
package bot

import (
    "fmt"
    "github.com/we-clay/we-clay/gateway"
)

func CreateLabel(client *gateway.Client, name string) (uint32, error) {
    label, err := client.Label.Add(name)
    if err != nil { return 0, err }
    if label == nil || label.GetId() == 0 { return 0, fmt.Errorf("标签回执缺少 ID") }
    return label.GetId(), nil
}
```

| 领域 | 已接通调用示意 |
| --- | --- |
| 标签 | `Label.List()`、`Add(name)`、`Update(id, name)`、`Delete(ids)`、`ModifyContactLabels(usernames, ids)`；ids 为逗号分隔十进制 ID |
| CDN 图片 | `CDN.UploadImage(receiver, reader)`、`DownloadImage(fileID, key)` |
| CDN 视频 | `CDN.UploadVideo(receiver, thumb, reader, duration)`、`DownloadVideo(fileID, key)`、`DownloadVideoCover(fileID, key)` |
| 朋友圈媒体 | `CDN.UploadMomentsImage(imageBytes)` 或 `Moments.Upload(imageBytes)`；上传本身不发布朋友圈 |
| 收藏 | `Favor.GetInfo()`、`Favor.Sync(nil)`；仅历史容量及空列表同步通过 |
| 小程序 | `Miniapp.GetRecord()` |
| 输入状态 | `Report.StartTyping(receiverID)`、`Report.StopTyping(receiverID)`；仅历史回执成功 |
| 账号查询 | `User.GetProfile()`、`User.GetQRCode(style)`、`User.GetSafetyInfo()`、`User.GetBoundHardDevices()` |

表内均以 `client.` 为前缀；每次调用单独处理错误及响应中的业务返回码，下载的 reader 用完后关闭。
同步接口首次可传 nil，后续使用服务返回的游标；不要把循环请求第一页当作增量同步。
完整的方法状态和未实现清单以 [README](../README.md#当前状态) 为准。

## 什么时候还需要插件

| 需求 | 推荐方式 |
| --- | --- |
| 一个业务程序，需要发消息、点赞、接 AI 或定时任务 | `WithoutPlugins()` + Client + 回调 |
| 功能随主程序一起编译、部署 | 普通 Go 包即可 |
| 多个扩展独立编译交付、分别启停或配置能力权限 | 可选插件模式 |
| 业务主程序同时搭载第三方扩展 | Client 回调和插件共存，分配好消息处理职责 |

插件不是调用微信的前置条件。它多一个插件进程和生命周期管理，只有需要独立扩展时才值得使用；插件进程拥有系统用户权限，能力权限配置不等于系统沙箱。

## 回调和生命周期

1. Run 连接 core，完成登录和基础缓存初始化；有启用插件时再初始化插件。
2. 收到 core 事件订阅就绪帧，调用一次 OnReady。事件流重连不会再次调用 OnReady。
3. 按同步批次处理消息和资料变更。消息先交给 OnMessage，再处理内置命令，未消费的消息进入 OnEvent，最后进入插件队列。
4. OnEvent 也包含联系人、群成员和本人资料的变更事件；同一变更可能有总主题和字段主题，按 Topic 选择订阅。
5. 直接回调串行执行，并拿到独立的事件副本。成功返回才继续处理并确认批次；返回错误或 panic 结束 Run，不在当前运行中自动重试业务回调。
6. context 取消时能力调用随之取消；Run 等待已经进入的 Client 调用结束，再清理插件、缓存和连接。旧 Client 永远不能用于下一次 Run，即使登录同一账号也要取得新对象。

没有独立的每调用 context 参数，业务方法沿用 SDK 签名并共享 Run 的 context，网络调用默认两分钟超时。
回调中等待外部 AI 或数据库时，应自行设置超时并遵守 ctx。应用自行创建的后台任务不参与事件确认，Run 不替应用等待这些任务。
回调如果不响应取消或一直阻塞，Run 也无法及时退出；不要在回调里等待 Run 返回。

失败时，批次中先前的业务可能已成功；下一次启动可能再次收到未确认批次。按消息 ID 做持久化去重，
超时或断线后先核对结果，不要盲目重发。缓存变更与外部操作不构成事务；资料变更事件也不保证在重启后重新产生。
OnReady 里的主动操作也会在每次新 Run 时执行，需要业务自己记录是否已执行。

## 当前限制

- Client 暴露 13 个接口域，共 129 个方法；61 个接通，68 个占位。完整状态按方法列在 [README](../README.md#当前状态)，不是所有接口都通过了当前版本真机验证。
- 占位方法保留参数和返回类型，直接调用返回 `gateway.ErrNotImplemented`，不发送业务请求；独立插件使用 gRPC `codes.Unimplemented` 判断。删除好友、拉黑、踢人、群主转让、支付等均在占位清单中。
- 有 error 返回值的 Client 方法遇到底层 panic 返回 `ErrAbilityPanic`；不包含 panic 原始内容，避免带出请求敏感字段。需核对操作结果后处理。
- SDK 少数旧查询签名没有 error，如 `Contact.Get/List/GetSelf/Search`、群成员缓存查询：客户端停止或发生底层 panic 时返回零值（通常 nil），panic 会记录不含载荷的错误。不要把空结果直接解释为好友已删除。
- 每进程一个活动 gateway，同一 core 一个事件订阅者；多账号使用独立进程与数据目录。
- 群信息响应追加 `Announcement` 字段，原字段和服务不变；core 通信协议未变，现有 core v0.3.0 可继续作为连接目标。此次接口测试使用本地替身，没有登录真实微信、发送真实消息或点赞真实朋友圈。

下载、令牌、端口、会话恢复和排错见[运行指南](运行指南.md)，插件扩展见[插件开发](插件开发.md)。

### v0.5.2 回执与同步注意事项

- 必须先处理每次调用的 `err`，不确定的写操作不要自动重发；缺失/失败业务回执现在明确返回错误。
- 朋友圈 `UserPage` 的 `BaseResult.Code == 207` 是正常末页。
- 收藏同步的 `Item.Type` 是类型，`Item.Id == 0` 表示未返回真实收藏 ID；不要把类型用于详情查询或删除。未知同步命令会报错，不向调用方返回新游标。
- CDN 上传只产生媒体引用，不会自动发出消息。上传成功后仍需使用对应业务流程；媒体下载不会把 JSON 成功信封当成文件。
- 详细核对范围和剩余限制见[接口契约核对](接口契约核对.md)。
