# 一键安装与升级

`we-clay` 有两种入口：预编译主程序用于直接运行 Dashboard、AI 和微信连接；Go 开发者仍可导入 `github.com/we-clay/we-clay/gateway` 与 SDK，在自己的程序中调用 `gateway.Run`。两个入口共用一个根 `go.mod` 和相同业务代码。独立 core 由主程序按固定版本下载并启动。

## 发布前提

`we-clay` 的版本 tag 推送到私有仓库 main 的提交后，Action 构建 macOS、Linux、Windows 的 amd64/arm64 六个平台，校验后上传到私有 OSS `weclay/we-clay/vX.Y.Z/`。每个 tag 需附带 `docs/releases/<tag>.md` 中文版本说明；流水线确认 OSS 发布成功后创建对应 GitHub Release 说明。Action 还将安装脚本的版本固定为该 tag，上传至稳定路径。授权服务公开提供 `/install.sh`、`/install.ps1`，只重定向到这两个脚本的短时签名地址；脚本本身不含 Key。正式发布前需要先配置仓库 Actions 的 `OSS_ACCESS_KEY_ID` 和 `OSS_ACCESS_KEY_SECRET` Secrets，并部署支持 `/v1/download` 的授权服务。不要把这两个 Secrets 放到最终用户机器。

发布用 RAM 身份只授予私有 Bucket `weclay` 下 `we-clay/*` 对象的读写权限，上传对象保持 private ACL。线上授权服务使用**另一套只读身份**，只需读取 `core/*` 与 `we-clay/*` 并生成短时签名下载地址。发布身份与授权服务身份不要混用；两套 AK/SK 均不得写入仓库或交付给最终用户。

## macOS / Linux

首次安装可在终端运行：

```sh
curl -fsSL https://nww.hihfy.com/we-clay-auth/install.sh | bash
```

脚本会从终端安全读取授权 Key，不在命令行显示。已有单独交付的 Key 文件时，可传路径：

```sh
curl -fsSL https://nww.hihfy.com/we-clay-auth/install.sh | bash -s -- \
  --key-file /absolute/path/to/license.key
```

也可以不传 `--key-file`：脚本会提示“请输入授权 Key（不回显）”，此时粘贴 Key 并按回车即可。不要把 Key 写进 `--key 字符串`、命令行或 shell 历史。

如果此前微信已在另一个 core 账号目录登录，应显式传原目录，防止创建新设备：

```sh
curl -fsSL https://nww.hihfy.com/we-clay-auth/install.sh | bash -s -- \
  --key-file /absolute/path/to/license.key \
  --core-data-dir /absolute/path/to/existing/core-data
```

安装完成后，主程序默认运行在 `~/Library/Application Support/we-clay/run.sh`（macOS）或 `${XDG_DATA_HOME:-~/.local/share}/we-clay/run.sh`（Linux）。也可传 `--data-dir /absolute/path` 指定运行目录。请注意 `--data-dir` 是整个本地运行目录，`--core-data-dir` 是原微信账号状态目录，二者含义不同。两者都不传时，core 账号目录默认为 `<data-dir>/core`；已有微信账号必须显式指向原目录，否则可能创建新设备。`--core-data-dir` 给错或不存在时安装会拒绝继续。

`--device-name '我的 Mac'` 可设置微信登录设备显示名称，并保存到运行目录，后续运行入口会继续使用。省略此参数时沿用已保存的安装配置；若此前没有设置，则由 core 沿用其保存的名称。修改**正在运行**的独立 core 的名称，需要先有序停止该 core 再启动，账号目录保持原路径；不要通过退出微信或删除数据来改名。

已有微信账号、首次使用该安装目录且希望直接输入 Key，可以把两个参数一起使用：

```sh
curl -fsSL https://nww.hihfy.com/we-clay-auth/install.sh | bash -s -- \
  --core-data-dir /absolute/path/to/existing/core-data \
  --device-name '我的 Mac' \
  --no-run
```

首次运行后按提示粘贴授权 Key；后续升级会自动读取安装目录里保存的 Key。`--no-run` 仅安装，适合旧 gateway 尚未停止时升级。

要把运行入口放在当前目录下，可指定 `--data-dir "$PWD/runtime/we-clay"`；运行入口会是 `$PWD/runtime/we-clay/run.sh`。如果当前目录是 Git 仓库，请确保 `runtime/` 已被忽略，避免提交授权 Key。安装时脚本会显示授权、下载、校验和写入阶段，并在下载主程序时显示进度；进度消息不包含 Key 或临时签名链接。

## Windows PowerShell

```powershell
$installer = Join-Path $env:TEMP 'we-clay-install.ps1'
Invoke-WebRequest 'https://nww.hihfy.com/we-clay-auth/install.ps1' -OutFile $installer
powershell -NoProfile -ExecutionPolicy Bypass -File $installer
```

如果有授权文件和旧微信账号目录：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File $installer `
  -KeyFile 'C:\path\to\license.key' `
  -CoreDataDir 'C:\path\to\existing\core-data' `
  -DeviceName '我的 Windows 电脑'
```

默认运行目录为 `%LOCALAPPDATA%\we-clay`，默认 core 账号目录为 `%LOCALAPPDATA%\we-clay\core`；后续可双击其中的 `run.cmd`，或在 PowerShell 中运行 `run.ps1`。`-DataDir` 可指定绝对运行目录，`-NoRun` 只安装不启动。已有微信账号需用 `-CoreDataDir` 指向原账号目录。
Windows 安装脚本也会显示安装阶段与主程序下载进度。
省略 `-KeyFile` 时，会通过 PowerShell 的隐藏输入提示读取授权 Key；`-DeviceName` 可保存设备显示名称供后续启动使用。

## 授权与下载

1. 安装脚本用同一个授权 Key 请求 `https://nww.hihfy.com/we-clay-auth/v1/download`，仅获取当前平台、固定版本的私有 OSS 短时地址和服务端确认的大小、SHA-256。
2. 脚本拒绝异常地址和跨站重定向；下载后检查大小及 SHA-256，验证通过才更新本地版本。验证失败保留此前安装的版本和 Key。
3. Key 以本机 `secrets/license.key` 保存：macOS/Linux 文件权限 0600；Windows 先收紧 `secrets` 目录 ACL，再创建 Key 临时文件并将文件 ACL 设为当前用户。脚本不把 Key 或签名地址写入命令行参数、普通配置文件、安装日志。
4. 主程序读取该文件，启动独立 core。core 的自动下载使用同一 Key 向授权服务申请签名地址，运行授权及续期仍由 core 自己完成。OSS AK/SK 不下发给用户。

安装脚本所在目录、二进制目录及 core 缓存互相分开。账号状态始终放在固定的 core 数据目录；授权文件和账号状态都不得上传 Git。

## 登录、停止与升级

首次运行后，打开 `http://127.0.0.1:8208` 创建控制台管理员，再点击账号区域的“微信连接”：同一弹窗会显示 core 状态、登录二维码和登录进度。扫码后如果微信要求验证码或设备确认，也在此弹窗完成。管理员可在这里停止、重新启动**本安装目录管理的独立 core**；停止会暂停消息接收，但保留微信设备与登录数据，不执行微信退出登录。扫码和 core 日常启停无需再打开另一页面。core 原登录页 `http://127.0.0.1:8201` 保留给兼容调用与应急排查。

安装脚本只负责下载、配置、首次启动和升级。主程序默认让 core 独立常驻；关闭主程序只断开 gateway，不会停止 core。重新运行同一 `run.sh` / `run.ps1` 时复用已登录的 core；控制台本身未运行时，需先运行入口才能使用网页按钮。第一次安装前，如果原 core 正在运行，先停止旧 gateway/core，再带原 `--core-data-dir` 安装，避免两个进程同时访问同一设备目录。

### 选择 Windows 设备信息

设备平台默认 `mac`，与安装程序运行的操作系统无关。需要创建 Windows 设备时，在全新安装中增加 `--device-type win`（PowerShell 为 `-DeviceType win`），同时指定独立的新 `--data-dir`，让 core 使用该目录下的新账号目录；不要指向已有 Mac 档案。直接运行主程序时同样使用 `--device-type win`。类型只接受 `mac` 或 `win`。

此配置须配套支持原版 1.0 `win` 标识的 core 发布版；we-clay v0.10.0 新安装默认配套 core v0.5.0，已有安装须用 `--core-version` 显式指定实际已发布版本，旧默认 core v0.4.6 不具备该能力。Windows 路径已覆盖离线配置和进程测试，但初轮真机验收未通过：出现会话失效，用户报告手机主设备退出，实验实例已停止；后续修正仅完成离线验证，尚未再次真机测试，不建议使用正式账号测试。详情见 [core PR #5](https://github.com/we-clay/core/pull/5)。

安装器会保存 `device-type.txt`，后续升级、启动和停止沿用该类型。主程序也会核对该文件：未显式传类型时沿用保存值；通过 `run.sh` / `run.ps1` 或直接运行主程序追加不同的 `--device-type` 会报错，即使账号目录还是空目录，也不能覆盖安装时选择的平台。旧安装缺少文件时按 `mac` 兼容。已有安装显式切换类型会在下载、停止 core 和写配置前报错；需要 Windows 设备时另建安装及账号目录。不要手工修改类型文件来切换已有档案。

### 已安装用户维护

先在运行旧 gateway 的终端按 Ctrl+C，等待它退出。普通升级可重新运行安装脚本并保持原 `--data-dir`；脚本先下载、校验新主程序，再切换本地版本。没有换 Key、core 版本、端口或设备名称时，即使使用 `--restart` 自动启动新 gateway，独立 core 也会保持在线。

只升级到 we-clay v0.10.0、保留原 core 时，先确认该版本已完成私有 OSS 发布。此前使用默认安装目录的用户不需要填写 `--data-dir`；安装器沿用已保存的授权 Key、core 版本与微信账号目录：

```sh
curl -fsSL https://nww.hihfy.com/we-clay-auth/install.sh | bash -s -- --restart
```

此前指定过安装目录的用户，升级时必须传入**同一个原路径**。例如：

```sh
curl -fsSL https://nww.hihfy.com/we-clay-auth/install.sh | bash -s -- \
  --data-dir "$HOME/Documents/.we-clay" \
  --restart
```

新安装默认选择 core v0.5.0；已有安装不因单独更新 we-clay 而自动切换正在运行的 core。若要使用本版新增接口并同时升级 core，确认目标版本已发布后再加 `--core-version v0.5.0 --restart`，完整命令见 [v0.10.0 版本说明](releases/v0.10.0.md#已安装用户升级)。旧安装缺少 `core-version.txt` 时，安装器仍按旧默认版本 v0.4.5 核验原 core，再受控切换。运行时额外传过 core 参数的安装，先按下文补齐对应的 `--previous-*` 参数。

更新 core、换 Key 或修改设备名称时，使用 `--restart` 一次完成校验、停止旧 core、保存新配置和启动。`--core-version` 必须是私有 OSS 已发布的 core 版本。`--key-file` 必须指向**新**授权文件，Key 内容不放入命令行。下面的示例沿用已安装目录及其保存的微信账号目录：

控制台的“启动 core”“停止 core”只操作当前保存的配置，不修改授权 Key、core 版本、设备名称、监听地址或账号目录。这些设置的变更仍按本节安装器的受控升级流程处理。

```sh
curl -fsSL https://nww.hihfy.com/we-clay-auth/install.sh | bash -s -- \
  --data-dir "$HOME/Documents/.we-clay" \
  --key-file /absolute/path/to/new-license.key \
  --core-version vX.Y.Z \
  --restart
```

只换 Key 时省略 `--core-version`；只更新 core 时省略 `--key-file`。脚本会用 Key 申请下载地址并校验主程序，所以即使只换 Key，也会重新下载当前发布的主程序。目标 core 会预先下载并校验；新程序及目标 core 均已校验、且确认旧 gateway 已停止后，旧 core 才会通过进程身份和 gRPC 鉴权检查被停止。若预检或停服检查失败，Key、core 版本及设备配置保持原样。停止 core 不调用微信退出登录接口，也不删除账号目录。不想由安装器立即运行新版本时，用 `--no-run`，安装完成后手动启动：

```sh
curl -fsSL https://nww.hihfy.com/we-clay-auth/install.sh | bash -s -- \
  --data-dir "$HOME/Documents/.we-clay" --key-file /absolute/path/to/new-license.key --no-run
"$HOME/Documents/.we-clay/run.sh"
```

更新到支持维护命令的版本后，还可单独运行 `run.sh --stop-core`，只停止该安装目录指向的 core；它不读取授权 Key 文件。新安装脚本会保存 core 版本和监听地址，后续 `run.sh` 自动沿用。旧安装若曾在运行命令后手工追加 `--core-data-dir`、`--core-version`、`--core-address`、`--login-address` 或 `--dashboard-address`，升级时须在安装命令中对应传入 `--previous-core-data-dir`、`--previous-core-version`、`--previous-core-address`、`--previous-login-address` 或 `--previous-dashboard-address`，用于准确识别原进程。账号目录应填写**原运行命令使用的同一路径字符串**，包括符号链接路径，不要临时改成解析后的真实路径。不要凭端口号结束不明来源的进程。已有安装换 Key 或改 core 配置时，仍必须使用**原来的** `--data-dir` 和 core 账号目录；脚本不会迁移或重建微信设备。

Windows PowerShell 使用同一流程：先结束旧 gateway，再运行安装器。默认数据目录可省略 `-DataDir`；自定义过目录时必须传原路径。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File $installer `
  -DataDir 'C:\path\to\existing\we-clay' `
  -KeyFile 'C:\path\to\new-license.key' `
  -CoreVersion 'vX.Y.Z' `
  -Restart
```

分步停止和重新运行可用安装目录中的 `run.cmd --stop-core` 与 `run.cmd`。`--no-run` / `-NoRun` 只安装，不自动启动；它们与 `--restart` / `-Restart` 不能同时使用。主程序还支持 `--check`（只检查本地配置和 Key 文件格式，不访问授权服务）与 `--version`。不要同时用不同版本或账号目录启动两个 core。

预检只能确认目标二进制可下载且校验正确，不能保证新版本随后一定能完成微信登录或业务启动。确认新版本正常前，请保留原授权文件，不要吊销旧 Key；安装目录下旧版本二进制也会保留。若新 core 启动失败，先结束新 gateway，再用原授权文件和原 core 版本重跑安装器（保留相同的 `--data-dir`，以及旧安装手工指定过的 `--previous-*` 参数），不加 `--restart`，最后运行安装目录中的 `run.sh` / `run.cmd`。若主程序版本本身无法启动，可从安装目录 `bin/` 中运行保留的旧版本主程序，传入原来的 `--data-dir`、`--license-file`、`--core-data-dir`、`--core-version` 和端口参数。若旧 Key 已失效，需要先取得一个有效的新 Key。整个恢复过程不要移动、复制或清空 core 账号目录。

## 多套实例与外部插件

每套实例使用自己的运行目录、授权文件、core 账号目录和三个本机端口。第二套先只安装，然后启动时显式传端口，例如：

```sh
curl -fsSL https://nww.hihfy.com/we-clay-auth/install.sh | bash -s -- \
  --data-dir "$HOME/we-clay-second" --no-run
"$HOME/we-clay-second/run.sh" \
  --core-address 127.0.0.1:8089 \
  --login-address 127.0.0.1:8202 \
  --dashboard-address 127.0.0.1:8209
```

主程序默认启用内建 Dashboard、AI 和业务插件，默认不发现或启动外部插件进程。只有明确准备并信任外部插件后，才在运行入口后传 `--external-plugins`。外部插件不会继承框架自己的授权、core 通讯和 OSS 下载变量；为了兼容旧插件，其他环境变量包括第三方服务密钥仍会继承。插件与主程序属于同一系统用户，仍可访问该用户有权限读取的文件，不能视为安全沙箱。

开发自己的机器人逻辑、接收消息回调或调用朋友圈接口，请继续使用 [Go SDK 快速开始](../README.md#快速开始)。预编译主程序提供现成控制台；它不替代 Go 库的导入能力。
