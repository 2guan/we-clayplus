# 迁移说明

## v0.5.0：直接接入机器人

新增 `WithHandlers`、`WithoutPlugins` 和有运行周期保护的 `Client`。消息收发、朋友圈等现有能力可以在自己的程序里直接调用，无需独立插件。原 `Run(ctx, cfg)` 的使用方式和默认插件行为保留。

`Run` 新增可变选项参数；普通调用不需修改。如果以前把 `Run` 赋给固定的 `func(context.Context, gateway.Config) error` 类型，需用一层函数包装。

OnReady 只在首次订阅成功后调用一次；直接回调报错或 panic 会停止 Run，不确认失败事件、不自动重试回调。旧 Client 在取消或退出后失效。插件仍沿用原有异步分发语义。

本次在已有 `chatroom.GetInfo.Response` 中追加字段 `announcement = 8`，旧字段编号和 RPC 保持不变；`corewire` 协议未变，无需重新发布 core。

**能力行为调整：** 依照实际验收范围，76 个未通过或未测试的上层方法改为显式占位，保留签名但不请求 core。过去能发出请求的未验收方法现在也返回 `ErrNotImplemented`；依赖这些方法的插件需要先评估升级。52 个已接通方法及消息子类型范围见 [README 完整清单](../README.md#当前状态)。新增群管理/媒体适配和直接入口完成离线验证，完整真机链路仍待复验。用法见[直接接入](直接接入.md)。

## v0.4.1：兼容正式 Release 命名

支持 `we-clay-core_<tag>_<goos>_<goarch>` 附件，同时保留不带 tag 的旧命名和本地缓存。
匹配版本与平台后再校验 SHA-256，适配 core-release v0.3.0 的实际产物。
we-clay 模块版本为 v0.4.1，core 版本为 v0.3.0，两者独立发布。

## v0.4.0：Run 管理 core

设置 `Config.Core` 后，Run 自动下载指定 Release 的当前平台二进制、校验 SHA-256、复用缓存、启动 core，并等待 Mac 登录。取消 Run 时回收它启动的子进程；不设置 `Core` 时保持 v0.3.0 的外部 core 行为。

新增 `CoreConfig`，没有改动 proto、SDK 或 core 的编译依赖。发布附件见 [core 发布指南](core发布.md)，配置见 [运行指南](运行指南.md)。

## v0.3.0：上层以库形式嵌入

- 原上层组件改名为 **gateway**，公共入口为 `gateway.Run(ctx, gateway.Config)`。
- 移除原 `main`、CLI 参数和独立上层编译产物。由开发者自己的 `main.go` 管理信号、日志和退出码。
- 原实现移入 `gateway/internal/`；SDK 仍在 `sdk/`，整个仓库只有根目录一个 `go.mod`。
- `DataDir`、`PluginsDir` 显式配置，不再通过更改进程工作目录切换数据位置。
- 联系人和群缓存改为按账号隔离的子目录；旧缓存不自动搬迁，第一次启动会重新从 core 读取。
- 管理者 `Owner` 为空时不再执行管理命令，避免默认配置开放管理权限。
- `core_address` 和 `core_token_env` 等 TOML 字段保留，但读取配置变为可选的 `gateway.LoadConfig`。

开发者在自己的项目执行 `go get github.com/we-clay/we-clay@v0.3.0`，然后使用 [README Example](../README.md)。
无需克隆本仓库，不需要 core 源码。原 SDK 导入路径保持不变。

## 协议与进程

插件仍通过 SDK 与 gateway 使用 gRPC；gateway 与 core 使用 `Invoke` 和 `Events` 双向流。
现有 protobuf package、字段编号和 RPC 服务名保持不变；协议中的 `HostService` 是保留的服务标识，
不代表仍需运行旧的上层程序。支持 `weclay.core.v1.CoreService` 的已有 core 可以继续使用。

core 仍以独立进程运行，可由 Run 启动或外部管理。浏览器使用它的 HTTP 登录页面；gateway/core 业务通信使用 gRPC，gateway 不监听 HTTP 回调。
插件仍为独立进程；SDK 和 gateway 是库，不需要单独部署 SDK 或 gateway 可执行文件。
同一 core 只允许一个事件订阅者，升级前先停止旧的上层运行程序。

## 历史仓库

本仓库由原 `we-clay/host`、`we-clay/sdk` 合并而来，旧仓库保留历史参考。
core 继续独立维护，没有把源码、账号状态、真实消息、旧二进制或旧 Git 历史导入本仓库。
原始 MIT 许可证及作者署名保留。

本次变化完成离线验证，未执行真实微信操作；不代表所有接口均已完成真实验证。
自动下载与启动在 v0.4.0 接入，v0.4.1 已验证 core v0.3.0 的 macOS ARM64 附件下载及启动至扫码页面；未扫码登录账号。
