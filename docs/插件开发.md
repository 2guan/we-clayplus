# 插件开发

## 依赖方式

gateway 与 SDK 共用 `github.com/we-clay/we-clay` 模块。插件导入 `sdk/` 下的包，
无需导入 `gateway/` 实现，也不需要 core 源码。运行插件需要 gateway，gateway 再连接 core。

本模块已公开，普通接入无需 GitHub 凭据或专门设置 `GOPRIVATE`。
独立 core 源码仍为私有，开发插件及编译应用只需要本模块。
如果已有覆盖本组织的 `GOPRIVATE`，Go 会直接通过 Git 拉取；可保留原配置，无需覆盖其他私有模块设置。

在你自己的插件项目中：

```sh
go mod init example.com/my-plugin
go get github.com/we-clay/we-clay@v0.4.1
```

本仓库内部的 `examples/plugin/` 共用根 go.mod，不需要另建模块。
独立插件是另一个项目，有它自己的 go.mod 是正常的。

## 最小插件

保存为独立插件项目的 `main.go`：

```go
package main

import "github.com/we-clay/we-clay/sdk/plugin"

type Demo struct{}

func (*Demo) GetMetadata() *plugin.Metadata {
    return &plugin.Metadata{
        Name: "demo",
        Version: "0.1.0",
        Description: "最小插件示例",
    }
}

func main() {
    plugin.Start(&Demo{})
}
```

编译 `go build -o we-clay-plugin-demo .`，放入 `gateway.Config.PluginsDir` 指定的目录。
这个最小示例只展示插件注册，不订阅事件或发送消息。
完整的生命周期、消息、命令、配置与能力注入参考仓库的 `examples/plugin/`。

需要消息能力时使用：

```go
import (
    "github.com/we-clay/we-clay/sdk/message"
    "github.com/we-clay/we-clay/sdk/contact"
    "github.com/we-clay/we-clay/sdk/plugin"
)
```

这只是导入片段；能力声明和注入方式请沿用完整示例。
SDK 不会自行登录微信，插件业务连接由 gateway 注入，不直接指向 core 的 gRPC 端口。

## 本地开发

修改仓库内的示例后在仓库根目录执行 `make example`，无需 replace 或 go.work。
独立插件与本仓库联调时，可以在二者的父目录使用本地 go.work：

```sh
go work init ./we-clay ./my-plugin
```

这些路径以你实际目录为准。go.work 只用于本地联调，不提交到本仓库。
发布前用 `GOWORK=off go build ./...` 验证独立插件使用已发布模块也能编译。

## 从旧 SDK 迁移

将 `github.com/we-clay/sdk/...` 改为 `github.com/we-clay/we-clay/sdk/...`，
更新 go.mod 依赖后执行 `go mod tidy` 并重新编译插件。
gRPC 服务名和字段编号保持原有值，握手标识统一改为 we-clay。旧插件二进制必须更新 SDK 并重新编译，文件名使用 `we-clay-plugin-` 前缀。自定义插件逻辑仍应按需进行联调验证。
