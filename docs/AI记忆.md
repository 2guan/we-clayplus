# 回复上下文与 AI 记忆

自动回复把当前消息、近期对话、引用资料和长期记忆分别组装。聊天归档仍保留在本地，升级不会把已有聊天自动转换成长期记忆。

## 开启与使用

管理员进入「模型中心 → 记忆设置」。三个开关独立控制，升级后默认关闭：

| 配置 | 作用 |
| --- | --- |
| `memory.enabled` | 在回复中检索已确认记忆 |
| `memory.direct_enabled` | 接受已开启记忆的私聊联系人明确提出的本人低敏偏好 |
| `memory.scan_enabled` | 允许管理员手动从聊天记录生成候选 |

在微信会话设置中打开「启用长期记忆」，才允许该会话直接记忆或注入记忆。打开扫描权限后，管理员仍需进入具体会话点击「从聊天记录更新」，不会自动扫描所有会话。关闭扫描开关会阻止后续候选写入。

直接记忆使用明确前缀 `记住：`、`记住，`、`请记住：` 或 `请记住，`。首版仅自动确认可确定的称呼、回复语言/详略/表情习惯，以及有限的饮食偏好，例如「记住：叫我小林」「请记住，回复简洁一些」「记住：不吃辣」。其他低敏请求进入候选，敏感请求不自动保存。冲突会保留证据并进入冲突状态；机器人只有在实际保存成功后才有依据表示已记住。

群共享事实、群内成员的个人记忆、机器人状态均由后台审核。群内没有自动确认的「记住」权限；机器人状态只能手动维护，不能从 AI 自己的发言中抽取。

## 近期对话与互动记录

模型中心每个模型的「上下文条数」「上下文 Token 预算」优先生效，填 0 继承全局设置。模型故障切换时，按下一个模型重新裁剪。预算使用保守字符估算，并保留本轮消息、时间/身份、系统规则和输出空间；必要引用也无法容纳时明确终止该次请求。

近期对话仅选择同会话有效消息，本轮消息只出现一次。历史合并为一个文本参考块，每条仅列时间、发言人和正文；当前账号发言统一标为「本人」，同名成员按稳定协议身份加临时编号。发送失败、结果未知、撤回和内部通知不作为有效历史；拍一拍作为互动事件保留，不当作普通系统噪声丢弃。

请求通常只包含系统规则、历史参考和本轮信息三条消息，不再附加 assistant 身份 JSON。完整身份 ID、会话 ID、状态及证据映射保留在服务端；@、拍一拍和引用在文本中显示简短关联。模型若误返回标准聊天记录包装，发送前只提取有效正文并继续执行安全检查；历史归档不改写。

本轮提供服务端北京时间、私聊/群聊、本人称呼、当前发言人、@ 成员和 @ 全体、引用关系；协议身份在服务端完成核对。拍一拍保存协议中的发起人和被拍者；缺少协议 ID 时标为未知，不根据昵称或模板猜测。正文粘贴的 XML 不会被识别成真实系统事件。

明确引用优先提供同会话原消息与邻近记录；「昨天」「前天」「上周」「上次」只在本会话按时间或关键词补充少量证据。普通闲聊不会主动注入多天旧记录。发给模型的当前时间与历史时间统一转换为北京时间，跨日显示日期标题；无可靠来源的状态仍为未知。

## 扫描、审核与来源

1. 从微信会话的「记忆」入口进入当前范围，或在「模型中心 → 记忆与审核」选定会话。
2. 点击「从聊天记录更新」，核对时间范围和模型。选中的聊天原文会发送到该模型；抽取出的敏感候选不会自动持久化，并显示跳过提示。这不代表发送前会自动删除聊天中的全部敏感原文。
3. 页面显示进度。扫描按入库顺序增量处理、固定本次上界，可取消；失败、取消或进程重启后可续扫。新到消息在下一轮处理。
4. 查看候选的内容、主体、可见会话、来源和有效期，再确认或拒绝。普通聊天偏好需要重复证据；明确请求可形成单条待审候选。
5. 冲突候选不会注入回复。确认其中一项后，旧冲突项保留为被替代记录；拒绝和删除的候选不会在续扫中反复出现。

敏感记忆需要手动录入并明确勾选「同意保存」；允许发送给模型是另一项独立授权。只同意保存并不允许注入。来源消息删除或撤回后，相关记忆立即停止使用；重放原事件也不会恢复已删除来源。过期事实立即停止注入，不等待清理任务。

个人主体和可见会话分别保存。私聊记忆不会进入群聊；群内成员记忆只在其本人发言、当前群范围内可用，群共享记忆也不会自动变成某个成员的个人事实。每个微信账号使用独立分区。账号切换取消旧任务，切回原账号也不会接受旧任务结果。

## 查询与本地数据

「模型中心 → 记忆与审核」支持筛选、分页、编辑、确认、拒绝、过期和删除，以及来源和变更记录。编辑后的内容重新进入待审状态。「当前可用记忆」是检索预览；「本次回复依据」按任务 ID 查询实际候选模型采用的消息 ID 和记忆版本，两者含义不同。

独立 SQLite 表保存记忆、来源索引、变更、扫描游标和归档事件。记忆正文、变更内容、扫描结果和归档消息使用现有本地密钥加密；索引保留账号/会话/消息 ID 等检索元数据。旧消息仅在手动扫描时补充归档索引，不冒充原始接收事件。密钥与数据库必须一起妥善保管，不得上传仓库。记忆内容不加入全量 `/api/state` 或普通任务/日志输出。管理接口只允许管理员访问。

生成前重新检查来源与权限，生成后再校验实际使用的来源和记忆版本；生成过程中来源失效、配置关闭或账号切换时丢弃结果，避免继续发送过时事实。

## 验证与回滚

离线回归覆盖四类供应商的实际 HTTP 请求、模型切换预算、@/拍一拍/引用/撤回、加密重启、权限与数据隔离、冲突/过期、扫描取消续扫及页面操作。测试全部使用合成数据、回环 HTTP 服务与独立 Mock，不调用真实微信。

本次未使用真实请求归档，也未进行微信真机写操作。不同客户端产生的事件字段仍需要后续授权的 Mac 模式实测；无法识别的身份不会补猜。首版使用关键词和明确类别检索，不含向量数据库；临时表达按来源消息时间采用保守期限，管理员可在审核时调整。

紧急回滚先关闭 `memory.enabled`；同时关闭会话记忆和另外两个写入开关即可停止记忆使用与新候选生成。聊天归档和已有记忆保留，恢复开关后继续可审核；代码回滚前备份数据库及密钥，保留独立表，不做破坏性降级迁移。

## 精简规则与按需能力

历史条数与预算仍按实际模型配置计算，容量按最终文本渲染结果估算，不再按本地归档 JSON 的长度提前裁剪。普通闲聊不携带群名、公告或备注工具；只有当前正文含明确操作请求，且权限检查通过时才提供对应工具。模型返回本轮未提供的工具调用会被拒绝。语音与图片协议只在本轮请求或回复模式需要时注入，用户自定义发送要求仍保留。

三个记忆页签位于模型中心的「行为与任务」之后，依次为「记忆与审核」「记忆设置」「本次回复依据」。旧记忆链接会自动进入模型中心并保留会话、筛选与任务参数；仅管理员可见，微信会话里的「记忆」入口直接进入对应会话范围。
