# core 在线运行授权

> we-clay v0.7.0 提供下述配置，core v0.4.0 起要求运行授权。升级前取得维护者签发的 Key，并确认目标 core 的 Actions/OSS 发布完成。旧 core v0.3.3 及以前不受此机制限制。

## 谁负责

在线授权由 **core 自己执行**。gateway 负责启动 core、传入环境变量和观察进程状态。直接运行 core 也需要授权；`KeepAlive: true` 时，应用退出不影响 core 自己续期。

下载 OSS 凭据、本机 API Token、运行授权 Key 分别管理；不要复用。OSS 权限只控制下载，不能代替 core 运行授权。

## 默认接入

通过本机可信的环境配置工具提供 `WE_CLAY_AUTH_KEY`。不要把 Key 写入 Go 源码、TOML、命令行参数或 Git。
原有 `gateway.Run` 代码不必为默认变量增加字段。授权 Key 会以固定环境变量传入 core，值不会保存到 gateway 的进程记录。

多个 core 使用不同 Key 时，指定各自的环境变量名称：

```go
cfg := gateway.Config{
    CoreAddress: "127.0.0.1:8188",
    Core: &gateway.CoreConfig{
        Version: os.Getenv("WE_CLAY_CORE_VERSION"), // 已发布的带授权版本
        OSS: &gateway.OSSConfig{Bucket: "weclay", Region: "cn-beijing", Prefix: "core"},
        DataDir: os.Getenv("WE_CLAY_ACCOUNT_B_DATA"), // 独立的固定绝对目录
        LoginAddress: "127.0.0.1:8186",
        KeepAlive: true,
        AuthKeyEnv: "ACCOUNT_B_AUTH_KEY", // 变量名称，不能填 Key 值
    },
}
```

TOML 对应 `[core]` 中 `auth_key_env = "ACCOUNT_B_AUTH_KEY"`。同一个 Key 也可以用于多套部署，同时在线上限由维护者签发授权时设置；端口和账号目录仍需分别隔离。

已有独立 core 继续使用启动时的 Key；更换环境变量值后先 `gateway.StopCore(ctx, cfg)`，再 Run。gateway 根据私有进程记录里的单向摘要检测明确的新 Key，防止配置变更被默默忽略。StopCore 不会因新 Key 与记录不同而拒绝停止。

## 失效和恢复

- core 每次启动必须联网获得签名租约。Key 无效/到期/撤销、超出实例数或者授权服务无法访问，都会启动失败。
- 租约最长 15 分钟，每 3 分钟续期。网络中断只在剩余租约时间内继续运行；明确拒绝或租约到期后 core 停止连接、退出，gateway 的 Run 返回进程退出/连接中断错误。查看账号目录里的 `core.log` 可以得到不含 Key 的原因。
- 不会调用微信退出登录，也不会重建设备。处理授权问题后，继续使用同一个 DataDir 重新 Run；微信会话自身已失效时才按登录流程重新扫码。
- 正常退出尽力释放名额；强杀/崩溃/网络失败最多占用到原租约过期，期间可能暂时无法启动替代进程。
- 授权故障不要无限重启、自动重新扫码或删除设备文件；这些操作不能修复运行授权。

运行授权不能保证防止本机二进制被修改；旧免授权版本也不会被新服务追溯限制。签名私钥和管理服务属于维护者，无需分发给机器人开发者。
