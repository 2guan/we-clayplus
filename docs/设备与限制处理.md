# 设备与限制处理（源码待发布）

## 升级时保留原账号目录

托管 core 的 `Core.DataDir` 现在必须显式填写绝对路径。不要为了修复配置报错新建目录：先找到原有 `runtime/core` 的绝对路径并使用它。程序不会自动迁移、复制或删除设备/会话文件。

```go
Core: &gateway.CoreConfig{
    Version: os.Getenv("WE_CLAY_CORE_VERSION"),
    DataDir: os.Getenv("WE_CLAY_DATA_DIR"),
},
```

`WE_CLAY_DATA_DIR` 由上述应用代码读取，不是 core 自行读取的隐含配置。改变工作目录或升级二进制都应继续使用同一路径。gateway 始终传 Mac 和关闭版本自动更新的启动参数；已有档案类型冲突由新版 core 拒绝，不会改写原档案。

## 获取原始错误码

```go
import "github.com/we-clay/we-clay/sdk"

// err 是任一业务调用返回的错误。
if problem, ok := sdk.AsCoreError(err); ok {
    switch problem.Category {
    case "restricted", "rate_limited":
        // 停止对应自动操作，交由操作者处理微信提示；不要自动重新登录或重试。
    }
    // problem.WeChatCode 是 *int32；nil 表示原始码未知，不能按 -1 猜测。
}
```

直接 Client 与独立插件都支持上述方法。旧 core 的错误文字仍保留，但没有结构化原始码时不会推测。
`OnReady` 只表示会话就绪；不表示微信的所有功能可用，不能据此自动重试先前受限的写操作。

新版 core 的本地限制会跨重启保存。维护者通过已鉴权的 gRPC Invoke 查询 `GET /api/runtime/restrictions`；完成实际验证后再显式调用 `POST /api/runtime/restrictions/clear`，body 如 `{"scope":"moments_write","verified":true}`。这只清除本地记录，不能解除微信服务端限制。同步普通业务错误暂停可用 `POST /api/runtime/sync/resume`、`{"reviewed":true}` 明确恢复；存在同步限制时必须先处理限制。

## 兼容性边界

- 本次 core 移除备注请求的手机版本覆盖。历史备注成功记录不能代表新行为已通过；仍保留读回和不自动重发的保护，须重新验收。
- 入群网页 UA 已恢复原版 v0.3.3 行为：扫码入群使用原版默认值，并保留 A8Key 返回请求头的覆盖优先级；确认邀请不显式设置 UA。撤回上一轮自定义 we-clay UA，登录模式仍为 Mac；已做离线回归，真实入群仍待验证。
- 朋友圈连续两次调用若会复用同一个秒级 ClientId，新版 core 会在发送前拒绝；原 wire 格式保持，跨进程业务幂等仍需应用处理。
- 系统消息发送者不在联系人缓存时，以协议用户名构造最小 Contact；不伪造昵称、好友关系或联系人详情。
- ClientCheck 只增加被动诊断，尚未实现合法应答；不保证解除异常提醒，也不伪造官方签名或采集本机硬件资料。
- 没有做真实账号操作。源码测试通过不等于新 core 已发布；需构建和发布新版后再固定其 tag。已发布版本号及附件本轮不更改。
