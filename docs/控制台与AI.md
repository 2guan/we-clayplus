# 控制台与 AI 基础插件

作者：2guan。此文描述当前代码实际实现的边界；“仅预览”选项不是已经完成的真实能力。

## 脱机体验

在仓库根目录运行：

```sh
make mock
```

打开 `http://127.0.0.1:8208`。这条命令复用 `gateway.Run` 的显式测试入口，没有增加上层 main 或 CLI。
按 Ctrl+C 结束。首次构建可能需要下载 Go 依赖；依赖齐备后，Mock 运行期间不下载或启动 core、不连接微信、不访问模型供应商。
前端资源已嵌入 Go，日常预览不需要安装 Node.js，也不依赖字体、图标或 CDN 外链。

Mock 只允许监听回环 IP，并限制请求 Host。默认使用 `runtime/mock-console/mock.db`，不会读取真实控制台数据库。
数据、账号、联系人、消息、图片和统计均为虚构。示例音频为合成提示音，不是人物语音；识音频结果是固定演示文案。

可通过环境变量指定本机预览地址和数据位置：

```sh
WE_CLAY_MOCK_ADDRESS=127.0.0.1:8208 WE_CLAY_MOCK_DATA_DIR=./runtime/demo make mock
```

顶部“脱机 Mock”面板提供正常、空数据、微信离线、发送／模型失败场景，以及登录页、首次初始化页的外观预览。
切换场景会重建虚构数据；重置不会删除正式数据库。登录页预览不会创建正式账号。

建议依次验收：

1. 总览：账号、消息和 Token 指标、趋势、运行状态；切换亮色、暗色、跟随系统。
2. 微信：统一的私聊／群聊列表、分类表情选择、粘贴图片／文件并预览发送、文字合成语音后试听发送、媒体播放、引用、撤回、置顶、人工接管、专属人设／模型、清空记忆。
3. 通讯录与朋友圈：好友／群筛选、备注、会话入口；虚构动态的发布、点赞、取消赞、评论。
4. 模型中心：六页签管理、厂商目录、逐模型测活与参数、对话、语音、图片与视频独立流水线、语音试听、图片与视频预览、人设优化、行为权限和任务记录。
5. 插件、洞察、日志、设置：启停 AI、生成演示报告、日志筛选／暂停／导出、表单保存、历史恢复、用户角色页面。
6. 手机宽度：微信列表和聊天分为独立页面，返回列表；底部微信式导航；输入与弹窗不横向溢出。

## 默认注册与接入

`gateway.Run` 默认在 core 登录前启动 Dashboard 服务；AI 共享同一个状态库、模型配置和任务执行器。
真实模式在原有插件管理器中注册 `dashboard`、`ai` 两个内建插件，仍保留 `pm`、`cm` 及外部插件机制。
保留原有协议名称，不引入第二个 go.mod，不导入私有 core 源码。

启动配置在 `gateway.Config.Console`（类型 `*control.Config`）或 TOML 的 `[console]` 中设置：

```toml
[console]
address = "127.0.0.1:8208"
data_dir = "./runtime/console"
mock = false
disabled = false
disable_ai = false
```

没有设置 `Console` 时，数据目录默认为 Gateway 数据目录的同级 `console`。
`gateway.WithoutDashboard()` 只关闭 Web 监听；AI 可继续为插件提供能力。
`gateway.WithoutAI()` 关闭 AI 调用；`gateway.WithoutPlugins()` 保持关闭全部插件的原有语义，并与 Mock 配置互斥。
端口冲突会明确报错，启动失败不会静默忽略。

首次真实模式访问控制台，直接设置登录名及至少 6 位密码，创建管理员，无需初始化凭据。
控制台登录与微信登录是两个独立步骤；当前微信扫码／验证仍使用 core 原有登录页面。
core 登录失败或进程退出时遵守现有 Run 生命周期，控制台不会单独留在后台运行。

## 页面与配置组织

右上角主题按钮展开绿色（默认）、蓝色、红色、橙色和灰色五色色板，选择后立即生效并收起；紧邻的显示模式按钮依次切换亮色、暗色与跟随系统。色板是按钮下的小浮层，不打开居中弹窗。
配色覆盖全部控制台页面、聊天、图表、弹窗及登录／初始化页面；登录前也可从右上角切换。
外观即时生效，偏好保存在当前浏览器，刷新后保留；不改变其他用户的外观。在线、警告与错误状态保持独立语义颜色。

| 页面 | 内容 |
| --- | --- |
| 总览 | 账号资产、今日消息、Token、任务结果、近 7／14／30 天及自定义日期统计、服务状态 |
| 微信 | 会话列表、消息、媒体、接管、专属策略、朋友圈入口 |
| 通讯录 | 好友／群列表、搜索、备注、资料与聊天入口 |
| 模型中心 | 对话模型、语音模型、图片模型、视频占位、提示词管理、行为与任务 |
| 插件中心 | 基础插件说明、AI 启停、演示扩展插件 |
| 智能洞察 | 左侧配置、右侧报告；拼音搜索对象、自定义正整数条数、重点示例、报告切换与导出 |
| 实时日志 | 控制台结构化日志、级别／组件／关键词筛选、暂停和导出 |
| 系统设置 | 品牌、存储、会话安全、提醒、用户与权限、配置历史；修改密码从左下角用户信息进入 |

设置由 Go `Schema()` 统一定义字段、默认值、范围、权限和是否“仅预览”，浏览器与后端共用。
配置修订号独立于消息版本号；后台收到消息不会使正在编辑的设置失效，但另一次配置修改会阻止陈旧覆盖。
对正在编辑的设置，站内跳转和关闭浏览器提供未保存提示。历史恢复只作用于对应快照的字段。

## 当前可执行能力

- Mock：全部页面、六类 AI 固定结果、会话和朋友圈的本机操作、失败／空数据场景、设置保存、任务状态可验证。
- 真实 AI：OpenAI 兼容协议的对话、识图、转写、标准 TTS、返回 `b64_json` 的图像生成；Gemini 文本／图片／音频／原生视频理解；Anthropic 文本与图片理解。
- 每个模型必须正确声明支持的能力。适配器不支持的组合会报错，模型列表声明本身不代表供应商已经验证可用。
- 并发上限、每日调用次数、超时、最大输出、TTS 长度／语速、图片大小限制、图片提示词风格补充已经接入。
- 默认对话、语音、图片与视频生成按各自流水线顺序调用，失败或超时后切换，成功立即停止。语音只在同一模式（TTS、声音设计、声音克隆）内切换；显式指定模型只调用该模型，微信写操作不自动重试。视频已受理但结果未知时停止切换，取消任务中止本地等待，不承诺取消远端任务。超时的厂商请求仍可能计费。
- 自动回复默认关闭，必须同时启用全局开关、通过名单规则、将会话设为自动、配置可用模型；默认使用空黑名单，不排除好友和群聊。普通群消息按配置概率触发；@ 与引用判断仍未开放，不作推断。支持私聊关键词、静默时段、会话冷却、独立人设／模型、消息数／有效期和保守字符预算。
- 人工发言可切换为人工接管，生成完成后再次检查接管状态。当前接管需要手动恢复，定时恢复标为仅预览。
- 真实微信已桥接联系人缓存、消息归档、文本／图片／文件发送、文字合成后发送原生语音、SDK 撤回、备注、群名和公告入口。撤回复用 SDK 保存的原始回执，不伪造客户端 ID；只允许已确认发送的本账号消息。
- 会话数据按微信账号分区保存与恢复，避免串入另一个账号的聊天、任务和专属策略。

插件可通过 `CallPlugin("ai.chat", args)` 等能力提交任务，返回 MIME `application/json`，内容为 `{id,status}`。
支持 `ai.chat`、`ai.vision`、`ai.audio`、`ai.video`、`ai.tts`、`ai.image`；通过 `ai.task` 和 `id` 读取任务结果。
输入为字符串 map：`prompt` 必填，其他包括 `system`、`model`、`media`（Base64）、`mime`、`filename`。
此入口不会附带微信发送副作用，也不能越过 AI 停用、并发和预算限制。

## 聊天输入与语音发送

会话与通讯录的专属策略支持从人设库载入提示词，也可自定义输入或选择继承全局人设。
载入后可继续编辑，保存的是当前会话的独立副本，不修改人设库，也不随后续库中修改自动变化；提示词留空则恢复继承。

表情面板支持分类、中文搜索和光标位置插入，表情为随前端内嵌的 Unicode 字符，无外部服务依赖。
输入框支持粘贴图片和浏览器剪贴板提供的文件，也可使用图片／附件按钮选择；一次最多 8 个，每个不超过 16 MB。
附件先进入可移除的预览队列，点击发送后逐个提交；附带文字独立发送。SVG、音视频文件按附件发送，不冒充微信原生媒体消息。
操作系统未向网页剪贴板暴露的文件，可改用附件按钮选择。

点击麦克风按钮，输入语音文字，再点击“合成试听”；试听后点击“发送语音”。
合成使用模型中心默认路由的语音合成模型，以及已配置的音色、语速和文字上限。
发送始终绑定合成时的会话，同一任务只允许提交一次；结果未知时先核对微信消息，避免重复发送。
Mock 使用固定示例音频验证整套流程，不朗读输入文字，不调用模型或微信，也不需要编码工具。

真实模式由 OpenAI 兼容 TTS 接口输出 WAV；Gateway 使用 `ffmpeg` 转为 24 kHz 单声道 PCM，再调用支持 `-tencent` 的 `silk_v3_encoder` 编成腾讯 SILK。
部署机器需要安装这两个工具并放入 PATH，也可通过 `WE_CLAY_FFMPEG` 和 `WE_CLAY_SILK_ENCODER` 指定各自可执行文件的绝对路径。
命令参数固定，不调用 shell；临时文件处理后删除。缺少工具、编码失败或时长不在 0.02 至 60 秒内时明确报错，不自动截断长语音。
微信发送参数使用毫秒时长和格式 `4`。本机验证覆盖实际编码、语音参数与发送→撤回的回执传递；没有执行真实账号发送。
若 core 返回非数字 `client_id`，现有 SDK 无法满足撤回接口的数字 ID 契约，会拒绝撤回，不伪造该字段。

## 自动回复的文字、语音与图片协议

自动回复始终先检查全局开关、目标名单、会话自动模式、触发策略及并发/每日配额。后台实验室的生成不会自动发到微信。专属提示词优先，空值继承默认人设；服务端额外注入实际可用能力和以下输出协议，旧人设无需重新粘贴。

- 普通聊天建议 1–3 条；双换行（包括 CRLF 和空白行）分条，单换行保留。默认每轮合计最多 5 条，可在全局对话设置中下调。超过上限整轮拒绝，不静默截断。
- `<voice>口语台词</voice>` 使用语音流水线，每轮最多一条；标签不允许属性或嵌套元素。音色由标准 TTS、声音设计或声音克隆模型配置决定，不允许模型用标签切换音色。方括号中的情绪提示作为台词传入供应商，具体表现取决于该模型，并不保证所有供应商支持相同音效。
- `<image prompt="画面描述"/>` 使用图片流水线，每轮最多一张。`ref="selfie"` 使用默认垫图，未上传则读取微信头像；`ref="last"` 只取当前会话最后一张收到的或确认已发送的图片。缺少票据、垫图或模型时明确失败，不降级为另一张无参考图的图片。
- 标签外的文字、语音与图片按原顺序发送。媒体先全部生成并校验，再开始发送；默认间隔 700 毫秒，可在全局对话设置中调整。每条发送前重新检查全局开关、名单、在线状态和人工接管状态。
- 每条发送回执独立归档。发送失败或结果未知时停止，不切换模型重新发送，不补发后续消息；父任务显示失败，已成功发送的内容保留。真实模型用量即便发送失败也统计。
- 只有确认发送成功的图片场景和语音台词进入后续 AI 上下文；失败、发送中和未知结果不作为已发送事实。媒体标签只解析本轮模型输出，不重放历史中的标签。

全局对话设置增加“允许自动发送语音”和“允许自动生成并发送图片”。语音合成设置的“微信回复形式”控制无标签的普通回复：文字保持分段，语音合并成一条语音，“跟随来信”仅在入站语音时合成语音；显式媒体标签优先。后台图片实验室仍只预览，不受自动聊天开关影响。

新收到的图片、语音支持按 `vision.auto` / `audio.auto` 开关识别后回复。SDK 媒体描述加密保存；按需下载受账号与会话绑定限制，最多 16 MB，不允许模型提供任意 URL。SILK 入站语音需要 `silk_v3_decoder`（或 `WE_CLAY_SILK_DECODER`）和 ffmpeg。历史消息若没有下载票据需重新发送，不扫描或重放旧消息。识别资料仍经过防注入检查，不成为系统指令。

MiMo 音频理解使用 `/chat/completions` 的 `input_audio.data` Base64 data URL，按[官方音频理解文档](https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/multimodal-understanding/audio-understanding)适配，不使用 multipart 转写端点。其他 OpenAI 兼容转写服务继续使用 `/audio/transcriptions`。

离线验收：`go test ./plugins/dashboard ./plugins/ai ./plugins/contextcleaner ./gateway/internal/console ./gateway/internal/ability/message`。覆盖解析、限额、混合发送顺序、人工接管、失败停止、跨会话拒绝、上下文排除未知发送、MiMo 请求格式及真实 SILK 编解码。Mock 用内嵌媒体完成流程，不访问微信或真实模型；离线通过不等于真实微信端到端已验证。

## 数据、安全与开发

控制台用户名和 bcrypt 密码哈希保存在本机；会话 Cookie 为 HttpOnly、SameSite Strict，角色在服务器检查。
API Key 采用 AES-GCM 保存，解密密钥为数据目录中的 `credential.key`；此文件和数据库必须一起备份。
它是静态存储保护，不能防御已取得操作系统账号或同时取得数据库和密钥的攻击者。
运行数据目录权限 0700，数据库、密钥和媒体文件 0600；不把凭据返回浏览器，也不记录供应商原始报错正文。
默认回环访问；需要手机访问真实模式时，部署受信任的 HTTPS 反向代理并保持同源。Mock 为本机验收模式，不提供公开免登录服务。

前端开发需要 Node.js 22.12+，Go 构建需要根 go.mod 对应的 Go 版本：

```sh
make dashboard                              # 安装锁定依赖并构建内嵌资源
npm --prefix plugins/dashboard/web run dev   # 代理同机 8208 的开发服务
npm --prefix plugins/dashboard/web exec -- playwright install chromium
npm --prefix plugins/dashboard/web test     # 独立 18899 端口，虚构数据库
make test                                   # Go 全仓库竞态测试
make vet
make build
```

浏览器测试需要已构建最新资源。发布时保留 `plugins/dashboard/assets`，最终程序不依赖 Node。
源码头部标注文件名、主要功能、作者；机器读取的 JSON 和 lock 文件保持其合法格式，编译产物由构建器生成标头。


## 模型中心配置与接口

- 厂商独立保存名称、API 地址、协议和加密密钥，同一厂商的多个模型共享凭据。获取模型支持 OpenAI 兼容、MiMo、Gemini、Anthropic 目录；目录失败时可手动输入 ID。更改地址或协议必须重新输入密钥，避免把旧密钥发送到新地址。
- 每个模型可覆盖超时、温度、思考模式、上下文条数及最大输出；数值 0 表示继承全局（温度留空表示厂商默认）。不同模型接受的思考参数有差异，测活失败会显示真实状态，不会由其他模型代答。MiMo 开启思考时不发送温度参数。
- 语音页提供 TTS、VoiceDesign、VoiceClone。MiMo 按模型后缀选择实际协议分支；声音设计使用描述，声音克隆使用 WAV/MP3 样本。可保存默认语音参数和样本供微信文字转语音使用。官方契约：[MiMo 语音合成](https://mimo.mi.com/docs/en-US/quick-start/usage-guide/audio/speech-synthesis-v2.5)。
- 图片页支持比例、长边分辨率、质量、风格、默认垫图和单次垫图。有垫图时使用图片编辑接口；选择自拍且无垫图时下载 SDK 当前账号头像。没有头像则明确报错；Mock 使用本机示例图。实际尺寸、质量参数必须在所选厂商支持范围内。
- 视频页提供厂商管理、独立流水线、参考图、默认及单次时长/尺寸、生成、播放和下载。新能力标识为 `video_generation`，保留 `video` 的视频理解语义。无参考图时为文生视频，有参考图时为图生视频，默认参考图与图片页分开保存。Mock 固定播放本机样片。
- 视频真实调用限定为 OpenAI Videos **兼容服务**：`POST /videos`（JSON、`input_reference.image_url` 内嵌图片）、`GET /videos/{id}`、`GET /videos/{id}/content`，支持 4/8/12 秒与四种横竖屏尺寸。单模型超时覆盖完整流程，媒体最大 64 MB，只从配置厂商地址取回且禁止重定向。不支持的厂商协议明确报错。请自行配置仍提供该兼容协议的服务；OpenAI 官方 Sora API 已宣布于 2026-09-24 停止，不能将其官方地址当作可用服务。契约参考：[视频接口](https://developers.openai.com/api/reference/resources/videos/methods/create)、[视频内容接口及停服说明](https://developers.openai.com/api/reference/resources/videos/methods/download_content)。
- 默认人设以列表首项保存，切换默认立即影响后续请求。提示词优化通过默认对话流水线生成候选文本，手动采用后再保存，不自动覆盖原人设。
- 行为目录直接嵌入 `gateway/capabilities.json`，不另外维护 core 支持清单。每项独立保存启用、系统提示词、影响范围、黑白名单。当前自动对话工具仅接通文字发送、联系人备注、群名和群公告（OpenAI 兼容 / MiMo），目标固定为当前会话；其余能力只保留策略配置。执行前重新检查 AI 开关、会话接管、回复名单规则和行为名单。空白名单拒绝全部目标，空黑名单不额外排除目标。
- 所有新增读写仍通过同源鉴权 API；厂商凭据、流水线和行为权限只能由管理员修改。旧模型升级时复用原凭据 ID，避免丢失已配置密钥。

本轮验证使用本机 HTTP 契约服务器和脱机浏览器，不代表已对真实模型额度或真实微信操作进行验收。

### 智能洞察的对象与资料范围

- 桌面输入与报告并排占满工作区，手机按输入、报告顺序上下排列；历史报告仍可独立查看。
- 对象搜索支持昵称、备注、微信 ID、全拼及拼音首字母。字典随前端打包，本地搜索不会外发联系人信息。
- 朋友圈候选只保留 `kind=friend` 的联系人，群聊分析只保留群；切换类型时清除不适用的选择。控制台桥接只把 SDK 明确标记的好友映射为好友。
- 朋友圈内容按 `author_id` 精确归属，避免同名内容串入。旧 Mock 的两条内置动态自动补齐作者 ID；缺少作者 ID 的真实历史内容不根据昵称推测归属。
- 条数可填写任意安全的正整数，例如 1000、2000；没有 200 条的页面上限。实际读取选中对象的已归档记录，记录不足时显示实际数量；不会自动补拉微信历史记录。
- 分析资料整体作为请求提交，不套用普通聊天的上下文保留条数裁剪。仍受模型上下文容量与现有请求体大小限制；失败显示在右侧报告，不静默丢弃选中内容。
- 三类分析各有四个重点示例，点击填入后可继续编辑，手动确认生成；报告支持运行状态、取消、切换和文本导出。

### 插件配置编辑

- 卡片名称位于图标右侧，移除能力和类型标签，保留版本、开关及使用、配置按钮。
- 使用按钮位于配置左侧，所有已登录角色均可查看插件介绍与使用说明。扩展插件的命令语法和触发词示例来自已注册的 `CommandSchema`；点击示例原样复制到剪贴板，不会执行命令。没有声明示例时不自动编造触发词；浏览器拒绝复制时提示手动复制。
- 内置插件说明对应网页入口与实际配置条件；Mock 的入群欢迎和每日摘要明确标注为演示插件，不声称执行真实欢迎或定时任务。
- 管理员点击配置，可在可视化表单和 TOML 文本之间切换草稿。字段类型决定开关、数字、文本或列表控件；新增专属字段可在文本模式填写后回到表单。
- Dashboard 与 AI 的配置文本是现有设置的 TOML 表达，保存仍写入控制台数据库，与系统设置和模型中心共用数据。模型供应商密钥继续在模型中心管理；监听地址、数据目录和启动停用项仍使用部署配置。
- 已加载扩展插件读取实际插件目录的 `config.toml`，编辑器只编辑当前插件配置段。保存时校验 TOML、字段类型和名单模式，比较文件摘要，原子替换文件并保留其他插件配置值。文件会重新格式化，不保留原注释和排版。
- 扩展插件保存后由现有文件监听器重载并注入运行实例；第三方插件拒绝配置时记录错误到实时日志，保存成功不代表第三方业务逻辑已验证。
- 读取和保存配置均仅允许管理员；配置内容不进入普通状态响应，专用接口禁止缓存。Mock 使用独立数据库文档，支持保存与重新读取，重置演示会清除对应配置。
- 文本语法错误保留草稿；切换模式不会保存，也不会刷新原编辑版本号。发生冲突时明确报错，用户可重新读取后再修改；关闭未保存的编辑器会提示确认。

### 提示词防护与上下文清洗（第一阶段）

两个基础插件 `prompt_guard`（提示词防护）和 `context_cleaner`（上下文清洗）默认注册并启用。升级仅补充缺失插件及配置，不覆盖已有设置；它们独立于 AI 插件显示，但共用现有任务执行器，不启动额外模型服务。第一阶段负责 AI 请求防护；下文的第二、三阶段业务插件独立配置与启停。

**使用入口**：插件中心卡片提供使用、配置与验证。配置支持可视化及 TOML；验证窗口提供离线验证、规则与范围（防护插件）和处理记录。离线验证使用已保存配置，不调用模型、不发送消息、不修改聊天记录，也不写正式处理记录。

- 防护入口包括微信自动回复、后台模型测试、智能洞察、管理员提示词编辑和跨插件请求。入口身份由服务端确定，HTTP 的 `source`、`context`、`tools` 字段不能伪造服务端权限。
- 标准模式拦截明确的指令覆盖、隐藏提示词提取、权限升级、角色标记伪造和凭据提取；宽泛能力探询仅观察。严格模式扩大输入检查；观察模式不阻止请求。可按会话唯一 ID 覆盖模式，并配置自定义规则的来源、级别、动作和开关。
- 输出中的解释或拒答不被当成输入指令：内置意图规则仅观察，角色分隔符、自定义输出规则、实际凭据和长篇内部人设全文回显分别检查。实际 API 密钥回显的拦截独立于插件开关；这是精确匹配保护，不声称可以识别任何形式的编码泄露。
- 当前消息被阻止时不会创建模型任务；历史或分析资料中的命中内容会从本次模型可见副本隔离。历史每次使用前重新检查，原始归档仍然保留。微信默认静默跳过，可改为固定说明；固定说明受自动回复目标与接管状态校验，有冷却限制，且不会进入后续 AI 历史。
- 清洗按会话隔离，保留发言人、角色、时间和消息 ID；只按事件 ID 去重，不按相同内容去重。清理异常控制字符，历史图片、音频、视频、文件和表情可用文字占位，当前上传文件不被替换。引用消息的文本不作为媒体删除。
- 条数与有效期限沿用现有记忆设置，模型可覆盖条数。请求容量使用保守字符估算，并预留系统提示、工具描述和最大输出；这不是供应商 tokenizer 或模型实际上下文容量的保证。单条最新消息超预算明确失败；分析资料不采用聊天滚动裁剪，超限明确报错。
- 历史和分析资料以 JSON 数据块提供给模型，不能成为系统指令。外部请求的人设补充作为请求文本处理；管理员提示词优化使用独立入口，把原提示词当作编辑素材，且不能执行工具或发送微信消息。
- 输出只删除明确的推理标签及异常控制字符，保留合法 JSON 和 Markdown 代码围栏中的示例。聊天旁白清理默认关闭；报告和编辑结果不应用聊天风格。精确的 `NO_REPLY` / `[SILENT]` 可停止自动发送，空正文不会被随机话术替代。
- 模型输出及解码后的工具参数在保存、发送或执行动作前检查。安全处理失败不切换备用模型；后端原有行为授权和目标检查始终保留。后台测试和普通插件任务没有隐式微信发送权限。
- 正式处理记录只保存时间、任务 ID、来源、阶段、动作、规则 ID 和数量，不保存输入正文或推理内容。记录仅管理员可见，默认保留 7 天、最多 1000 条，页面展示最近 100 条。

**范围与边界**：当前实现是文本规则、资料隔离及后端授权的组合，不保证识别全部提示词攻击；不对原始图片、音频或视频额外执行 OCR/转写来检测隐藏指令。已有模型返回的文字会经过输出处理。自行直连外部服务的第三方插件不会自动获得本处理链，需改接统一 AI 能力。未自动清除或改写旧聊天归档。

**离线验收**：插件内置指令覆盖、正常 JSON 摘要、历史污染、推理清理和提示词编辑示例。Go 测试另覆盖会话隔离、规则校验、JSON 转义参数、实际 HTTP 请求的拦截与故障切换边界、权限与升级；浏览器测试覆盖配置持久化、审计脱敏和手机暗色显示。上述结果不代表已完成真实微信或外部模型的现场验收。

### 启用、配置和脱机验证

- 真实模式中新业务插件默认关闭，白名单为空时不产生自动行为。启用开关与生效名单都必须满足；黑名单模式表示排除名单中的目标。
- Mock 新数据默认启用并允许 `mock-contact-0`、`mock-contact-1`、`mock-contact-2`；升级保留旧开关和已有配置。真实凭据、账号、模型和外部服务都不会被 Mock 调用。
- 配置支持可视化/TOML 双向切换、服务端类型校验与版本冲突保护。菜单、词典、欢迎语和 JSON 字段支持多行文本。
- 每个插件的“使用”页列出介绍、步骤与可复制触发词；“工作台”提供生成预览、确认发送和最近 100 条执行记录。
- 预览绑定账号、目标和已生成的结果，最多保留一小时、200 项；发送消费该预览一次。不会重新抽菜单、重新生成图片或重复调用模型。修改输入后需重新预览。
- 入群欢迎和自动通过提供 Mock 系统事件模拟入口。普通聊天伪造的系统通知不会触发欢迎，网页不能向真实模式提交好友票据。
- 自定义素材按账号隔离，最多 100 个；单个上传最多 8 MiB、1200 万像素。重新编码为 PNG，删除素材条目不删除可能被历史消息引用的图片文件。

### 定时任务的执行语义

每个账号最多 100 项任务。周期表达式为 `分 时 日 月 周`，支持 `*`、列表、区间和步长，周日为 0；例如 `0 9 * * 1-5`。日与周都指定时遵循传统 Cron 的“或”语义。默认时区为 `Asia/Shanghai`，每项周期任务可以覆盖；单次时间由浏览器转换为带时区的绝对时间。

任务运行前先保存下一次执行时间及执行占位。错过超过一分钟的计划不补发；服务中断后将运行中记录标记为中断，不自动重发。发送结果未知时也不自动重试，避免生成重复微信消息。编辑/删除任务、关闭插件、改变账号或名单会阻止尚未发送的操作。业务运行同时最多 4 个，等待事件最多 64 个。

定时调用其他插件时，需要同时满足 `cron` 与被调用插件的启用/名单规则。立即执行属于明确的手动发送操作，界面会确认。任务记录保留最近 2000 条，工作台展示当前账号最近 100 条；去重键使用摘要，不保存好友票据。去重键保留 30 天。

### 外部服务配置

新闻填写公开 RSS/Atom URL。音乐、视频解析和表情搜索使用统一的可配置 JSON 服务契约，便于接入现有服务或自行部署的适配器；没有把第三方不稳定接口硬编码成可用能力。**仅填写普通网站首页不能提供搜索/解析功能**，目标服务必须支持以下契约：

```text
GET <endpoint>?q=<搜索词或分享链接>&url=<同一输入>&limit=5
Authorization: Bearer <可选凭据>
```

响应结构：

```json
{
  "items": [
    {
      "title": "内容标题",
      "url": "https://example.com/share",
      "artist": "可选作者",
      "media_url": "https://example.com/media.mp3"
    }
  ]
}
```

`key_env` 只填写服务端环境变量名，程序从环境中读取 Bearer Key；不要将密钥写进 URL、插件设置或示例。跨域重定向不携带认证头，HTTPS 不允许降级跳转。服务请求使用 25 秒超时，JSON/新闻源最多 2 MiB，媒体最多 16 MiB；公网地址与 DNS 结果均检查，拒绝本机、内网及保留地址。仅接受可识别的图片、音频和视频，媒体经本机受保护路径预览，不让浏览器直接加载第三方资源。

没有配置源/服务时真实模式明确报错，不返回演示成功；Mock 始终返回本地样例，不依赖这些服务。

### 字体与已知接口边界

图片生成使用 `golang.org/x/image` 读取本机字体；词云中文分词使用 `gse` 的内嵌词典，不在运行时联网下载。可在词云、表情包及摸鱼日报分别指定 TTF/TTC 路径。默认寻找 macOS Arial Unicode/Songti、Linux Noto Sans CJK/WenQuanYi 或 Windows 微软雅黑。缺少可解析中文字体时显示明确错误；Linux 部署请预装中文字体或提供字体路径。仓库不复制系统字体。

core v0.3.1 的接受群邀请接口仍为占位，自动通过插件**只处理好友申请**。欢迎插件仅解析上述中文系统通知格式，不把未知格式猜成入群事件。原生音乐卡片、解析服务覆盖的平台和真实微信客户端媒体表现不在离线验收范围内。

本次测试均为脱机、Mock 或本机协议夹具：包括请求参数/失败传播、调度去重、重启恢复、权限、预览快照、规则作用范围、媒体与响应式页面；未登录微信，未执行真实账号写操作，也未用未提供的外部服务凭据做生产验收。


## 本机真实微信验收

执行 `make run` 从私有 OSS 下载并校验 core v0.4.5（Mac 模式），启动真实控制台。运行前通过受信任的本机环境配置提供 `WE_CLAY_AUTH_KEY`；默认由授权服务签发短时 OSS 下载链接，原有 `OSS_ACCESS_KEY_ID`、`OSS_ACCESS_KEY_SECRET`（可选 `OSS_SESSION_TOKEN`）也可继续使用。不要把凭据写入仓库。可用 `WE_CLAY_CORE_VERSION` 指定其他已发布的固定版本。后台访问 `http://127.0.0.1:8208`，core 登录 HTTP 监听 `127.0.0.1:8201`；gRPC 仍为 `127.0.0.1:8088`。普通 `go test` 不会启动真实验收。

首次在后台直接创建管理员账号，无需初始化凭据。真实控制台数据保存在 `runtime/console/`，微信会话默认沿用 `runtime/core/`；已有其他账号目录时，设置 `WE_CLAY_DATA_DIR` 为其绝对路径，升级时不得换新目录。真实数据与 `make mock` 的 `runtime/mock-console/` 隔离。不需要重新编译前端即可切换运行模式。`make attach` 只连接已登录的独立 core，不下载或重启 core。

直接在浏览器打开 `http://127.0.0.1:8201/` 扫码，无需额外浏览器参数。终止 `make run` 会关闭本次启动的服务并保留真实会话，不执行微信退出登录。


### 厂商预设与未登录配置

厂商名称可下拉选择，也可直接输入。选择预设会填入 API 地址和协议，地址仍可编辑；切换到其他地址时清空尚未保存的 API Key 与模型选择，避免带入旧厂商内容。预设只提供连接信息，不代表各类模型能力均已适配；填写密钥后获取实际模型，不支持目录接口的厂商可手填模型 ID。各预设附官方文档入口。

开启 Web 控制台时，core 已启动后的扫码等待不受 LoginTimeout 限制；扫码暂停不会关闭后台，模型和插件配置保持可用。关闭控制台的纯 gateway 模式仍遵守原有登录超时和暂停退出规则。core 进程退出等启动故障仍按原有错误处理。


### 扫码暂停后重试

当扫码弹窗显示“登录流程已暂停”时，管理员可点击“重启 core，重新获取二维码”。后台只重启当前 Run 管理的 core，强制进入 Mac 扫码阶段，保留原账号数据目录；后台服务与管理员会话继续有效。已在线、仍在等待扫码以及外部独立运行的 core 不允许从该入口重启。重复请求串行核验状态，旧二维码在暂停和重启期间隐藏，新二维码通过原登录状态接口自动读取。


### 不重启微信的前端调试

实时日志将系统日志与后台已归档的微信消息按时间合并，展示收发方向、会话、发送者、消息类型、文字内容和状态。选择“微信消息”组件可独立筛选；搜索和导出作用于全部匹配记录，列表每次展开 300 条。媒体只展示类型和文字说明，不把媒体二进制写入日志。此视图不补拉微信历史或绕过 core 的消息接收范围，也不记录好友验证票据。


### 微信数据展示与独立 core 调试

账号头像读取 `account.photo`，经过已认证的同源图片接口加载；该接口只接受微信 qlogo.cn/qpic.cn 子域的图片，限制重定向、格式和大小。会话列表从通讯录及已归档消息合并，未知联系人不会被误标记为好友。朋友圈打开时读取 core 时间线，支持刷新与向前分页；失败会展示错误，而非静默显示空列表。

已登录的独立 core 使用 `make attach` 连接。此入口不会启动或停止 core，后台可单独重启，原来的 8201 登录服务保持运行。前端开发继续使用 8209，API 代理到 8208。不得对仍管理 core 子进程的旧 `make run` 直接使用普通退出操作，否则会一并停止 core。

### 微信结构化消息展示

控制台按原始消息类型解析拍一拍、图片、语音、位置、引用、转账、红包及表情包。拍一拍中的协议账号占位符替换为通讯录名称；位置保留名称、地址及地图入口；引用单独显示来源和摘要。转账、红包展示原始通知；管理员可点击收到的卡片，查看对象后人工领取。缺失票据或未明确确认的回执不会推断为到账。

图片与语音通过登录后的媒体接口按需读取，媒体票据加密保存；语音转换为浏览器可播放格式。表情包通过受限微信图片代理读取，加载失败可重试。常用 `[微笑]` 等文字表情转换为 Unicode 对应图形，并保留原始名称提示，并非微信官方表情素材。过期或上游不可用的历史媒体可能无法恢复。

解析和桌面、移动端布局有离线回归测试；无真实样本的引用消息使用合成协议样本验证。离线验证不代表所有微信媒体均已实测。

### 原生引用回复

引用回复提交原消息 ID 与回复正文，由服务端核对当前账号、目标会话、原消息状态并生成应用消息类型 57。原文加密存储，不接受浏览器提供的原始 XML 或发言人。缺少原始协议、微信消息 ID 或消息已撤回时明确报错，不降级为拼接文字。发送沿用 core `/api/message/app`，保留原始消息 ID、创建时间及 client_id 进入既有回执处理；不自动重试。core 返回非数字 client_id 时，既有撤回保护仍会拒绝，不能保证该引用可撤回。

收到引用后，按同一会话中的原消息 ID 打开已归档图片、语音或文件；引用链接使用协议内合法 HTTP(S) 地址。原消息未归档或已撤回时提示不可用，不伪造媒体内容。引用发送已核对 core v0.3.2 参数校验，并做协议与失败回执离线回归；未执行真实账号的引用发送或发送后撤回验收。


### 表情库：人工与 AI 共用

微信聊天输入栏的贴纸图标展开小型表情包选择器，点击图片直接发送；右下角“管理”进入上传、含义编辑和授权面板。收到的自定义表情与微信专辑表情按资源 MD5 去重，按登录账号隔离；现有归档中保留了原始协议的表情会在启动时补入。专辑分类根据 `productid` 判断。资源链接加密保存，浏览器使用经过认证的图片代理，模型只能看到 ID、名称、含义和标签。

- 可按名称、含义、标签搜索，按全部、收藏、自定义、微信专辑筛选。管理员可编辑、收藏、停用表情。
- 上传支持 GIF、PNG、JPEG、WebP，单个不超过 8 MB，保留原文件字节及动画，不统一转换为 PNG。
- “AI 识别含义”走已有识图模型流水线和任务限额，仅返回建议；动图只分析一帧。点击“采用建议”后仍需保存，不会自动授予发送权限。
- 人工发送选择库中表情，直接走原生表情接口。已收集资源使用 MD5 引用，本地上传表情携带原文件与 MD5。结果未知时停止，不自动重试或自动改成图片发送。
- AI 使用需要同时满足现有会话自动回复条件、回复策略中的“允许自动发送表情”，以及该表情已填写含义、启用且勾选“允许 AI 使用”。新收集表情默认不授权 AI，全局表情自动发送默认关闭。
- 模型使用 `<emoji id="资源MD5"/>` 选择，每轮最多一张并计入分条上限。候选最多 30 个，优先收藏和标签匹配；同一会话不连续重复上一张表情。整个回复先验证，发送前再次检查权限。

脱机 Mock 支持相同的上传、编辑与发送流程，数据在独立的 Mock 数据库；不会调用真实微信发送。正式库不会注入演示表情。图片链接失效时会提示预览不可用，可以上传同一表情原文件恢复本地预览与发送。

core v0.4.2 的 `/api/message/emoji` 接受 `receiver`、`md5` 与可选 `emoji` 文件，不接受 `productid`；专辑信息用于归档分类，不能保证发送后保留专辑归属。新版 core 返回 `revoke_client_id` 与 `revoke_create_time`，控制台归档原始回执后支持撤回；回执缺失时仍禁止撤回，不伪造字段。图片、语音、文件和引用消息的字符串回执保存在现有 `original_client_id` 归档字段中，调用 core 时映射为 `string_client_id`。已对照 core v0.4.2 参数校验并验证发送→归档→清空缓存→撤回及拒绝传播；离线结果不代表本次已完成真实账号写操作验收。


### 人工收红包与确认收款

管理员点击聊天中收到的红包或转账卡片，先查看原发送人和金额，再点击“确认领取红包”或“确认收款”。仅打开卡片不会调用微信资金接口。普通后台用户没有领取权限，AI 行为列表不开放资金操作。红包金额未在原通知中给出时不猜测金额。

服务端从当前账号、当前会话的加密归档读取原始票据，浏览器不能提供或替换领取链接、交易号。红包走 core 的接收与拆开流程，转账走确认收款接口；缺少原始票据、本人发出的通知、非待收款通知和群内转账不会发起收款。已归档但过期的红包/转账仍可能被微信拒绝，字段完整不代表仍可领取。

交易按账号和交易标识持久化去重；重复消息 ID 不会绕过去重。提交中或结果未知时不自动重试，服务重启也不重新提交。只有明确识别到业务成功码才显示“领取回执已确认”；不能识别的响应提示去微信核对。该记录独立于聊天通知，不伪造微信同步消息、金额或到账凭据。

Mock 使用独立数据库演示领取，不调用真实 Host。可选只读归档检查：`WE_CLAY_AUDIT_PAYMENT_DIR=/绝对路径/runtime/console go test ./plugins/dashboard -run TestPaymentArchiveReadOnly -v`，只输出票据完整性统计，不执行资金请求。

已对照当前 core v0.3.2 的实际参数实现 SDK、gateway 与 Dashboard 适配，并验证失败不重试、账号/会话隔离和请求去重。尚未执行真实资金验收。发红包、发转账、支付账户查询继续保留占位，不提供付款入口；兼容支付凭据生成和红包付款确认仍是待补齐的 core 契约。

### 微信置顶与群消息免打扰

联系人详情和增量资料保留置顶、群通知状态：`bit_value & 0x800` 表示置顶；`chatroom_notify=0` 表示群免打扰，`1` 表示正常通知。已用用户提供的置顶好友、置顶群和免打扰群做真实只读对照；不保存测试账号标识。置顶标志也可参考 [WeixinBot 协议常量](https://github.com/Urinx/WeixinBot/blob/master/wxbot_project_py2.7/wechat/wechat_apis.py)。

- 微信已同步的置顶状态优先于旧后台本地设置；同为置顶的会话仍按消息时间排序，不承诺复现微信自定义置顶顺序。
- 免打扰群有未读消息时只显示小红点，不显示数量。内部未读计数继续保留，查看会话后正常清除。
- 未提供字段视为未知；部分位掩码更新不能清除不相关的置顶状态。非群联系人的通知字段不用于推断群免打扰。
- 微信状态可通过通讯录刷新重新同步；已收到的联系人置顶/免打扰增量会更新后台。core 当前同步结构未单独暴露群通知专用命令，因此不能保证每次微信端更改都即时推送，可用通讯录刷新补齐。
- 群折叠样本存在额外标志，但尚未确定稳定含义，本轮不实现折叠分组，也不从免打扰状态推断折叠。

### 默认回复模式

模型中心 → 对话模型 → 全局对话设置，可分别设置好友和群聊的默认模式，初始均为人工。通讯录提供同一配置入口，并允许逐个选择默认、人工或自动。聊天标题的人工 / 自动标签显示当前有效模式，点击后成为该会话的单独设置。

未单独设置的历史暂停会话跟随默认；已有人工、自动或明确暂停设置保持原有行为（明确暂停显示人工）。公众号和系统账号不继承好友或群聊的自动默认值。继承在读取时解析，避免保存、同步或重启后固化为旧默认值。自动模式仍受自动回复总开关、生效名单规则和触发规则约束。

群聊的会话资料与专属策略支持单独设置普通群消息回复概率（0–100 的整数百分比）。默认跟随模型中心的全局群回复概率，界面直接显示当前全局数值；单独设置 0% 表示不随机回复，恢复默认会删除此项覆写。该概率不绕过自动模式、总开关、名单规则、冷却等其他限制。

### 聊天标题资料

点击聊天标题可打开人员资料或群资料。群资料通过 core 的群成员专用接口读取成员头像、昵称和群内显示名，支持成员搜索、群公告查看、群备注编辑。好友资料支持添加、修改、清空备注；保存沿用既有备注接口，不修改对方微信昵称。

当前 core v0.3.2 的公开群接口尚未提供修改本人的群内昵称。资料窗口展示已读取的昵称并提示在微信中修改，不使用修改群名称接口替代，也不伪造保存成功。真实验证只读取资料；备注写入仅在用户点击保存后执行，脱机验证不代表真实写操作已经实测。


回复策略的默认名单模式为黑名单，初始黑名单为空。好友和群聊均通过同一规则判断；通讯录或会话选择自动后，无须再次添加白名单。模型中心可切换黑名单／白名单，两份名单独立保存；升级不会将旧白名单变成黑名单。此设置不会自动开启全局回复开关、改变手动会话或提高群回复概率，也不将公众号和系统账号作为自动回复目标。

### 企业微信账号分类

控制台将 `@openim` 识别为企业微信联系人，保留在聊天入口并在通讯录单列企业微信；`@im.chatroom` 按群聊展示并标记企业微信群。此分类同时处理历史归档、新消息补建及联系人同步，不依据消息是否含文章链接来判断公众号。企业联系人不冒充已确认普通好友，也不展示普通好友朋友圈入口。

现有真实账号验证中，core v0.3.2 的普通联系人详情接口对 OpenIM ID 返回 HTTP 400；现有公开路由没有企业联系人专用资料接口。页面保留已知备注、昵称和头像，未获取昵称时使用明确的类型占位名和 ID 尾号，资料浮窗说明缺失原因。不编造昵称、企业名称或宣称资料获取完成。完整企业资料同步仍依赖 core 补齐专用接口。

### 失败消息重发

本账号发送失败或结果未知的消息可通过右键菜单重发。服务端从原归档重建正文、引用、表情或本地附件，不接受客户端替换消息内容。结果未知需要用户确认可能重复送达；发送中及已成功消息不能重发。新发送收到有效回执后，原失败记录与新消息状态在同一事务中更新；再次失败时保留原记录。历史附件或引用来源缺失时明确报错。此入口是手动发送，不引入 AI 模拟延迟；不用于支付操作。验证使用脱机服务，未对真实账号发送测试消息。
