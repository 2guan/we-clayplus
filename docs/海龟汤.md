# 海龟汤插件

海龟汤是随控制台加载的内建插件，不需要独立进程，不修改 core。真实模式默认关闭；名单默认黑名单，在「插件中心 → 海龟汤 → 配置」启用后，空黑名单对所有会话生效。填写会话 ID 可排除这些对象；切换为白名单时仅允许名单内对象，空白名单不生效。普通 AI 的回复概率不影响游戏消息。

## 开局和指令

在允许的私聊或群聊发送：

```text
来碗海龟汤
来碗海龟汤 职场
来碗海龟汤 悬疑，难一点
```

触发词只匹配整句或后接主题参数，支持首尾空白、结尾标点和对账号的真实 @。普通聊天中提到这句话不触发，引用触发词不另开一局。已有题目时再次开局只重发汤面。

默认开启「群聊开局必须 @ 本人」。群里需通过微信选择真实的 @ 对象，再发送「@当前账号 来碗海龟汤 职场」；手工输入昵称、@ 其他成员或 @ 全体都不算。未 @ 的开局不进入游戏或普通 AI 兜底。可在插件配置关闭此限制。私聊及开局后的提问、提示等不受此开局开关影响，后续提问仍遵守单独的「群聊提问方式」。

| 内容 | 行为 |
| --- | --- |
| 直接提问或推理 | 判断是、不是、无关、信息不足，或要求拆分问题 |
| 汤问 他认识这个人吗？ | 明确提交游戏问题 |
| 提示 | 按预设顺序公开下一条提示 |
| 看汤面 | 重发题目，不清空进度 |
| 看汤底 | 公开答案并结束 |
| 换一碗 | 请求换题，回复「确认换汤」才生效；默认沿用主题 |
| 不玩了 | 结束且不公开答案 |
| 继续 | 恢复暂停的游戏 |

短指令仅在当前会话有对局时被游戏接管。私聊由当前联系人操作；群内所有成员都可提问和取提示，揭晓、结束和换题仅开局者可以执行，使用成员稳定 ID 判断，不依赖昵称。管理员可在工作台暂停、恢复或结束，不会因此发送微信消息。

## 出题和主持

1. 优先使用模型中心的对话流水线；插件指定模型 ID 时只用指定模型。故障切换遵守模型中心开关。
2. 模型须返回题目、完整答案、关键事实、至少两个通关要点和分级提示。结构不合法、字段缺失、额外输出、未知事实及不完整的通关裁定均视为失败；游戏不允许工具调用。
3. 一整条候选流水线失败后，从首个候选再试一轮，总共最多两轮；仍失败才选择同主题、当前会话未玩过的固定题。没有对应题目时明确提示失败，保留工作台重试入口，不悄悄替换主题。出题失败时可重新发送带不同主题的开局消息。
4. 开局后保存题目快照。修改题库、切换模型、重启应用都不会改变这一局的答案。
5. 问答只携带本局固定题目、已公开提示、已猜中事实、必要的近期游戏问答及当前玩家消息。近期条数及容量服从候选模型设置；固定资料装不下会明确失败，不能截断汤底。
6. 常规回复由程序把枚举裁定转换成短文字，提示来自固定题目，避免把模型的自由长文直接发给玩家。通关要求当前完整推理覆盖全部必需事实 ID，程序不会只相信 `solved=true`。

结构校验不能证明题目的语义一定无矛盾，也不能证明模型每次裁定都正确；管理员可查看题目并纠正裁定。内置题为本项目自编示例，不从网络抓取题库。模型出题和主持的质量仍需用实际配置的供应商验证。

## 身份和人设

主持每轮读取当前微信昵称；「主持自称」留空时使用昵称，也可以填写更自然的自称。开场和每隔几轮的裁定会自然带上自称，不逐条重复。表达风格参考提示词页面的默认人设或会话人设，但游戏规则和结构化输出契约独立生效。不会从人设或聊天猜测账号的工作、位置等真实状态。

## 群聊和上下文隔离

自然模式会把当前游戏期间的文字交给主持判断；无关闲聊解除游戏标记，交回普通插件或 AI 回复流程。活跃群可选择定向模式，仅接收 @ 当前账号、引用本会话游戏消息或以「汤问」开头的问题。

每个账号、每个会话最多一局有效游戏。多人提问按持久化入队顺序处理，群内回答关联实际提问成员；不接管本人发送的消息。游戏消息保留在原始归档。公开的汤面、玩家提问、主持回答、提示，以及已经公开的汤底，会按模型的近期上下文设置进入普通回复、主动说一句和历史搜索，并明确标注“海龟汤游戏·虚构”。模型会收到边界说明，不能把游戏角色、经历和偏好当作参与者的现实情况。未公开的对局汤底不读取、不注入；游戏记录继续不作为长期记忆来源，插件关闭后也保留游戏标记。

## 工作台

「插件中心 → 海龟汤 → 工作台」提供：

- **对局**：按会话筛选，查看汤面、提示用量和状态；管理员展开后才显示汤底与关键事实；可暂停、恢复和结束。
- **题库**：新增、编辑、启停、导入和导出。导入为 JSON 题目数组，每次最多 50 道。模型生成的已开局题目可另存为停用草稿，审核后启用。
- **问答与重试**：查看来源消息、裁定、失败原因，纠正当前对局的裁定。纠正只修改主持参考记录，不重复发送微信消息。
- **脱机体验**：仅 Mock 提供模拟消息入口，不连接真实微信或模型；脱机裁定固定为「信息不足」，不代表真实推理效果。

题库导出可作为导入模板。关键事实 ID 唯一；`required` 引用至少两项事实，`hints` 为由浅入深的 1—5 条提示。题库覆盖只影响以后开局的快照。

## 持久化与失败恢复

题库、对局及回合使用现有控制台密钥加密，保存到独立的 `soup_puzzles`、`soup_games`、`soup_turns` 表；已玩固定题的索引保存在 `soup_played`。数据按微信账号和会话隔离，汤底通过管理员接口读取；普通任务列表只展示不含汤底的处理摘要。已有管理员 DEBUG 日志配置仍可能记录完整模型请求及响应，应按原有日志权限管理。

应用重启后保留对局，将未完成回合标记为失败并允许手动重试，不自动补发旧消息。对局变更和待发正文同一事务保存，重试不重新扣提示或换题；发送中断、缺少回执等未知结果禁止自动重发。账号会话更新后旧排队回合也不会自动执行。

默认空闲 30 分钟暂停，下次互动时检查；需要发「继续」恢复。暂停和结束都不自动揭底。模型任务沿用现有用量、并发、提示词防护与上下文清洗限制。

验证使用虚构消息、本地模型服务、脱机浏览器和已有 Host 契约，不执行真实账号写操作。代码测试通过不代表已经完成真实微信或模型供应商验收。部署只需更新上层应用；插件启用和名单配置保存后生效，不需要重启 core。
