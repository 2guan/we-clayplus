# gateway 与 core 的 gRPC 通信

## 进程与模块

直接接入：你的业务 → Client → gateway → gRPC → core，事件通过应用内回调交给业务。
可选插件：插件 → SDK → gRPC → gateway → gRPC → core。事件沿相反方向返回。
gateway、SDK 仍在同一个仓库、共用一个 go.mod；core 是独立仓库和进程。
公共定义位于 `proto/corewire/core.proto`，生成包为 `sdk/corewire`。
core 依赖本模块已发布版本的这个协议包，gateway 编译不依赖 core 源码。

## 两种 RPC，共用一个连接

- `Invoke`：一次业务调用对应一次响应，保留成功结果和错误。登录、消息、联系人、群聊、
  朋友圈、媒体等现有 API 都经过这个入口。
- `Events`：双向流。gateway 首先订阅协议版本；core 返回就绪帧，随后发送带唯一标识的事件；
  gateway 完成现有分发函数后回复 Ack。gateway 不提供 HTTP 服务，不注册 webhook。

`Invoke` 目前保留原 API 的 method/path、query、JSON/multipart 参数与响应封装，
由 protobuf 承载。core 在**进程内**调用共用处理器，不向自己或另一个 HTTP 服务发网络请求。
这是通信层迁移，尚未把每个底层操作重写成独立强类型 RPC。插件已有强类型业务 SDK 不变。
这也保留了参数校验、权限检查、文件名、64 位 ID 和原有业务错误语义。
文件沿用现有上传限制，gRPC 单帧上限含封装为 160 MiB；不是无限流式上传。

## 可靠性边界

- core 在原有本地队列中保存事件，Ack 收到后才持久化确认；断开且未确认的事件会重发。
- 同一 core 只允许一个 gateway 事件订阅，防止多个 gateway 竞争同一个确认队列。
- gateway 自动重新建立事件流，退避 1～30 秒；使用连接保活检测失联。
- gateway 在进程内保留最近 4096 个事件 ID，用于重连去重。gateway 重启后可能重复分发。
- core 队列上限为 1024 个事件；队列满时保留同步游标并报告积压，不丢弃未确认事件。
- 启用直接回调时，OnMessage/OnEvent 成功返回后才确认整个 core 同步批次；回调失败或 panic 停止 Run，不确认该批次、不自动重试回调。
- 一个批次可含多个消息/变更；其中前面的操作可能已成功，重启后整个未确认批次仍可能重放。缓存更新和业务写入不构成事务；资料变更事件由缓存差异产生，重启后也不保证再次产生相同差异。
- Ack 表示 gateway 的分发函数已处理，不代表回调自己启动的后台任务或插件的异步业务已成功或已保存。
  需要严格一次业务效果的插件必须使用微信消息 ID 等持久化去重。
- 业务调用默认 2 分钟超时，不自动重试。服务器开始执行前提交 gRPC 响应头，防止透明重试
  已执行的操作；超时或断线后的结果可能未知，应先核对微信状态，不能直接盲目重发。
- 在队列里等待的已取消业务请求不会再执行；已经提交给微信的操作无法因本地取消自动撤销。

因此“发送事件、接收事件”描述了双向传输，但业务请求仍有明确的结果和错误。
普通请求与事件流分开，等待事件确认不会占用 core 的微信业务锁。

## 登录网页

默认 core 在 `127.0.0.1:8086` 提供 HTTP 登录页面，同时在 `127.0.0.1:8088` 提供 gRPC。
二维码、扫码状态、登录验证和退出 API 都可通过 `Invoke` 调用。
新增 `GET /api/login/view` 返回与页面相同的状态、二维码和验证提示，遵守 API 令牌验证。

HTTP 页面直接由浏览器访问，gateway 与 core 的通信不经过这个端口。
独立界面可以完全使用 gRPC 登录并给 core 传 `-listen ""`；当前 gateway 自身还不提供登录网页，
使用 `Config.Core` 时，Run 启动 core 后等待页面登录，随后初始化能力并触发 OnReady；外部 core 模式需先完成登录再调用 Run。

## 升级

应用接入优先按 [README](../README.md#快速开始) 指定 core Release，由 Run 自动下载和启动；下列步骤适用于独立维护 core 进程的部署。

1. 编译并更新 core 与 gateway，保留原账号数据及存储密码。
2. core 启动时提供 `-grpc-listen 127.0.0.1:8088`，不用 `-push-url`。
3. 按新 `configs/gateway.example.toml` 迁移本地配置；访问令牌仍来自 `WE_CLAY_CORE_TOKEN`。
4. core gRPC 模式忽略保存的旧回调配置，并拒绝同时启用 HTTP 回调；不删除旧配置文件。
5. 完成登录后启动 gateway；HTTP 连接失败不会触发 gateway 自动降级。

本轮为离线验证，未重新登录微信或发送真实消息。
