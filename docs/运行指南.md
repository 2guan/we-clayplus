# 运行指南

## 1. 选择接入方式

- **自己的程序直接处理业务**：使用 `WithHandlers` 获取 Client，收消息、主动发送、操作朋友圈；加入 `WithoutPlugins()` 可完全关闭插件机制。
- **独立插件**：保留 `Run(ctx, cfg)`，加载插件处理业务。
- **混合使用**：传 `WithHandlers`，不传 `WithoutPlugins`。同一消息会经过回调和插件，要明确各自负责的回复规则。

## 2. 在自己的程序里调用

安装模块后，在自己的 `main.go` 中调用 [README 的完整 Example](../README.md#快速开始)。
导入路径为 `github.com/we-clay/we-clay/gateway`，不需要克隆仓库或获取 core 源码。

```go
err := gateway.Run(ctx, gateway.Config{
    Core: &gateway.CoreConfig{
        Repository: "we-clay/core-release",
        Version: os.Getenv("WE_CLAY_CORE_VERSION"), // 填已发布的固定 tag
    },
    DataDir: "./runtime/gateway/data",
    }, gateway.WithoutPlugins(), gateway.WithHandlers(gateway.Handlers{
    OnReady: func(ctx context.Context, client *gateway.Client) error {
        // 登录、缓存初始化和事件订阅完成，可以保存 client 供业务主动调用。
        return nil
    },
}))
```

设置 `Core` 后，Run 首次下载并校验当前平台的二进制，启动 core 并通过 gRPC 等待登录。
看到启动日志后，打开 `http://127.0.0.1:8086` 完成 Mac 扫码。登录成功后初始化缓存，按选项加载插件，完成首次事件订阅再调用 OnReady。OnReady 不代表联系人缓存绝对完整：初始化读取失败仍可能留下空缓存，应处理查询不到的情况。
直接接入的完整消息回复、发送图片、朋友圈点赞和后台调用代码见[直接接入](直接接入.md)。
如果登录页面需要调用受保护的 API，请在页面的访问令牌输入框填写自己的 `WE_CLAY_CORE_TOKEN`。

已有独立运行且已登录的 core 时，省略 `Core`：

```go
err := gateway.Run(ctx, gateway.Config{CoreAddress: "127.0.0.1:8088"})
```

这时 Run 只连接服务，不下载、不启动或停止外部 core。

## 3. 配置

| Go 字段 | 可选 TOML 字段 | 用途/默认值 |
| --- | --- | --- |
| `Core` | `[core]` | 非 nil 开启自动下载与子进程管理；默认 nil |
| `CoreAddress` | `core_address` | `127.0.0.1:8088`，core 的 gRPC 地址 |
| `CoreToken` | TOML 不读取 | 程序传入的令牌，禁止硬编码进源码或日志 |
| `CoreTokenEnv` | `core_token_env` | 令牌为空时读取的环境变量，默认 `WE_CLAY_CORE_TOKEN`；`-` 禁用读取 |
| `DataDir` | `data_dir` | 默认 `./runtime/gateway/data`，按账号隔离的联系人及群缓存 |
| `PluginsDir` | `plugins_dir` | 默认 `./runtime/gateway/plugins`，插件及其 `config.toml` |
| `Owner` | `owner` | 管理者微信 ID，只保存在本地；为空不执行管理命令 |
| `Forbidden` | `forbidden` | 无权限提示语 |

### CoreConfig

| Go 字段 | `[core]` 下 TOML 字段 | 用途/默认值 |
| --- | --- | --- |
| `Repository` | `repository` | `we-clay/core-release`，下载源仓库 |
| `Version` | `version` | 必填，已发布的固定 tag，不接受 `latest` |
| `CacheDir` | `cache_dir` | `./runtime/core-bin`，仓库/版本/平台分别缓存 |
| `DataDir` | `data_dir` | `./runtime/core`，账号状态、设备数据和 `core.log` |
| `LoginAddress` | `login_address` | `127.0.0.1:8086`；`-` 关闭页面 |
| `Stage` | `stage` | `auto`；也可明确指定 `login` 或 `resume` |
| `GitHubTokenEnv` | `github_token_env` | `WE_CLAY_GITHUB_TOKEN`，私有 Release 的读取令牌环境变量名 |
| `StorageEncrypted` | `storage_encrypted` | 默认 false；开启时通过 `WE_CLAY_STORAGE_PASSWORD` 提供密码 |
| `StartupTimeout` | 仅 Go 配置 | 等待 core gRPC 就绪，默认 `2*time.Minute` |
| `LoginTimeout` | 仅 Go 配置 | gRPC 就绪后等待扫码/恢复，默认 `10*time.Minute` |

路径在启动时解析为绝对路径，不修改调用方工作目录。不要让不同进程共用同一账号或插件目录。
自动管理模式新设备固定使用 Mac；`auto` 在发现 `session.json` 或 `session.info` 时选择 `resume`，否则选择 `login`。
恢复失败会返回错误，不删除账号文件，也不自动换设备或改为扫码登录。需要重新扫码时，明确设置 `Stage: "login"`。
原有加密状态应保留原密码；core 从本地存储格式标记识别已有的加密数据。

core 的 API 令牌经子进程环境传递，不出现在命令行参数中。GitHub 下载令牌不会传给 core。
不要打印完整配置或提交运行数据。只接受本机回环 IP，跨机器使用受信任的加密隧道映射到本机。

### 可选 TOML

复制 [gateway.example.toml](../configs/gateway.example.toml) 到本地运行目录后：

```go
cfg, err := gateway.LoadConfig("./runtime/gateway.toml")
if err != nil { return err }
return gateway.Run(ctx, cfg)
```

上例放在返回 `error` 的函数内。文件不是必须的；`LoadConfig` 不连接 core、不下载文件。
相对路径基于调用时工作目录；`cfg.Resolve()` 可补全默认值并验证配置，不创建文件。
旧 `core_url`、`push_*` 字段会被拒绝。gateway/core 的业务调用、登录状态和事件全部使用 gRPC；
只有 Release 下载使用 GitHub HTTPS，浏览器页面使用 core HTTP。

## 4. 下载与生命周期

1. 按固定版本查找当前平台附件，读取 GitHub SHA-256；没有摘要时读取同 Release 的 `SHA256SUMS`。
2. 下载到临时目录，校验大小和 SHA-256 后才赋予执行权限并原子发布缓存。失败时清理临时文件。
3. 有效缓存可以离线复用，每次运行重新计算哈希；改变 tag 才切换版本。不要覆盖已发布 tag 的附件。
4. 检查本地监听端口并启动 core，等待 gRPC 和登录完成，再初始化缓存、按需加载插件、订阅事件并调用 OnReady。
5. 取消 context 后关闭插件、保存 gateway 缓存、释放连接，并回收本次启动的 core。保留设备与账号状态，不调用退出微信接口。

macOS / Linux 先向子进程发送 SIGTERM，最多等待 5 秒后强制结束；Windows 直接结束子进程。
应用需像 README 示例一样处理系统信号并取消 context；若应用被强制终止，不能保证执行清理。
省略 `Core` 时，外部 core 始终由调用方自行管理。

下载失败、登录超时、core 退出或不可恢复的鉴权/协议错误会返回 `error`。core 不会被无限自动重启。
事件流暂时断开仍按既有机制重连。启动失败并清理后可再次调用 `Run`。
每进程仅一个活动 gateway，并发启动返回 `gateway.ErrAlreadyRunning`。多账号请使用独立进程。

## 5. 插件（可选）

使用 `WithoutPlugins()` 时跳过整个插件系统，不创建或读取插件目录、不注册内置命令。
省略它时保留历史行为；没有安装插件也会初始化插件目录及管理器。

在 `PluginsDir` 中放入 `we-clay-plugin-名称`（Windows 带 `.exe`），以及该目录的 `config.toml`。
插件仍为独立二进制；gateway 是你的程序中的库。信号、日志和其他服务由你的 `main` 管理。

[插件配置模板](../configs/plugins.example.toml) 中示例默认禁用。启用前填写白名单及 `reply_enabled`，
阅读 [示例插件说明](../examples/plugin/README.md)。未配置的插件默认启用，添加插件前先准备配置。
插件配置保存后自动重新加载。实际配置可能含账号 ID 和凭据，禁止提交。

## 6. 常见问题

| 现象 | 检查方法 |
| --- | --- |
| GitHub 返回 404 | tag 是否已经发布，是否含对应平台附件，令牌是否有私有仓库读取权限 |
| GitHub 返回 403 / 429 | 检查权限或 API 限流；公开仓库也可通过环境变量提供令牌 |
| SHA-256 校验失败 | 核对附件与摘要；文件不会执行，不要跳过校验 |
| core 缓存无效 | 检查本地文件是否被修改；移除错误中指定的版本缓存目录后重新下载 |
| 地址被占用 | 先停止已有 core，或省略 `Core` 连接它；不会主动终止其他进程 |
| core 启动/登录失败 | 查看 `Core.DataDir/core.log` 和登录页面，日志只保留本地 |
| 恢复会话失败 | 保留状态和密码；需要重新扫码时明确设置 `Stage: "login"` |
| core 连接失败 | 默认 gRPC 8088，不能填浏览器端口 8086 |
| gRPC Unauthenticated | 核对调用方进程环境及 core 的 API 令牌 |
| 收不到事件 | 同一 core 只允许一个事件订阅者 |
| 回调一直没有执行 | OnReady 要等登录、缓存初始化和事件订阅完成；检查是否返回启动错误 |
| 发消息后程序退出 | 回调返回错误会结束 Run；按业务需要处理错误，不要盲目自动重发 |
| ErrClientClosed | 使用新一轮 OnReady 提供的客户端，旧对象不能跨 Run 复用 |
| ErrAbilityPanic | 底层存在占位实现或发生异常；查看直接接入指南的当前限制 |
| ErrAlreadyRunning | 先取消并等待前一次 Run 返回 |
| 插件未发现 | 检查目录、文件名前缀及执行权限 |
| go get 失败 | 本模块公开；检查网络、Go 代理及以前遗留的 Git 认证设置 |

自动下载、缓存校验、等待登录和子进程清理已完成离线验证。
core v0.3.0 已在 macOS ARM64 完成真实 Release 下载、SHA-256 校验、gRPC 鉴权与二维码就绪验证，取消 Run 后子进程退出且端口释放。
本轮未扫码登录账号，未验证登录后的业务操作。协议及可靠性边界见 [gRPC 通信](gRPC通信.md)。

### Go 代理暂时未同步新版本

如果 `goproxy.cn` 的模块或 sumdb 镜像返回 `404 temporarily unavailable`，可以只对这次安装切换代理：

```sh
GOPROXY=https://proxy.golang.org,direct GOSUMDB=sum.golang.org go get github.com/we-clay/we-clay@v0.5.1
```

保留校验，不需要设置 `GOSUMDB=off`。core tag 与 Go 模块 tag 独立，例如模块 v0.5.1 搭配 core v0.3.0。
