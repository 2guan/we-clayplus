# 微信掉线通知与重新登录

## 三层职责

| 层 | 负责 | 不承担 |
| --- | --- | --- |
| core | 判断微信会话、网络重连、维护设备资料、执行二维码/认证/Init/心跳/消息接收，提供状态与重登控制接口 | 机器人界面和业务通知渠道 |
| we-clay/gateway | 通过 gRPC 查询状态并触发 `OnConnectionChanged`；会话离线后取消本轮 Run，使旧 Client 失效；应用再次 Run 时请求 core 重登 | 微信认证报文、设备指纹、二维码轮询 |
| robot | 接收回调，展示掉线提示和登录页，暂停 AI 发送；用户点击连接时调用 gateway.Run | 自己刷新微信 token、复制 core 登录代码 |

## 触发顺序

1. **普通网络故障**：core 尝试恢复传输；这不等于微信会话失效，不要求每次断网都扫码。
2. **微信明确拒绝会话**：同步返回会话失效，续期也被拒绝时，core 停止旧心跳/刷新任务，清零运行时登录状态并释放长连接。账号资料、设备标识与固定 data_dir 保留。core 发布 `phase=login_required`、`online=false`、`can_retry=true`。
3. **通知应用**：gateway 每 2 秒通过本机 gRPC Invoke 查询 `/api/login/view`，只在状态变化时调用 `OnConnectionChanged`；这不是新增微信心跳，也不是发送业务消息。发现离线后，Run 返回可用 `errors.Is(err, gateway.ErrLoginRequired)` 判断的错误，旧 Client 失效。
4. **显式重新登录**：robot 的用户点击“连接微信”，再次调用 Run。gateway 发现 core 可重登后，通过 gRPC Invoke 提交 `POST /api/login/retry`，请求体 `{}`。或者用户在 core 登录页点击“重新扫码登录”。
5. **core 完成流程**：core 合并重复请求，执行 Check → 新二维码 → 手机确认/验证 → 认证 → Init → 心跳及消息接收。失败停在 `login_failed`，保留服务，等待下一次明确重登请求；不会靠重新创建设备恢复。
6. **恢复机器人**：gateway 等待 core 在线，重新初始化当前账号缓存、插件与事件订阅，然后调用 OnReady；robot 此时恢复业务使用。

如果只在 core 页面扫码而 gateway 的上一轮 Run 已结束，需要重新连接 gateway，才会恢复机器人业务。

## 状态与回调

`GET /api/login/view` 新增兼容字段：`phase`（登录阶段）、`can_retry`（可以明确发起重登）。既有 `online`、`status`、二维码及指标字段保留。阶段包括 `authenticating`、`waiting_scan`、`waiting_confirm`、`verification_required`、`online`、`login_required`、`login_failed`、`logged_out`。

新增 `POST /api/login/retry` 复用本机 API 鉴权；HTTP 页面和 gRPC Invoke 调用同一处理器。该入口用于独立 core；嵌入式 core 仍由调用方调用 `login.Check`。

```go
err := gateway.Run(ctx, cfg, gateway.WithHandlers(gateway.Handlers{
    OnConnectionChanged: func(ctx context.Context, state gateway.ConnectionState) error {
        log.Printf("微信状态：%s，%s", state.Phase, state.Status)
        return nil
    },
    OnReady: func(ctx context.Context, client *gateway.Client) error {
        // 到这里，微信会话、gateway 缓存及事件订阅才全部就绪。
        return nil
    },
}))
if errors.Is(err, gateway.ErrLoginRequired) {
    // 展示重登入口。不要无条件循环 Run，避免反复发起登录。
}
```

OnConnectionChanged 与其他应用回调串行执行，可能早于 OnReady；应及时返回，并遵守 context 取消。登录状态在线并不代表 gateway 已完成初始化。回调不携带二维码、访问令牌或微信票据。

当前状态通知复用已有 gRPC Invoke，以本机轮询实现；微信消息仍走既有双向 gRPC 事件流。没有将状态伪装成聊天消息，也没有改变现有 proto 字段。旧 core 支持在线状态检查，但完整的重登控制入口需要本次 core 修复。

## 错误含义

- 微信 `-100: 为了你的账号安全，请重新登录`：当前微信会话被拒绝，必须重新进行微信认证。仅凭此码不能断言微信后台具体判定原因。
- “本机 API 访问令牌”：页面/gateway 访问本机 core 的 Bearer 凭据，与微信 token、短信验证码、设备验证不同。它不能修复微信会话失效。
- 本修复解决本地状态不一致及重登流程恢复，不保证服务端会接受登录，也不绕过手机端要求的验证。

## 验证边界

离线回归覆盖会话拒绝后的状态清零与设备资料保留、取消任务的迟到响应、鉴权后的重登、重复点击合并、认证成功后重新激活接收、gRPC 状态回调以及旧 Client 停用。真实微信重新扫码与后续接收需要另行确认。
