# AI 行为与任务

所有配置位于 **模型中心 → 行为与任务**。只扩展 gateway、SDK 适配和控制台，不修改或重启独立 core。

## 完整接入范围

能力目录继续来自 `gateway/capabilities.json`；AI 参数契约来自 `sdk/control/actions.go`。目录中的 enabled 表示已有接口声明，不等于当前运行的 core、微信账号权限及每个模型均已通过真实验收。

| 类别 | 对话工具 |
| --- | --- |
| 消息（5项） | Send、Forward、Revoke、Pat、Download |
| 联系人（7项） | Get、List、GetSelf、SetRemark、Search、AddFriend、VerifyFriend |
| 群聊（12项） | Create、GetInfo、GetQRCode、InviteMember、SetName、SetAnnouncement、SetRemark、Save、SetAdmin、ListMembers、GetMember、GetMembersDetail |
| 朋友圈（7项） | Timeline、UserPage、Detail、Like、Unlike、Comment、Post |
| 标签（5项） | List、Add、Delete、Update、ModifyContactLabels |
| 收藏（2项） | GetInfo、Sync |
| 小程序（1项） | GetRecord |
| 本人账号（3项） | GetProfile、GetQRCode、UploadAvatar |

共42项。Send 支持文字、@、图片、WAV语音、MP4视频、文件、链接、联系人名片和位置。普通文字回复继续走原有回复协议；图片生成、语音合成和表情库继续使用原有已配置能力。显式发送操作使用本轮已经取得的媒体引用，不能让模型读取任意文件或提交媒体密钥。视频不超过16MB、10分钟，需本机 `ffmpeg` 和 `ffprobe`，可用 `WE_CLAY_FFMPEG`、`WE_CLAY_FFPROBE` 配置路径；语音仍依赖原有 SILK 编码工具。

另11项作为后台配套：媒体CDN的6项上传/下载、朋友圈上传/同步、输入开始/停止通知、主人配置读取。输入通知只跟随当前私聊回复，并与模型推理并行，单次通知请求最多1秒。媒体上传不等于消息或朋友圈已发布。

资金相关6项及安全设备查询2项继续仅限后台人工管理；未实现的退群、踢人、直接加群成员、转让群主、删除好友等在页面显示底层暂不支持，不提供模型工具。不新增或猜测 core 接口。

## 授权配置

每项行为独立配置启用、提示词、目标范围及黑白名单，并增加：

- **允许发起操作的成员 ID**：群聊检查实际发言成员，不使用群ID冒充发起人。新增能力需明确填写；不会因为某群自动回复已开启，就把通讯录、朋友圈和跨会话发送权限交给全体群成员。原有改备注、改群名、改公告留空时保持原有当前会话授权。
- **允许跨会话操作**：仅对有目标的工具生效。开启后仍需通过发起人名单和目的联系人/群的范围、黑白名单；发送到其他会话不修改收件会话的自动回复模式。
- **执行前由后台确认**：写操作进入待确认记录，尚未调用微信。管理员可核对内容及目标后确认或拒绝。确认只执行该步骤，不自动恢复后续模型流程；需要更多操作时重新明确发起。待确认命令最多保留24小时的可执行窗口，确认时重新检查原消息、账号和授权。

影响范围、目标名单针对实际操作对象。账号级读取以当前登录账号作为目标；建群以发起会话作为授权范围，因此需要从私聊发起建群时，应把建群范围设为“全部范围”或“私聊”。邀请入群需先允许邀请能力和发起人，再授权目标群；建群后的继续改名也要允许新群作为跨会话目标。

发起人名单用于工具操作；普通自动回复仍按会话模式、概率、@和回复名单执行。升级保留已有显式启用、名单及自定义提示词，仅迁移完全匹配旧内置文本的三项默认提示词，使其表述与目标授权一致。

## 模型返回与连续执行

使用供应商原生工具调用，正文里的普通JSON不执行。OpenAI兼容与MiMo使用 `tool_calls`，Anthropic使用 `tool_use`，Gemini使用 `functionCall`；宿主保留调用ID并用相应的工具结果消息回传。

多数模型首先看到简短目录及 `actions__Discover`，按需接入最多8项工具的完整参数，避免每条闲聊重复携带全部参数。Anthropic在单次任务内固定已授权工具目录，以保持思考块签名所依赖的上下文稳定。各模型是否真正支持工具调用，仍取决于所配置供应商和模型。

例如用户明确要求建群、命名、通知指定好友：

1. 发现联系人查询、建群、改名和发送能力。
2. 查询已授权联系人，获得服务端生成的临时引用。同名或目标不明确时询问，不能猜测。
3. 调用 `chatroom__Create`，传入 `member_refs`。
4. 使用真实回执返回的 `group_ref` 调用 `chatroom__SetName`。
5. 使用联系人引用调用 `message__Send`，传入精确正文。
6. 模型依据每一步真实结果答复发起会话。邀请只说明已发出，不宣称对方已经入群。

模型不接触好友验证票据、媒体解密密钥、原始XML、任意文件路径或撤回用的原始client_id。服务端为引用绑定当前任务、账号、会话和对象类型；每一步重新检查当前权限、账号及原消息是否仍有效。

单次最多12次顺序工具调用，不并行执行模型提供的多个操作。模型选择意图不依赖固定触发句式；无操作需求直接回复。继续调用同一模型时保留各供应商所需的原始思考块/签名。工具结果中的聊天文字和动态内容仍为不可信资料，不能授予权限。参考供应商契约：[Gemini函数参数与返回](https://ai.google.dev/api/generate-content#FunctionDeclaration)、[Gemini思考签名](https://ai.google.dev/gemini-api/docs/generate-content/thought-signatures)、[Anthropic思考块保留](https://platform.claude.com/docs/en/build-with-claude/thinking)。

近期聊天仍按照选定模型配置裁剪；连续操作证据不静默删除。超过模型上下文预算、全局请求容量或12步上限时明确停止，保留已完成步骤。

## 回执、失败与数据保存

写操作先把操作记录落盘，再调用微信。相同任务内的同一命令不会再次执行；成功时返回已保存结果，运行中、待确认及未知状态不会重放。服务中断后运行中记录改为结果未知，不自动恢复写操作。

初次模型生成仍保留既有流水线和自动补试；一旦进入工具循环，固定模型，不因后续模型超时或输出失败重新执行已发生的微信操作。建群成功、改名失败属于部分完成，原群保留。

联系人标签提供添加、移除及明确的完整替换模式；添加/移除先读取并保留其他现有标签，每位好友独立取得回执。未能读取现有标签时停止合并，不把未知状态当成空标签。

消息发送保存真实服务端ID以及原始client_id或original_client_id、create_time、account，包含同步回显先于发送RPC返回时的合并。撤回只允许本人消息、完整原始回执及两分钟有效窗口；不补造字段。好友申请与自动通过插件共用去重声明，避免重复接受。

写操作记录存于 `console.db` 的 `ai_action_records`，按账号隔离。原始回执、好友申请和待确认执行参数使用现有 `credential.key` 加密保存，不进入模型或普通日志。后台展示最近100条写操作及待确认项；DEBUG模式继续记录模型实际请求/响应原文和系统操作元数据，不复制操作票据。

备份和重启仍需保留整个控制台数据目录及 `credential.key`。本次只新增表和可选策略字段；关闭单项能力或AI即可停止工具注入，不影响聊天归档。回退旧程序前应先处理或拒绝待确认操作；旧程序不执行新增记录。

## 验证边界

离线验证覆盖42项适配、三类供应商协议及MiMo、组合操作、授权/引用校验、后台确认、去重、重启未知状态、消息回执保存、模型失败不重放、以及浏览器中的配置与确认交互。使用会随建群、改名、发送和邀请改变状态的协议服务核对参数、读回与拒绝传播。

这些结果不代表所有42项均已在当前真实微信账号和所有供应商模型上完成验收。本次不为测试向真实联系人发送消息、建群、邀请、修改资料或操作朋友圈。
