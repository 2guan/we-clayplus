# 统一媒体下载

直接接入与插件都沿用 `Message.Download`。文件消息有两个阶段：收到 `TypeAppFileNotify`（入站 appmsg type 74）表示发送方仍在上传，此时下载返回 `FailedPrecondition`；收到带 `attachid` 和 `totallen` 的 `TypeAppFileAttach`（appmsg type 6）后，才用**这条完成消息**下载。两条消息的 ID 不同；完成消息可能带 `overwrite_newmsgid` 指向先前的上传通知。不能只根据外层消息 `status` 判断上传完成，也不能假定每次上传通知最终都会到达完成消息。

文件按读取进度向 core 请求分块，不会在 `Download` 时一次装入内存。旧 CGI 附件与普通 CDN 附件（`filetype=5`、`/download`）每块最多 64 KiB；core 仅将长度为 228 个十六进制字符、解码后为 114 字节且首字节为 `0x7f` 的严格大文件 ID 路由至 `filetype=7`、`/downloadbig`，该路径每块最多 256 KiB。SDK 返回的 reader 也按 gRPC 帧读取，使用后必须关闭。首块或后续分块失败都可能在首次或后续 `Read`、`io.Copy` 时返回；只有读到 EOF 才表示下载完整。将下载写入临时文件，成功后再交付最终文件：

```go
stream, err := client.Message.Download(completeMessage)
if err != nil { return err }
defer stream.Close()

tmp, err := os.CreateTemp(filepath.Dir(target), ".download-*.part")
if err != nil { return err }
defer os.Remove(tmp.Name())
if _, err = io.Copy(tmp, stream); err != nil {
    tmp.Close()
    return err
}
if err = tmp.Close(); err != nil { return err }
return os.Rename(tmp.Name(), target)
```

上例假设调用方已选定可写的 `target` 路径，并已处理是否覆盖同名文件。`completeMessage` 必须是完成阶段的消息。普通 `attachid` 保留原 CGI 分块下载；带 `cdnattachurl`、`aeskey` 和 `md5` 的完成消息走 CDN 分块下载，按明文长度及 MD5 校验。代码设置的文件大小上限为 1 GiB，这是本地参数边界，**不表示微信 CDN 已支持下载该范围内的所有附件**。

## 文件附件真机验证与限制

已登录的 Mac 会话下，上传通知及 769,693 B、294,168,750 B 完成文件经过 `SDK → gateway → core → CDN` 真实链路验证。上传中消息经 SDK gRPC 调用 `Message.Download` 后，`Read` 返回 `FailedPrecondition`；两个完成文件均全量下载，读到 EOF 后核对大小和明文 MD5。51,017,382 B 文件目前仅完成 core CDN HTTP 直测，尚未验收 SDK 完整链路。

| 消息阶段或文件大小 | 已验证路径 | 结果 |
| --- | --- | --- |
| 上传中，appmsg type 74 | SDK gRPC → gateway | `Read` 返回 `FailedPrecondition`，未下载。 |
| 完成，6,659 B、178,535 B | core CDN HTTP | 下载完整，明文 MD5 与消息中的值一致。 |
| 完成，769,693 B | SDK → gateway → core gRPC → CDN HTTP | 全量下载；大小与完成消息 XML 一致，明文 MD5 匹配，正常读到 EOF。 |
| 完成，51,017,382 B | core CDN HTTP，大文件 `filetype=7`、`/downloadbig` | 64 KiB 分块下载 779 块，明文 MD5 匹配。 |
| 完成，294,168,750 B | core CDN HTTP，大文件 `filetype=7`、`/downloadbig` | 256 KiB 分块下载 1,123 块，172.1 秒，测试脚本未重试，明文 MD5 匹配；此前 64 KiB 分块 4,489 块，经测试脚本重试 25 次后也匹配 MD5，耗时 1,160.5 秒。 |
| 完成，294,168,750 B | SDK → gateway → core gRPC → CDN HTTP | 全量下载，耗时 3 分 8.971 秒；大小及明文 MD5 匹配，正常读到 EOF。 |

收到 type 6 只说明发送方的上传阶段已结束，不保证 CDN 会允许当前会话取回附件。上述大文件曾使用普通附件的 `filetype=5`、`/download` 路径请求，收到 TLV `retcode=-5103017`；改用匹配该类文件的 `filetype=7`、`/downloadbig` 后，core 直测完成全量校验，294,168,750 B 文件也通过 SDK 完整链路。大附件结果依赖本次新增的 core 分块路由及 type 7 实现；旧发布 core 不具备这项能力，相关新代码目前尚未打标签发布。core 仅对该大文件路径的网络错误最多尝试 3 次（两次退避为 200、500 毫秒）；HTTP 状态、协议及解密错误不重试。下载失败仍须清理临时文件，不能将已有片段标记为完整下载。上述结果只代表这些具体附件与当前会话，不保证所有大文件均可下载。

图片、视频等沿用 core 的下载能力；当前 gateway 对这些类型仍会先取得完整数据。表情包由 we-clay 识别微信 CDN 并下载，支持已验证的 GIF、PNG，以及 JPEG/WebP 文件类型。不会修改 GIF 动画帧。下载受超时、20 MiB 大小、域名与目标 IP 限制约束；重定向同样校验，失败信息不暴露带鉴权参数的原始 URL。加密或未知格式会明确报错。

robot 只负责私有缓存、消息所属账号、HTTP Range 和界面展示。图片、视频、表情不再分别在 robot 实现 CDN 协议。已经缓存的媒体可以离线查看；未缓存内容需要有效的 Client。
