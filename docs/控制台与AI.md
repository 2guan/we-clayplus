# 控制台与 AI 基础插件

作者：2guan。此文描述当前代码实际实现的边界；“仅预览”选项不是已经完成的真实能力。

## 脱机体验

在仓库根目录运行：

```sh
make mock
```

打开 `http://127.0.0.1:8208`。这条命令复用 `gateway.Run` 的显式测试入口，没有增加上层 main 或 CLI。
按 Ctrl+C 结束。首次构建可能需要下载 Go 依赖；依赖齐备后，Mock 运行期间不下载或启动 core、不连接微信、不访问模型供应商。
前端资源已嵌入 Go，日常预览不需要安装 Node.js，也不依赖字体、图标或 CDN 外链。

Mock 只允许监听回环 IP，并限制请求 Host。默认使用 `runtime/mock-console/mock.db`，不会读取真实控制台数据库。
数据、账号、联系人、消息、图片和统计均为虚构。示例音频为合成提示音，不是人物语音；识音频结果是固定演示文案。

可通过环境变量指定本机预览地址和数据位置：

```sh
WE_CLAY_MOCK_ADDRESS=127.0.0.1:8208 WE_CLAY_MOCK_DATA_DIR=./runtime/demo make mock
```

顶部“脱机 Mock”面板提供正常、空数据、微信离线、发送／模型失败场景，以及登录页、首次初始化页的外观预览。
切换场景会重建虚构数据；重置不会删除正式数据库。登录页预览不会创建正式账号。

建议依次验收：

1. 总览：账号、消息和 Token 指标、趋势、运行状态；切换亮色、暗色、跟随系统。
2. 微信：统一的私聊／群聊列表、分类表情选择、粘贴图片／文件并预览发送、文字合成语音后试听发送、媒体播放、引用、撤回、置顶、人工接管、专属人设／模型、清空记忆。
3. 通讯录与朋友圈：好友／群筛选、备注、会话入口；虚构动态的发布、点赞、取消赞、评论。
4. 模型中心：六页签管理、厂商目录、逐模型测活与参数、对话、语音、图片与视频独立流水线、语音试听、图片与视频预览、人设优化、行为权限和任务记录。
5. 插件、洞察、日志、设置：启停 AI、生成演示报告、日志筛选／暂停／导出、表单保存、历史恢复、用户角色页面。
6. 手机宽度：微信列表和聊天分为独立页面，返回列表；底部微信式导航；输入与弹窗不横向溢出。

## 默认注册与接入

`gateway.Run` 默认在 core 登录前启动 Dashboard 服务；AI 共享同一个状态库、模型配置和任务执行器。
真实模式在原有插件管理器中注册 `dashboard`、`ai` 两个内建插件，仍保留 `pm`、`cm` 及外部插件机制。
保留原有协议名称，不引入第二个 go.mod，不导入私有 core 源码。

启动配置在 `gateway.Config.Console`（类型 `*control.Config`）或 TOML 的 `[console]` 中设置：

```toml
[console]
address = "127.0.0.1:8208"
data_dir = "./runtime/console"
mock = false
disabled = false
disable_ai = false
```

没有设置 `Console` 时，数据目录默认为 Gateway 数据目录的同级 `console`。
`gateway.WithoutDashboard()` 只关闭 Web 监听；AI 可继续为插件提供能力。
`gateway.WithoutAI()` 关闭 AI 调用；`gateway.WithoutPlugins()` 保持关闭全部插件的原有语义，并与 Mock 配置互斥。
端口冲突会明确报错，启动失败不会静默忽略。

首次真实模式访问控制台，直接设置登录名及至少 6 位密码，创建管理员，无需初始化凭据。
控制台登录与微信登录是两个独立步骤。安装版登录控制台后，可在账号区域点击“微信连接”，在同一弹窗查看 core 状态与微信二维码；core 原有登录页面仍可用于兼容调用与应急排查。
安装版只管理当前安装目录配置的独立 core：管理员可以在弹窗中停止、重新启动它，控制台保持运行，扫码成功后恢复本轮消息订阅。停止 core 不退出微信账号，也不删除设备或会话数据。普通嵌入式 `gateway.Run` 没有启用 `WithCoreConsoleControl()` 时，仍按原有 Run 生命周期处理 core 进程退出。

## 页面与配置组织

首页“已运行时间”读取当前 core 监听进程的运行时长，与 dashboard 启动、浏览器刷新及微信登录时刻无关。重启 dashboard 不归零，重启 core 后随新进程重新计时。首页每 15 秒校准一次轻量指标，页面隐藏时暂停、重新显示时立即校准，不重复读取聊天归档。上层只读查询操作系统进程指标并缓存 5 秒，不修改或重启 core；macOS/Linux 使用 `lsof` 和 `ps`（Linux 无 `lsof` 时尝试 `ss`），Windows 使用系统 PowerShell。无法确定唯一监听进程、缺少系统查询能力或 Mock 无真实 core 时显示“—”，不回退为 dashboard 运行时间。

右上角主题按钮展开绿色（默认）、蓝色、红色、橙色和灰色五色色板，选择后立即生效并收起；紧邻的显示模式按钮依次切换亮色、暗色与跟随系统。色板是按钮下的小浮层，不打开居中弹窗。
配色覆盖全部控制台页面、聊天、图表、弹窗及登录／初始化页面；登录前也可从右上角切换。
外观即时生效，偏好保存在当前浏览器，刷新后保留；不改变其他用户的外观。在线、警告与错误状态保持独立语义颜色。

| 页面 | 内容 |
| --- | --- |
| 总览 | 账号资产、今日消息、Token、任务结果、近 7／14／30 天及自定义日期统计、服务状态 |
| 微信 | 会话列表、消息、媒体、接管、专属策略、朋友圈入口 |
| 通讯录 | 好友／群列表、搜索、备注、资料与聊天入口 |
| 模型中心 | 对话模型、语音模型、图片模型、视频占位、提示词管理、行为与任务 |
| 插件中心 | 基础插件说明、AI 启停、演示扩展插件 |
| 智能洞察 | 左侧配置、右侧报告；拼音搜索对象、自定义正整数条数、重点示例、报告切换与导出 |
| 实时日志 | 控制台结构化日志、级别／组件／关键词筛选、暂停和导出 |
| 系统设置 | 品牌、存储、会话安全、提醒、用户与权限、配置历史；修改密码从左下角用户信息进入 |

设置由 Go `Schema()` 统一定义字段、默认值、范围、权限和是否“仅预览”，浏览器与后端共用。
配置修订号独立于消息版本号；后台收到消息不会使正在编辑的设置失效，但另一次配置修改会阻止陈旧覆盖。
对正在编辑的设置，站内跳转和关闭浏览器提供未保存提示。历史恢复只作用于对应快照的字段。

## 当前可执行能力

- Mock：全部页面、六类 AI 固定结果、会话和朋友圈的本机操作、失败／空数据场景、设置保存、任务状态可验证。
- 真实 AI：OpenAI 兼容协议的对话、识图、转写、标准 TTS、返回 `b64_json` 或同源图片链接的图像生成；Gemini 文本／图片／音频／原生视频理解；Anthropic 文本与图片理解。
- 每个模型必须正确声明支持的能力。适配器不支持的组合会报错，模型列表声明本身不代表供应商已经验证可用。
- 并发上限、每日调用次数、超时、最大输出、TTS 长度／语速、图片大小限制、图片提示词风格补充已经接入。
- 默认对话、语音、图片与视频生成按各自流水线顺序调用，失败或超时后切换，成功立即停止。语音只在同一模式（TTS、声音设计、声音克隆）内切换；显式指定模型只调用该模型，微信写操作不自动重试。视频已受理但结果未知时停止切换，取消任务中止本地等待，不承诺取消远端任务。超时的厂商请求仍可能计费。
- 自动回复总开关默认开启，已有手动关闭设置保留；仍需启用 AI 插件、通过名单规则、将会话设为自动、配置可用模型。默认使用空黑名单，不排除好友和群聊。普通群消息按配置概率触发；默认跳过真实 @ 他人且未 @ 本人的消息，即使群回复概率为 100%。模型中心的「群聊 @ 他人时不插话」可关闭此规则。协议中真实 @ 本人始终触发，正文中的昵称不作推断。支持私聊关键词、静默时段、会话冷却、独立人设／模型、消息数／有效期和保守字符预算。
- 人工发言可切换为人工接管，生成完成后再次检查接管状态。当前接管需要手动恢复，定时恢复标为仅预览。
- 真实微信已桥接联系人缓存、消息归档、文本／图片／文件发送、文字合成后发送原生语音、SDK 撤回、备注、群名和公告入口。撤回复用 SDK 保存的原始回执，不伪造客户端 ID；只允许已确认发送的本账号消息。
- 会话数据按微信账号分区保存与恢复，避免串入另一个账号的聊天、任务和专属策略。
- 拍一拍保留协议中的发起人与被拍者 ID、原始展示模板和自定义后缀；姓名按本人、通讯录备注、同会话已归档的真实发言人及联系人昵称补齐，不从正文猜身份，不跨群借用成员昵称。旧归档被替换为「对方」的表头在读取副本中修复，保留原始归档及后缀换行、表情；后续名称补齐后旧记录也能更新。聊天中仅显示拍一拍文案，不显示「互动详情」或第二行微信 ID；结构化协议资料仍保留用于归档和上下文。
- 微信页面中的朋友圈入口同步 SNS 互动通知（命令 46），结合微信设备的 `MomentsUnreadMsgStatus` 已读时间和本地已读记录计算角标；不依赖 Windows 模式下可能恒为零的时间线 `unread_count`。通知按账号分区加密保存并去重，同步游标不返回浏览器。每分钟及窗口恢复可见、获得焦点时刷新，超过 99 显示「99+」；读取失败保留旧计数并显示错误。打开互动提醒后展示回复者、具体回复、被回复的原评论和时间，列表不清除未读，点开对应动态成功后仅将该条通知 ID 标记为本地已读，不清除随后新到的提醒，也不伪造手机端已读回执。
- 朋友圈普通留言显示「作者：」，回复留言保留微信返回的回复对象，显示「作者回复对象：」。缺失回复用户名时，仅在同一动态按评论编号核对；无法核实时显示「未知用户」。AI 留言草稿也带上这些回复关系，微信 ID 不注入提示词。
- 动态列表、好友主页及互动提醒中的评论均提供「回复」入口。选中后展示原评论和回复对象，输入框切为定向回复；「取消回复」恢复普通留言。提交时传递原评论编号及作者，服务端重新读取动态，拒绝已删除、编号缺失或作者不符的对象，不降级成普通留言。当前 core 接口使用正数 32 位评论编号；仅返回 64 位编号时不截断冒充可回复编号。发送后核对真实回执中的本人新增评论及其原评论编号，必要时只读回查一次；无法确认则保留输入和对象并提示核对，不自动重发，也不凭请求参数伪造成功标签。
- 选中评论后点击「AI」，会结合该评论原文、朋友圈正文、缩略图及全部可见讨论，起草本人对该评论作者的回复；相关记忆和专属设置改为匹配被回复者。仍只填入草稿，由用户确认发送。取消或切换回复对象会使旧草稿失效，防止迟到结果写给错误的人。
- 朋友圈留言框的「AI」按钮仅为管理员生成草稿，不自动发送。按动态 ID 读取真实正文、作者昵称、全部已返回的可见评论和缩略图；图片经受控下载并压缩，不把本机 URL 交给模型。记忆沿用总开关和该联系人的开关，仅参考该作者已确认、未过期、有有效来源的相关低敏记忆；不读取群共享记忆或其他人的私聊记忆。有图使用模型中心的识图配置，纯文字沿用对话流水线；继续执行防护、并发和额度检查。图片部分失败会提示，生成失败保留输入，可再次点击重试。生成期间若手工编辑，迟到的草稿不覆盖输入；切换账号或离开页面取消等待。

插件可通过 `CallPlugin("ai.chat", args)` 等能力提交任务，返回 MIME `application/json`，内容为 `{id,status}`。
支持 `ai.chat`、`ai.vision`、`ai.audio`、`ai.video`、`ai.tts`、`ai.image`；通过 `ai.task` 和 `id` 读取任务结果。
输入为字符串 map：`prompt` 必填，其他包括 `system`、`model`、`media`（Base64）、`mime`、`filename`。
此入口不会附带微信发送副作用，也不能越过 AI 停用、并发和预算限制。

## 聊天输入与语音发送

会话与通讯录的专属策略支持从人设库载入提示词，也可自定义输入或选择继承全局人设。
载入后可继续编辑，保存的是当前会话的独立副本，不修改人设库，也不随后续库中修改自动变化；提示词留空则恢复继承。

表情面板支持分类、中文搜索和光标位置插入，表情为随前端内嵌的 Unicode 字符，无外部服务依赖。
输入框支持粘贴图片和浏览器剪贴板提供的文件，也可使用图片／附件按钮选择；一次最多 8 个。普通文件的上层限制默认 500 MB，可在「系统设置 → 附件与传输」调整（1–1024 MB）；图片仍为 16 MB。超过 16 MB 的普通文件使用二进制流式上传，不经过 Base64 JSON。当前 core 发送链路仍限 32 MB，超出会提前提示并拒绝，不表示已经支持 500 MB 的真实微信发送；完整能力需要另行升级 core。详见 [附件上传](附件上传.md)。
附件先进入可移除的预览队列，点击发送后逐个提交；附带文字独立发送。SVG、音视频文件按附件发送，不冒充微信原生媒体消息。
操作系统未向网页剪贴板暴露的文件，可改用附件按钮选择。

点击麦克风按钮，输入语音文字，再点击“合成试听”；试听后点击“发送语音”。
合成使用模型中心默认路由的语音合成模型，以及已配置的音色、语速和文字上限。
发送始终绑定合成时的会话，同一任务只允许提交一次；结果未知时先核对微信消息，避免重复发送。
Mock 使用固定示例音频验证整套流程，不朗读输入文字，不调用模型或微信，也不需要编码工具。

真实模式由 OpenAI 兼容 TTS 接口输出 WAV；Gateway 使用 `ffmpeg` 转为 24 kHz 单声道 PCM，再调用支持 `-tencent` 的 `silk_v3_encoder` 编成腾讯 SILK。
部署机器需要安装这两个工具并放入 PATH，也可通过 `WE_CLAY_FFMPEG` 和 `WE_CLAY_SILK_ENCODER` 指定各自可执行文件的绝对路径。
命令参数固定，不调用 shell；临时文件处理后删除。缺少工具、编码失败或时长不在 0.02 至 60 秒内时明确报错，不自动截断长语音。
微信发送参数使用毫秒时长和格式 `4`。本机验证覆盖实际编码、语音参数与发送→撤回的回执传递；没有执行真实账号发送。
若 core 返回非数字 `client_id`，现有 SDK 无法满足撤回接口的数字 ID 契约，会拒绝撤回，不伪造该字段。

## 自动回复的文字、语音与图片协议

自动回复始终先检查全局开关、目标名单、会话自动模式、触发策略及并发/每日配额。后台实验室的生成不会自动发到微信。专属提示词优先，空值继承默认人设；服务端额外注入实际可用能力和以下输出协议，旧人设无需重新粘贴。

- 普通聊天建议 1–3 条；双换行（包括 CRLF 和空白行）分条，单换行保留。默认每轮合计最多 5 条，可在全局对话设置中下调。超过上限整轮拒绝，不静默截断。
- `<voice>口语台词</voice>` 使用语音流水线，每轮最多一条；标签不允许属性或嵌套元素。音色由标准 TTS、声音设计或声音克隆模型配置决定，不允许模型用标签切换音色。方括号中的情绪提示作为台词传入供应商，具体表现取决于该模型，并不保证所有供应商支持相同音效。
- `<image prompt="画面描述"/>` 使用图片流水线，每轮最多一张。`ref="selfie"` 使用默认垫图，未上传则读取微信头像；`ref="last"` 只取当前会话最后一张收到的或确认已发送的图片。缺少票据、垫图或模型时明确失败，不降级为另一张无参考图的图片。
- 标签外的文字、语音与图片按原顺序发送。媒体先全部生成并校验，再开始发送；默认间隔 700 毫秒，可在全局对话设置中调整。每条发送前重新检查全局开关、名单、在线状态和人工接管状态。
- 每条发送回执独立归档。发送失败或结果未知时停止，不切换模型重新发送，不补发后续消息；父任务显示失败，已成功发送的内容保留。真实模型用量即便发送失败也统计。
- 只有确认发送成功的图片场景和语音台词进入后续 AI 上下文；失败、发送中和未知结果不作为已发送事实。媒体标签只解析本轮模型输出，不重放历史中的标签。

全局对话设置增加“允许自动发送语音”和“允许自动生成并发送图片”。语音合成设置的“微信回复形式”控制无标签的普通回复：文字保持分段，语音合并成一条语音，“跟随来信”仅在入站语音时合成语音；显式媒体标签优先。后台图片实验室仍只预览，不受自动聊天开关影响。

开启自动生图后，未包含图片操作的普通聊天草稿会通过原聊天模型复核一次，结合本轮及上下文判断是否只口头答应发图；这会增加一次模型请求和相应等待时间。判定漏图时，发送前按原流水线纠正重试，保留生图能力；重试仍失败则保留人工重试入口，不发送空承诺。正常闲聊、拒绝或澄清不会被强制生图。媒体标签格式错误同样先纠正协议，不会因此自动降成纯文字；实际图片仍在生成和读取成功后才随文字一起发送。

新收到的图片、语音支持按 `vision.auto` / `audio.auto` 开关识别后回复。SDK 媒体描述加密保存；按需下载受账号与会话绑定限制，最多 16 MB，不允许模型提供任意 URL。SILK 入站语音需要 `silk_v3_decoder`（或 `WE_CLAY_SILK_DECODER`）和 ffmpeg。历史消息若没有下载票据需重新发送，不扫描或重放旧消息。识别资料仍经过防注入检查，不成为系统指令。

MiMo 音频理解使用 `/chat/completions` 的 `input_audio.data` Base64 data URL，按[官方音频理解文档](https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/multimodal-understanding/audio-understanding)适配，不使用 multipart 转写端点。其他 OpenAI 兼容转写服务继续使用 `/audio/transcriptions`。

离线验收：`go test ./plugins/dashboard ./plugins/ai ./plugins/contextcleaner ./gateway/internal/console ./gateway/internal/ability/message`。覆盖解析、限额、混合发送顺序、人工接管、失败停止、跨会话拒绝、上下文排除未知发送、MiMo 请求格式及真实 SILK 编解码。Mock 用内嵌媒体完成流程，不访问微信或真实模型；离线通过不等于真实微信端到端已验证。

## 数据、安全与开发

控制台用户名和 bcrypt 密码哈希保存在本机；会话 Cookie 为 HttpOnly、SameSite Strict，角色在服务器检查。
API Key 采用 AES-GCM 保存，解密密钥为数据目录中的 `credential.key`；此文件和数据库必须一起备份。
它是静态存储保护，不能防御已取得操作系统账号或同时取得数据库和密钥的攻击者。
运行数据目录权限 0700，数据库、密钥和媒体文件 0600；不把凭据返回浏览器，也不记录供应商原始报错正文。
默认回环访问；需要手机访问真实模式时，部署受信任的 HTTPS 反向代理并保持同源。Mock 为本机验收模式，不提供公开免登录服务。

## 模型中心配置与接口

- 厂商独立保存名称、API 地址、协议和加密密钥，同一厂商的多个模型共享凭据。获取模型支持 OpenAI 兼容、MiMo、Gemini、Anthropic 目录；目录失败时可手动输入 ID。更改地址或协议必须重新输入密钥，避免把旧密钥发送到新地址。
- 每个模型可覆盖超时、温度、思考模式、上下文条数及最大输出；数值 0 表示继承全局（温度留空表示厂商默认）。不同模型接受的思考参数有差异，测活失败会显示真实状态，不会由其他模型代答。MiMo 开启思考时不发送温度参数。
- 语音页提供 TTS、VoiceDesign、VoiceClone。MiMo 按模型后缀选择实际协议分支；声音设计使用描述，声音克隆使用 WAV/MP3 样本。可保存默认语音参数和样本供微信文字转语音使用。官方契约：[MiMo 语音合成](https://mimo.mi.com/docs/en-US/quick-start/usage-guide/audio/speech-synthesis-v2.5)。
- 图片页支持比例、长边分辨率、质量、风格、默认垫图和单次垫图。有垫图时使用图片编辑接口；选择自拍且无垫图时下载 SDK 当前账号头像。没有头像则明确报错；Mock 使用本机示例图。实际尺寸、质量参数必须在所选厂商支持范围内。

自拍由对话模型结合本轮主题描述场景、人物可见外观、表情、姿势动作、构图及光线；服装可选，仅在明确要求或场景需要时补充，使用 `ref="selfie"`。人物面容和身份特征以参考图为准，垫图优先级为本次上传、已上传的默认照片、当前微信头像。生图描述不使用微信昵称或微信 ID，不把职业、所在地等身份履历当作画面描述；发送给图片服务前会替换当前账号的昵称与 ID，并追加保持参考图人物一致的要求。新场景只是生成设定，不作为真实经历写入上下文；任务详情显示实际整理后的生图描述。
- 图片编辑先按标准 multipart 提交；服务明确返回 HTTP 415 时，仅协商一次 JSON，以 `image` data URL 传递相同参考图和生成参数。超时、5xx 和结果未知时不会因此自动重复生成。兼容网关返回图片链接时，只下载配置服务的同源地址，拒绝跨源和重定向、限制 32 MB 并检查实际图片类型；PNG、JPEG、WebP 等按实际类型归档。415 提示明确说明请求内容类型不兼容，不再笼统归因于额度或权限。
- 视频页提供厂商管理、独立流水线、参考图、默认及单次时长/尺寸、生成、播放和下载。新能力标识为 `video_generation`，保留 `video` 的视频理解语义。无参考图时为文生视频，有参考图时为图生视频，默认参考图与图片页分开保存。Mock 固定播放本机样片。
- 视频真实调用限定为 OpenAI Videos **兼容服务**：`POST /videos`（JSON、`input_reference.image_url` 内嵌图片）、`GET /videos/{id}`、`GET /videos/{id}/content`，支持 4/8/12 秒与四种横竖屏尺寸。单模型超时覆盖完整流程，媒体最大 64 MB，只从配置厂商地址取回且禁止重定向。不支持的厂商协议明确报错。请自行配置仍提供该兼容协议的服务；OpenAI 官方 Sora API 已宣布于 2026-09-24 停止，不能将其官方地址当作可用服务。契约参考：[视频接口](https://developers.openai.com/api/reference/resources/videos/methods/create)、[视频内容接口及停服说明](https://developers.openai.com/api/reference/resources/videos/methods/download_content)。
- 默认人设以列表首项保存，切换默认立即影响后续请求。提示词优化通过默认对话流水线生成候选文本，手动采用后再保存，不自动覆盖原人设。
- 行为目录继续嵌入 `gateway/capabilities.json`，在“行为与任务”中区分 42 项对话工具、11 项后台配套、8 项既有仅限人工能力，以及本轮新增但暂不提供 AI 调用的 6 项能力。新增能力只完成离线调用链验证，默认关闭，不作为模型自由调用工具。支持发起人、实际目标范围/名单、跨会话授权和后台确认；模型可根据真实回执连续执行，写操作不自动重放。OpenAI兼容、MiMo、Anthropic与Gemini均接入原生工具协议。完整范围、配置、回执及验证限制见 [AI行为与任务](AI行为与任务.md)。
- 所有新增读写仍通过同源鉴权 API；厂商凭据、流水线和行为权限只能由管理员修改。旧模型升级时复用原凭据 ID，避免丢失已配置密钥。

本轮验证使用本机 HTTP 契约服务器和脱机浏览器，不代表已对真实模型额度或真实微信操作进行验收。

### 智能洞察的对象与资料范围

- 桌面输入与报告并排占满工作区，手机按输入、报告顺序上下排列；历史报告仍可独立查看。
- 对象搜索支持昵称、备注、微信 ID、全拼及拼音首字母。字典随前端打包，本地搜索不会外发联系人信息。
- 朋友圈候选只保留 `kind=friend` 的联系人，群聊分析只保留群；切换类型时清除不适用的选择。控制台桥接只把 SDK 明确标记的好友映射为好友。
- 朋友圈内容按 `author_id` 精确归属，避免同名内容串入。旧 Mock 的两条内置动态自动补齐作者 ID；缺少作者 ID 的真实历史内容不根据昵称推测归属。
- 条数可填写任意安全的正整数，例如 1000、2000；没有 200 条的页面上限。实际读取选中对象的已归档记录，记录不足时显示实际数量；不会自动补拉微信历史记录。
- 分析资料整体作为请求提交，不套用普通聊天的上下文保留条数裁剪。仍受模型上下文容量与现有请求体大小限制；失败显示在右侧报告，不静默丢弃选中内容。
- 分析继承模型中心的单次调用超时（默认 300 秒，模型独立设置可提高至 600 秒），按整个请求计时。超时或流中断时，已收到的正文仍经过输出防护，再保存为未完成报告并展示原因，不冒充完整结果。
- 三类分析各有四个重点示例，点击填入后可继续编辑，手动确认生成；报告支持运行状态、取消、切换和文本导出。

### 报告重试、追问与资料缓存

- 服务方返回明确拒绝（如 `finish_reason=content_filter`、`refusal` 字段或完整高风险拒绝说明）时，报告标记失败并提供手动重试；不把拒绝说明当正文，也不自动切换模型绕过拒绝。旧版本误标成功的完整拒绝说明会在启动时修正；正常正文引用该句不会误判。
- 洞察任务先创建再准备资料，读取失败也会留下可重试记录。详情中的“重试”适用于无正文、部分正文、超时和中断任务；正在处理时禁止重复提交。每次尝试独立保存，沿用原模型选择与模型中心当前参数。
- 朋友圈按当前微信账号与好友 ID 加密缓存，默认复用；扩大条数只从已保存游标补取。勾选“更新资料后分析”才重新读取最新资料。缓存不代表微信当前可见状态，页面标明北京时间的采集时间；缩略图压缩结果单独缓存，最多并发处理 3 张。
- 每次分析在调用模型前保存固定资料快照，重试与追问不会重新拉取微信，也不会因更新缓存改变原报告依据。快照和图片不进入全局状态接口。会话资料撤回、删除或账号变化时拒绝继续使用旧来源。
- “追问与补充”保留原报告，按轮追加问题与补充正文，失败的一轮可单独重试；刷新页面仍可查看。部分报告可追问但提示尚未完成，无正文时先重试。原资料、报告和历史回答均按参考资料处理，继续执行防护与容量校验，超限明确报错。
- “导出报告与追问”导出 Markdown，包含正文、追问补充、采集时间和未完成说明。删除报告会清理其重试、追问及独立快照，共享资料缓存不影响其他报告。
- 旧报告没有完整快照时，不猜测原范围。详情提供补选条数和“重建资料并分析”，创建独立的新报告，并提示资料可能与原分析不同。

### 提示词防护与上下文清洗（第一阶段）

两个基础插件 `prompt_guard`（提示词防护）和 `context_cleaner`（上下文清洗）默认注册并启用。升级仅补充缺失插件及配置，不覆盖已有设置；它们独立于 AI 插件显示，但共用现有任务执行器，不启动额外模型服务。第一阶段负责 AI 请求防护；下文的第二、三阶段业务插件独立配置与启停。

**使用入口**：插件中心卡片提供使用、配置与验证。配置支持可视化及 TOML；验证窗口提供离线验证、规则与范围（防护插件）和处理记录。离线验证使用已保存配置，不调用模型、不发送消息、不修改聊天记录，也不写正式处理记录。

- 防护入口包括微信自动回复、后台模型测试、智能洞察、管理员提示词编辑和跨插件请求。入口身份由服务端确定，HTTP 的 `source`、`context`、`tools` 字段不能伪造服务端权限。
- 标准模式拦截明确的指令覆盖、隐藏提示词提取、权限升级、角色标记伪造和凭据提取；宽泛能力探询仅观察。严格模式扩大输入检查；观察模式不阻止请求。可按会话唯一 ID 覆盖模式，并配置自定义规则的来源、级别、动作和开关。
- 输出中的解释或拒答不被当成输入指令：内置意图规则仅观察，角色分隔符、自定义输出规则、实际凭据和长篇内部人设全文回显分别检查。实际 API 密钥回显的拦截独立于插件开关；这是精确匹配保护，不声称可以识别任何形式的编码泄露。
- 当前消息被阻止时不会创建模型任务；历史或分析资料中的命中内容会从本次模型可见副本隔离。历史每次使用前重新检查，原始归档仍然保留。微信默认静默跳过，可改为固定说明；固定说明受自动回复目标与接管状态校验，有冷却限制，且不会进入后续 AI 历史。
- 清洗按会话隔离，保留发言人、角色、时间和消息 ID；只按事件 ID 去重，不按相同内容去重。清理异常控制字符，历史图片、音频、视频、文件和表情可用文字占位，当前上传文件不被替换。引用消息的文本不作为媒体删除。
- 条数与有效期限沿用现有记忆设置，模型可覆盖条数。全局上下文 Token 预算和请求容量均支持 0（无限制）或最多 9999999；模型预算 0 继承全局，勾选“不限制”保存为 -1。模型显式不限制不会取消单独配置的请求容量，需把请求容量也设为 0 才能取消两层 Token 限制；消息条数、回看期限及防护仍生效。有限请求容量使用保守字符估算，并预留系统提示、工具描述和最大输出；这不是供应商 tokenizer 或模型实际上下文容量的保证。超过供应商容量仍会返回失败。单条最新消息超预算明确失败；分析资料不采用聊天滚动裁剪，超限明确报错。
- 历史和分析资料以 JSON 数据块提供给模型，不能成为系统指令。外部请求的人设补充作为请求文本处理；管理员提示词优化使用独立入口，把原提示词当作编辑素材，且不能执行工具或发送微信消息。
- 输出只删除明确的推理标签及异常控制字符，保留合法 JSON 和 Markdown 代码围栏中的示例。聊天旁白清理默认关闭；报告和编辑结果不应用聊天风格。精确的 `NO_REPLY` / `[SILENT]` 可停止自动发送，空正文不会被随机话术替代。
- 模型输出及解码后的工具参数在保存、发送或执行动作前检查。安全处理失败不切换备用模型；后端原有行为授权和目标检查始终保留。后台测试和普通插件任务没有隐式微信发送权限。
- 正式处理记录只保存时间、任务 ID、来源、阶段、动作、规则 ID 和数量，不保存输入正文或推理内容。记录仅管理员可见，默认保留 7 天、最多 1000 条，页面展示最近 100 条。

**范围与边界**：当前实现是文本规则、资料隔离及后端授权的组合，不保证识别全部提示词攻击；不对原始图片、音频或视频额外执行 OCR/转写来检测隐藏指令。已有模型返回的文字会经过输出处理。自行直连外部服务的第三方插件不会自动获得本处理链，需改接统一 AI 能力。未自动清除或改写旧聊天归档。

**离线验收**：插件内置指令覆盖、正常 JSON 摘要、历史污染、推理清理和提示词编辑示例。Go 测试另覆盖会话隔离、规则校验、JSON 转义参数、实际 HTTP 请求的拦截与故障切换边界、权限与升级；浏览器测试覆盖配置持久化、审计脱敏和手机暗色显示。上述结果不代表已完成真实微信或外部模型的现场验收。

### 启用、配置和脱机验证

- 真实模式中新业务插件默认关闭，名单默认黑名单；启用后空黑名单全局生效，填写名单可排除目标。手动切换白名单后仅允许名单内目标，空白名单不生效。
- Mock 新数据默认启用业务插件并使用空黑名单；升级保留旧开关和已有手动配置。真实凭据、账号、模型和外部服务都不会被 Mock 调用。
- 配置支持可视化/TOML 双向切换、服务端类型校验与版本冲突保护。菜单、词典、欢迎语和 JSON 字段支持多行文本。
- 每个插件的“使用”页列出介绍、步骤与可复制触发词；“工作台”提供生成预览、确认发送和最近 100 条执行记录。
- 预览绑定账号、目标和已生成的结果，最多保留一小时、200 项；发送消费该预览一次。不会重新抽菜单、重新生成图片或重复调用模型。修改输入后需重新预览。
- 入群欢迎和自动通过提供 Mock 系统事件模拟入口。普通聊天伪造的系统通知不会触发欢迎，网页不能向真实模式提交好友票据。
- 自定义素材按账号隔离，最多 100 个；单个上传最多 8 MiB、1200 万像素。重新编码为 PNG，删除素材条目不删除可能被历史消息引用的图片文件。

### 定时任务的执行语义

每个账号最多 100 项任务。周期表达式为 `分 时 日 月 周`，支持 `*`、列表、区间和步长，周日为 0；例如 `0 9 * * 1-5`。日与周都指定时遵循传统 Cron 的“或”语义。默认时区为 `Asia/Shanghai`，每项周期任务可以覆盖；单次时间由浏览器转换为带时区的绝对时间。

任务运行前先保存下一次执行时间及执行占位。错过超过一分钟的计划不补发；服务中断后将运行中记录标记为中断，不自动重发。发送结果未知时也不自动重试，避免生成重复微信消息。编辑/删除任务、关闭插件、改变账号或名单会阻止尚未发送的操作。业务运行同时最多 4 个，等待事件最多 64 个。

定时调用其他插件时，需要同时满足 `cron` 与被调用插件的启用/名单规则。立即执行属于明确的手动发送操作，界面会确认。任务记录保留最近 2000 条，工作台展示当前账号最近 100 条；去重键使用摘要，不保存好友票据。去重键保留 30 天。

### 外部服务配置

新闻默认沿用 Golem 的今日新闻和昨日图卦图片源，工作台与计划任务可选择类型；原 RSS/Atom 地址、筛选和默认行为保留。见 [新闻插件](新闻插件.md)。音乐默认组合酷我和抖音：先验证酷我搜索结果及音频，失败再试抖音；配置可单选音源或使用自定义服务。原 Golem Music 地址 `https://109a.cn/API/qqyy/api.php` 保留于自定义配置，仍支持 `golem` 和 `items` 格式。已有自定义服务升级后保留地址、接口格式和分享方式。完整音乐配置见 [音乐插件](音乐插件.md)。

视频解析、表情搜索和音乐的 `items` 模式使用以下可配置 JSON 服务契约。**仅填写普通网站首页不能提供搜索/解析功能**，目标服务必须支持该契约：

```text
GET <endpoint>?q=<搜索词或分享链接>&url=<同一输入>&limit=5
Authorization: Bearer <可选凭据>
```

响应结构：

```json
{
  "items": [
    {
      "title": "内容标题",
      "url": "https://example.com/share",
      "artist": "可选作者",
      "media_url": "https://example.com/media.mp3",
      "cover": "https://example.com/cover.jpg",
      "lyric": "可选歌词"
    }
  ]
}
```

`key_env` 只填写服务端环境变量名，程序从环境中读取 Bearer Key；不要将密钥写进 URL、插件设置或示例。跨域重定向不携带认证头，HTTPS 不允许降级跳转。服务请求使用 25 秒超时，JSON/新闻源最多 2 MiB，媒体最多 16 MiB；公网地址与 DNS 结果均检查，拒绝本机、内网及保留地址；系统 DNS 仅返回代理 `198.18/15` 虚拟地址时，通过固定 HTTPS 解析器取得真实公网地址再校验连接，不直接放行虚拟地址。仅接受可识别的图片、音频和视频，媒体经本机受保护路径预览，不让浏览器直接加载第三方资源。音乐封面最多 8 MiB，试听最多 16 MiB，仅代理当前账号已保存的卡片或管理员的一小时有效预览。

需要手动配置的源/服务未配置时，真实模式明确报错，不返回演示成功；Mock 始终返回本地样例，不依赖这些服务。

### 字体与已知接口边界

图片生成使用 `golang.org/x/image` 读取本机字体；词云中文分词使用 `gse` 的内嵌词典，不在运行时联网下载。可在词云、表情包及摸鱼日报分别指定 TTF/TTC 路径。默认寻找 macOS Arial Unicode/Songti、Linux Noto Sans CJK/WenQuanYi 或 Windows 微软雅黑。缺少可解析中文字体时显示明确错误；Linux 部署请预装中文字体或提供字体路径。例如 Ubuntu 24.04 可执行 `sudo apt-get install -y fonts-noto-cjk`。仓库不复制系统字体。

自动通过插件**只处理好友申请**。欢迎插件仅解析上述中文系统通知格式，不把未知格式猜成入群事件。原生音乐卡片已接通既有应用消息接口（外层子类型 76、XML 类型 3），不修改 core；真实微信客户端的发送、播放、撤回，以及解析服务覆盖的平台不在离线验收范围内。

本次测试均为脱机、Mock 或本机协议夹具：包括请求参数/失败传播、调度去重、重启恢复、权限、预览快照、规则作用范围、媒体与响应式页面；未登录微信，未执行真实账号写操作，也未用未提供的外部服务凭据做生产验收。


## 本机真实微信验收

执行 `make run` 从私有 OSS 下载并校验 core v0.4.6（Mac 模式），启动真实控制台。运行前通过受信任的本机环境配置提供 `WE_CLAY_AUTH_KEY`；默认由授权服务签发短时 OSS 下载链接，原有 `OSS_ACCESS_KEY_ID`、`OSS_ACCESS_KEY_SECRET`（可选 `OSS_SESSION_TOKEN`）也可继续使用。不要把凭据写入仓库。可用 `WE_CLAY_CORE_VERSION` 指定其他已发布的固定版本。后台访问 `http://127.0.0.1:8208`，可从“微信连接”弹窗扫码；core 原登录 HTTP 仍监听 `127.0.0.1:8201`，gRPC 仍为 `127.0.0.1:8088`。普通 `go test` 不会启动真实验收。

首次在后台直接创建管理员账号，无需初始化凭据。真实控制台数据保存在 `runtime/console/`，微信会话默认沿用 `runtime/core/`；已有其他账号目录时，设置 `WE_CLAY_DATA_DIR` 为其绝对路径，升级时不得换新目录。真实数据与 `make mock` 的 `runtime/mock-console/` 隔离。不需要重新编译前端即可切换运行模式。`make attach` 只连接已登录的独立 core，不下载或重启 core。

从控制台的“微信连接”弹窗扫码即可；需要兼容或排查时也可打开 `http://127.0.0.1:8201/`。`make run` 是普通嵌入式 Run 的人工验收入口，终止它会关闭本次启动的服务并保留真实会话，不执行微信退出登录。安装版通过 `run.sh` / `run.ps1` 启动，才启用网页中的独立 core 启停按钮。


### 厂商预设与未登录配置

厂商名称可下拉选择，也可直接输入。选择预设会填入 API 地址和协议，地址仍可编辑；切换到其他地址时清空尚未保存的 API Key 与模型选择，避免带入旧厂商内容。预设只提供连接信息，不代表各类模型能力均已适配；填写密钥后获取实际模型，不支持目录接口的厂商可手填模型 ID。各预设附官方文档入口。

开启 Web 控制台时，core 已启动后的扫码等待不受 LoginTimeout 限制；扫码暂停不会关闭后台，模型和插件配置保持可用。安装版即使 core 停止或启动失败也保留控制台，可在本页查看状态并重新启动本安装管理的 core。关闭控制台的纯 gateway 模式，以及未启用控制台 core 管理的普通嵌入式 Run，仍遵守各自原有的退出规则。


### 扫码暂停后重试

当扫码弹窗显示“登录流程已暂停”时，安装版管理员可点击“重新获取二维码”。gateway 请求当前 core 重试登录，保留原账号数据目录；新二维码在同一弹窗显示。已在线或仍在等待扫码时不会重复触发重登。外部独立运行的 core 只显示在线状态；登录、验证和启停由原程序负责。

安装版管理员还可在弹窗中明确确认“停止 core”，或在已停止、启动失败时点击“启动 core”。停止后控制台继续运行，微信消息接收暂停；重新启动使用原授权文件、版本、端口与账号目录。若要更换 Key、升级 core 版本或修改设备名称，应继续使用一键安装器的受控升级流程，不能靠网页启停完成配置更新。


### 不重启微信的前端调试

真实账号在线期间，保留 8201 的 core 与 8208 的后台进程，执行 `npm --prefix plugins/dashboard/web run dev -- --port 8209 --strictPort`，从 `http://127.0.0.1:8209` 访问支持热更新的前端。API 与媒体代理到原 8208 后台，共用已有数据和会话。8208 的内嵌前端仍是该进程启动时的版本；前端构建不会自动替换运行中的内嵌资源。

实时日志将系统日志与后台已归档的微信消息按时间合并，展示收发方向、会话、发送者、消息类型、文字内容和状态。选择“微信消息”组件可独立筛选；搜索和导出作用于全部匹配记录，列表每次展开 100 条。后台日志列表读取摘要，全文搜索在服务端匹配原文；点击详情、复制和导出时才读取完整原文。媒体只展示类型和文字说明，不把媒体二进制写入日志。此视图不补拉微信历史或绕过 core 的消息接收范围，也不记录好友验证票据。

管理员可在“系统设置 → 调试日志”将日志级别设为 `DEBUG`，随后在“实时日志”按 `DEBUG` 级别或 `debug` 组件筛选，点击记录查看和复制完整原文。默认 `INFO` 不新增这些原文记录；切回 `INFO` 立即停止新增，已有记录仍随运行日志保留，运行日志合计最多保留 2000 条。

模型日志在实际 HTTP 传输处记录请求体与未经过提示词防护、上下文输出清洗的响应体，包含完整系统提示、选用的历史/引用/记忆、工具参数和模型原始返回；流式报告记录原始 SSE 文本。任务、模型、会话及请求编号用于对应请求与响应，故障切换的各次请求独立记录。HTTP 错误记录状态码及已读取的错误正文；读取未完成或超过既有 128 MiB 流式响应上限时明确标记，不伪装为完整响应。密钥与认证头不记录，媒体和 multipart 二进制仅保留类型、大小或省略标记，不改写真实传输内容。离线 Mock 不产生模型 HTTP 原文。

手动操作与 AI 工具共用系统操作日志，记录修改群名、备注、公告、发送/撤回消息及已接通的朋友圈操作等的开始、目标、内容与成功/失败；操作编号对应开始与结果。保留原有权限校验和原始回执传递，不把撤回、好友验证或支付参数中的票据复制进日志。调试原文仅向管理员返回，非管理员仍可查看原有普通运行日志。调试日志可能包含完整聊天与提示词，只保存在本机运行数据中，不应提交到 Git。

### 状态存储与缓存清理

消息、联系人、朋友圈和任务按账号、集合及原有顺序逐条保存；日志原文单独保存。更新只写变化的记录，并与主配置在同一 SQLite 事务中提交；数据库失败不发布内存更新。内存快照复制可变容器，共享不可变文本，不再通过整份 JSON 往返复制。全局状态接口最多返回 100 条日志摘要，不携带整批 DEBUG 原文。

首次升级会在事务中将旧状态迁入新表，成功后才标记存储版本。迁移保留聊天内容、发送/撤回回执、原始日志、记忆、报告及密钥。升级前应使用 SQLite 备份接口生成一致快照，并保留 `credential.key`。回滚旧版本时先停止后台，恢复升级前数据库备份及配套密钥；不能只换回不支持分表存储的旧程序。core 账号目录不参与本次迁移。

管理员进入“系统设置 → 缓存清理”，可按全部、7 天前、30 天前或 90 天前统计并逐项确认清理：

- **控制台日志**：清理当前微信账号的普通日志与 DEBUG 原文，保留聊天归档；另留一条清理操作记录。不操作 launchd 的标准输出文件或 core 日志。
- **头像缓存**：头像仅由浏览器缓存，服务端没有独立头像文件。刷新版本后各页面绕过旧缓存重新请求，浏览器旧副本按自身策略过期，不虚构磁盘释放量。
- **文件与媒体缓存**：清理当前账号入站附件的下载副本和无引用文件，并清除相应本地缓存链接；保留原消息和下载票据，后续查看可重新下载，但微信已过期资源可能无法恢复。保护已发送素材、音色样本、垫图、表情、插件素材及其他账号引用，始终跳过最近 10 分钟的新文件，不跟随符号链接删除目录外文件。
- **洞察复用缓存**：清理本机所有账号的采集和图片处理缓存，重新分析时再采集；保留已有报告、追问和固定资料快照。此项整体清理，不按日期筛选。
- **下载临时文件**：仅清理 `.download-*.part`，始终跳过最近 24 小时的文件，不清理备份、账号、设备、凭据或原始归档。

任务运行期间拒绝清理，防止删除正在使用的资源。清理数据库记录后，空间供后续记录复用，不承诺 SQLite 文件立即缩小；在线清理不执行阻塞收发的全库压缩。


### 微信数据展示与独立 core 调试

账号头像读取 `account.photo`，经过已认证的同源图片接口加载；该接口只接受微信 qlogo.cn/qpic.cn 子域的图片，限制重定向、格式和大小。会话列表从通讯录及已归档消息合并，未知联系人不会被误标记为好友。新私聊与群会话会在后台补齐资料；首次联系人增量也会更新页面，确认好友分类后自动进入洞察候选。重连时会补取缺失头像，连续消息合并查询，失败后按限频重试。朋友圈打开时读取 core 时间线，支持刷新与向前分页；失败会展示错误，而非静默显示空列表。

已登录的独立 core 使用 `make attach` 连接。此入口不会启动或停止 core，后台可单独重启，原来的 8201 登录服务保持运行。前端开发继续使用 8209，API 代理到 8208。不得对仍管理 core 子进程的旧 `make run` 直接使用普通退出操作，否则会一并停止 core。

### 微信结构化消息展示

控制台按原始消息类型解析拍一拍、图片、语音、位置、引用、转账、红包及表情包。拍一拍中的协议账号占位符替换为通讯录名称；位置保留名称、地址及地图入口；引用单独显示来源和摘要。转账、红包展示原始通知；管理员可点击收到的卡片，查看对象后人工领取。缺失票据或未明确确认的回执不会推断为到账。

图片与语音通过登录后的媒体接口按需读取，媒体票据加密保存；语音转换为浏览器可播放格式。表情包通过受限微信图片代理读取，加载失败可重试。常用 `[微笑]` 等文字表情转换为 Unicode 对应图形，并保留原始名称提示，并非微信官方表情素材。过期或上游不可用的历史媒体可能无法恢复。

解析和桌面、移动端布局有离线回归测试；无真实样本的引用消息使用合成协议样本验证。离线验证不代表所有微信媒体均已实测。

微信普通回复会先拆除模型误加的段首 `[assistant]` 角色标签，再识别 `NO_REPLY`（含 `[NO_REPLY]`）与原因；沉默仅写入现有 INFO 判定日志，不发送到微信。只有角色标签或冒充其他角色的输出视为生成失败，沿用有界重试。普通微信表情名称、引用、代码和业务 JSON 不作为角色标签清理。已误发的沉默协议、明显回复规划不再作为后续 assistant 示例，也不计为已经回答；原始聊天归档保留。正文点名其他群友会附上“正文称呼”的弱指向线索，不冒充协议 @，不改变实际发言人或执行授权。

微信行为函数与媒体输出协议分别下发：原生函数取 core 已开放能力、AI 执行器已实现操作及后台授权策略的交集，再核对发起人、会话范围、名单和跨会话权限；常规轮次直接提供旧行为及查询工具，扩展行为先经 `actions__Discover` 获取参数，Anthropic 使用完整已授权目录。生图不注册 `image_gen` 函数，而是在聊天生图开关启用且存在可用图片模型时提供 `<image>` 输出协议，不再要求当前句命中特定关键词；是否应生图由模型结合本轮意图、否定和上下文判断，执行前仍复验开关、模型及发送权限。

未执行任何操作时，模型写出未引用的 `tool_call/function/parameter` 调用文本，或在首个结果中调用本轮未下发的函数，会在任何微信发送前作为协议错误进入已有流水线纠正。纠正禁用原生工具但保留已开放的媒体协议，避免图片请求被降级成只能文字回答；两轮失败保留人工重试入口。工具循环中已经执行的操作不重放。代码围栏、行内代码与引用中的协议示例仍保留；旧误发的伪工具文本不再作为 assistant 示范，原始归档不改动。回复依据保存实际工具名和媒体输出模式，DEBUG 同时记录“本轮实际下发能力”，便于区分未授权、未开放媒体和模型编造函数。

沉默协议按开头的独立标记解析，也支持 `[NO_REPLY] 沉默原因：…`、换行原因和枚举原因列表；INFO 日志仅记录允许的短原因，不复制附加私密正文。正常解释、引用和代码中的标记保持原样。分段正文、语音台词和原生引用内混入角色包装或沉默控制内容时，整份发送计划先失败并沿用有界纠正，不先发送前半段。群聊中，同一成员在十分钟内已互道告别、当前和候选回复都只有短告别时，发送前记录重复拦截；新问题、其他成员、游戏、明确 @/引用和混合新内容不适用。每轮上下文标明本人现实状态未知，只有本轮已确认的本人状态记忆可作依据，旧闲聊不作为线下承诺或生活状态的证据。

普通自动回复还会在任何发送前检查同份结果中的重复长段落，避免模型重复一段正文后被拆成多条发送。正文达到 80 个有效字符，且与本轮或最近十二条有效记录中的长文有较多文字重合、或共用多位数字时，只触发接续复核，不直接据相似度判错。复核沿用当前候选模型及生成时实际选中的全部上下文，核对真实发言人、已有进度、最新纠正、相互关联的数字与新增内容；用户明确要求改写、翻译、总结或引用时允许相似正文。普通短回复不会因此额外调用模型；触发复核会增加一次模型调用，用量计入统计。

复核只能返回内部裁决，不能执行工具，也不会把裁决正文直接发给微信。不通过、超时或裁决格式无效时，草稿不发送，具体纠正进入原有模型流水线；两轮都失败后保留人工重试入口。复核通过与拒绝均保留任务原因日志，原始请求和响应继续按 DEBUG 配置记录。复核期间的新来信仍须在发送前合并处理；已经执行过微信操作的工具回合不进入这条可重生成路径，防止重复执行写操作。

收到的普通文本若完整等于已有操作参数校验提示，自动回复会在确认会话已启用后跳过，并以 INFO 记录原因；不把他人转来的校验提示当作新话题或操作授权。关于该提示的真实提问、附加请求和引用消息仍按正常流程处理。

### 原生引用回复

引用回复提交原消息 ID 与回复正文，由服务端核对当前账号、目标会话、原消息状态并生成应用消息类型 57。原文加密存储，不接受浏览器提供的原始 XML 或发言人。缺少原始协议、微信消息 ID 或消息已撤回时明确报错，不降级为拼接文字。发送沿用 core `/api/message/app`，保留原始消息 ID、创建时间及 client_id 进入既有回执处理；不自动重试。core 返回非数字 client_id 时，既有撤回保护仍会拒绝，不能保证该引用可撤回。

普通 AI 自动回复已接入原生 @ 和引用，不依赖跨会话发送工具。模型可见的实际消息带短编号，例如 `〔m12ab34cd〕`；编号对应真实消息，历史裁剪不会令它指向其他发言人。模型选择 `<reply ref="m12ab34cd" mode="quote">回复正文</reply>` 发送原生引用；`mode="at"` 真正 @ 该条消息的发言人，`mode="both"` 同时引用和 @。群聊中的同名成员仍按所选消息的实际成员 ID 区分，不按昵称猜测；私聊只支持引用。 若模型直接以 `@昵称 正文` 开头，发送前读取当前群成员表，按群昵称、昵称或已核实成员的本地备注精确匹配，并补齐微信提醒 ID 与称呼分隔符。连续多个段首 @ 可同时提醒；同名、未入群、无法取得成员资料或无效目标一律停止发送，记录失败原因，不降级发送假的文字 @。正文中间提到的 @ 不自动转成提醒；手动消息、私聊与主动发言不走此兼容逻辑。无须每次使用，多人对话容易混淆或接续较早发言时优先引用，需要提醒时再 @。

服务端只解析本轮实际可见、同一会话、仍有效的非本人消息，不接受模型提供微信 ID、原始 XML、跨会话目标、本人或全体提醒。标签内只能是文字，特殊字符按 XML 转义；发送时去掉协议标签，生成真实 `mentions` / `quote_xml`，沿用现有发送策略、分条上限、回执与撤回保护。定向文字保留为文字，不转换成语音；模型沉默仍使用整段 `NO_REPLY`。未知编号、引用撤回或格式错误在外发前停止，沿用已有的有界纠正；已经开始发送的结果不自动重发。后台“主动说一句”继续只发普通文字。

收到引用后，按同一会话中的原消息 ID 打开已归档图片、语音或文件；引用链接使用协议内合法 HTTP(S) 地址。原消息未归档或已撤回时提示不可用，不伪造媒体内容。引用发送已核对 core v0.3.2 参数校验，并做协议与失败回执离线回归；未执行真实账号的引用发送或发送后撤回验收。


### 表情库：人工与 AI 共用

微信聊天输入栏的贴纸图标展开小型表情包选择器，点击图片直接发送；右下角“管理”进入上传、含义编辑和授权面板。收到的自定义表情与微信专辑表情按资源 MD5 去重，按登录账号隔离；现有归档中保留了原始协议的表情会在启动时补入。专辑分类根据 `productid` 判断。资源链接加密保存，浏览器使用经过认证的图片代理，模型只能看到 ID、名称、含义和标签。

- 可按名称、含义、标签搜索，按全部、收藏、自定义、微信专辑筛选。管理员可编辑、收藏、停用表情。
- 上传支持 GIF、PNG、JPEG、WebP，单个不超过 8 MB，保留原文件字节及动画，不统一转换为 PNG。
- “AI 识别含义”走已有识图模型流水线和任务限额，仅返回建议；动图只分析一帧。点击“采用建议”后仍需保存，不会自动授予发送权限。
- 人工发送选择库中表情，直接走原生表情接口。已收集资源使用 MD5 引用，本地上传表情携带原文件与 MD5。结果未知时停止，不自动重试或自动改成图片发送。
- AI 使用需要同时满足现有会话自动回复条件、回复策略中的“允许自动发送表情”，以及该表情已填写含义、启用且勾选“允许 AI 使用”。新收集表情默认不授权 AI，全局表情自动发送默认关闭。
- 模型使用 `<emoji id="资源MD5"/>` 选择，每轮最多一张并计入分条上限。候选最多 30 个，优先收藏和标签匹配；同一会话不连续重复上一张表情。整个回复先验证，发送前再次检查权限。

脱机 Mock 支持相同的上传、编辑与发送流程，数据在独立的 Mock 数据库；不会调用真实微信发送。正式库不会注入演示表情。图片链接失效时会提示预览不可用，可以上传同一表情原文件恢复本地预览与发送。

core v0.4.2 的 `/api/message/emoji` 接受 `receiver`、`md5` 与可选 `emoji` 文件，不接受 `productid`；专辑信息用于归档分类，不能保证发送后保留专辑归属。新版 core 返回 `revoke_client_id` 与 `revoke_create_time`，控制台归档原始回执后支持撤回；回执缺失时仍禁止撤回，不伪造字段。图片、语音、文件和引用消息的字符串回执保存在现有 `original_client_id` 归档字段中，调用 core 时映射为 `string_client_id`。已对照 core v0.4.2 参数校验并验证发送→归档→清空缓存→撤回及拒绝传播；离线结果不代表本次已完成真实账号写操作验收。


### 人工收红包与确认收款

管理员点击聊天中收到的红包或转账卡片，先查看原发送人和金额，再点击“确认领取红包”或“确认收款”。仅打开卡片不会调用微信资金接口。普通后台用户没有领取权限，AI 行为列表不开放资金操作。红包金额未在原通知中给出时不猜测金额。

服务端从当前账号、当前会话的加密归档读取原始票据，浏览器不能提供或替换领取链接、交易号。红包走 core 的接收与拆开流程，转账走确认收款接口；缺少原始票据、本人发出的通知、非待收款通知和群内转账不会发起收款。已归档但过期的红包/转账仍可能被微信拒绝，字段完整不代表仍可领取。

交易按账号和交易标识持久化去重；重复消息 ID 不会绕过去重。提交中或结果未知时不自动重试，服务重启也不重新提交。只有明确识别到业务成功码才显示“领取回执已确认”；不能识别的响应提示去微信核对。该记录独立于聊天通知，不伪造微信同步消息、金额或到账凭据。

Mock 使用独立数据库演示领取，不调用真实 Host。可选只读归档检查：`WE_CLAY_AUDIT_PAYMENT_DIR=/绝对路径/runtime/console go test ./plugins/dashboard -run TestPaymentArchiveReadOnly -v`，只输出票据完整性统计，不执行资金请求。

已对照当前 core v0.3.2 的实际参数实现 SDK、gateway 与 Dashboard 适配，并验证失败不重试、账号/会话隔离和请求去重。尚未执行真实资金验收。发红包、发转账、支付账户查询继续保留占位，不提供付款入口；兼容支付凭据生成和红包付款确认仍是待补齐的 core 契约。

### 微信置顶与群消息免打扰

联系人详情和增量资料保留置顶、群通知状态：`bit_value & 0x800` 表示置顶；`chatroom_notify=0` 表示群免打扰，`1` 表示正常通知。已用用户提供的置顶好友、置顶群和免打扰群做真实只读对照；不保存测试账号标识。置顶标志也可参考 [WeixinBot 协议常量](https://github.com/Urinx/WeixinBot/blob/master/wxbot_project_py2.7/wechat/wechat_apis.py)。

- 微信已同步的置顶状态优先于旧后台本地设置；同为置顶的会话仍按消息时间排序，不承诺复现微信自定义置顶顺序。
- 免打扰群有未读消息时只显示小红点，不显示数量。内部未读计数继续保留，查看会话后正常清除。
- 未提供字段视为未知；部分位掩码更新不能清除不相关的置顶状态。非群联系人的通知字段不用于推断群免打扰。
- 微信状态可通过通讯录刷新重新同步；已收到的联系人置顶/免打扰增量会更新后台。core 当前同步结构未单独暴露群通知专用命令，因此不能保证每次微信端更改都即时推送，可用通讯录刷新补齐。
- 群折叠样本存在额外标志，但尚未确定稳定含义，本轮不实现折叠分组，也不从免打扰状态推断折叠。

### 默认回复模式

模型中心 → 对话模型 → 全局对话设置，可分别设置好友和群聊的默认模式，初始均为人工。通讯录提供同一配置入口，并允许逐个选择默认、人工或自动。聊天标题的人工 / 自动标签显示当前有效模式，点击后成为该会话的单独设置。

未单独设置的历史暂停会话跟随默认；已有人工、自动或明确暂停设置保持原有行为（明确暂停显示人工）。公众号和系统账号不继承好友或群聊的自动默认值。继承在读取时解析，避免保存、同步或重启后固化为旧默认值。自动模式仍受自动回复总开关、生效名单规则和触发规则约束。

群聊的会话资料与专属策略支持单独设置普通群消息回复概率（0–100 的整数百分比）。默认跟随模型中心的全局群回复概率，界面直接显示当前全局数值；单独设置 0% 表示不随机回复，恢复默认会删除此项覆写。协议中真实 @ 本人、引用本群已确认发送且仍有效的本人原消息，均触发模型判断，不受普通消息概率及冷却影响；引用只凭显示名或原文内容无法获得此优先级。100% 的群消息也不受冷却限制。默认开启「群聊 @ 他人时不插话」，仅真实 @ 其他成员且未 @ 本人的消息在模型调用前跳过，优先于 100% 概率；同时 @ 本人仍触发，@所有人按普通群消息概率处理。纯文字写出的 @ 昵称不作为提醒元数据。自动模式、总开关、名单、静默时段、安全防护和调用额度仍生效。群聊原始消息先逐条归档，停顿 7 秒后合成一批交给模型；同群其他成员继续发言也延长等待，但首条消息最多等 15 秒即提交，不包含模型生成及排队耗时。100% 表示每批交给模型判断，模型判断无需回应时允许保持沉默；NO_REPLY（不区分大小写）和 [SILENT] 只作为控制标记，不发送到微信、不因此自动重试。合并消息分别保留真实发言人、时间、@ 和引用，不挤占模型设置的近期历史条数；本批之后的新消息留给下一批。模型只能以本人身份回复，正文内冒充他人的标签不能改变真实发言人。忙时已提交的批次按会话顺序排队，出队时合并同群尚未生成的排队批次，已开始生成的任务不重跑；被合并任务标明目标任务，失败后可对合并后的全部来源重试。全局生成并发仍受模型中心限制。待合并会话及等待队列各最多 256 项，额度或队列满时记录失败原因。未提交批次仅原始消息归档，重启不补发。人工接管或切换账号后不继续发送排队结果，进程重启时沿用中断标记，不自动重放旧任务。INFO 判定日志关联消息 ID，并注明 @ 本人、引用本人或普通群消息触发，以及排队、合并、跳过和沉默原因。

### 聊天标题资料

点击聊天标题可打开人员资料或群资料。群资料通过 core 的群成员专用接口读取成员头像、昵称和群内显示名，支持成员搜索、群公告查看、群备注编辑。好友资料支持添加、修改、清空备注；保存沿用既有备注接口，不修改对方微信昵称。

当前 core v0.3.2 的公开群接口尚未提供修改本人的群内昵称。资料窗口展示已读取的昵称并提示在微信中修改，不使用修改群名称接口替代，也不伪造保存成功。真实验证只读取资料；备注写入仅在用户点击保存后执行，脱机验证不代表真实写操作已经实测。


回复策略的默认名单模式为黑名单，初始黑名单为空。好友和群聊均通过同一规则判断；通讯录或会话选择自动后，无须再次添加白名单。模型中心可切换黑名单／白名单，两份名单独立保存；升级不会将旧白名单变成黑名单。此设置不会自动开启全局回复开关、改变手动会话或提高群回复概率，也不将公众号和系统账号作为自动回复目标。

### 企业微信账号分类

控制台将 `@openim` 识别为企业微信联系人，保留在聊天入口并在通讯录单列企业微信；`@im.chatroom` 按群聊展示并标记企业微信群。此分类同时处理历史归档、新消息补建及联系人同步，不依据消息是否含文章链接来判断公众号。企业联系人不冒充已确认普通好友，也不展示普通好友朋友圈入口。

现有真实账号验证中，core v0.3.2 的普通联系人详情接口对 OpenIM ID 返回 HTTP 400；现有公开路由没有企业联系人专用资料接口。页面保留已知备注、昵称和头像，未获取昵称时使用明确的类型占位名和 ID 尾号，资料浮窗说明缺失原因。不编造昵称、企业名称或宣称资料获取完成。完整企业资料同步仍依赖 core 补齐专用接口。

### 失败消息重发

本账号发送失败或结果未知的消息可通过右键菜单重发。服务端从原归档重建正文、引用、表情或本地附件，不接受客户端替换消息内容。结果未知需要用户确认可能重复送达；发送中及已成功消息不能重发。新发送收到有效回执后，原失败记录与新消息状态在同一事务中更新；再次失败时保留原记录。历史附件或引用来源缺失时明确报错。此入口是手动发送，不引入 AI 模拟延迟；不用于支付操作。验证使用脱机服务，未对真实账号发送测试消息。

### 微信回复失败重试

发送前会检查正文是否误带已知发言人的“时间＋姓名：”聊天记录前缀，或复读内部操作拒绝提示；异常结果不发送，按既有流水线切换和自动重试规则处理。普通时间表达、引用和代码块中的日志不因此拦截。近期上下文仍按模型设置选取，不修改原始归档或会话人设。

模型误调群名、公告或备注工具且当前原始消息未授权时，服务端继续拒绝执行，记录包含工具名和任务编号的 WARN 日志，并把“未执行”的结果反馈给当前模型，只允许一次正常回复纠正。纠正后仍请求工具或输出异常正文时，任务记录失败，不把固定拒绝文案当成功回复发进微信。未登记任何写操作的模型生成失败可手动重试；已经登记的写操作（包括待确认及结果未知）和安全拦截不会进入可重放重试。

微信自动回复先按模型中心配置的流水线依次调用模型，第一个失败后切换第二个，任一成功即停止。整条流水线全部失败后等待 1 秒，从第一个模型开始完整重跑一次；例如两个模型都持续失败时，调用顺序为 A → B → A → B，总共最多两轮。单模型会话最多请求两次，每次沿用对应模型的超时设置。关闭故障切换或为会话指定单个模型时，每轮只使用选中的模型。每次调用前重新验证当前账号、会话自动回复权限、原消息及资料，并重新执行提示词防护和上下文清洗。入站图片、语音识别的模型调用采用相同重试顺序；后台测活、提示词编辑和视频生成不因本功能自动重试。

两轮流水线仍全部失败时，微信会话的输入框上方显示原因和“重试”按钮。点击后使用原消息与当前模型/人设配置重新创建回复任务，重新执行最多两轮流水线；不会重复入库原消息，也不会重新执行“记住”写入。提交期间按钮禁用，后端同时拒绝对同一失败任务重复入队；会话已有更新的回复任务时拒绝旧任务重试。人工接管、关闭自动回复、微信离线、原消息撤回或删除时不允许重新生成。

微信自动回复与“主动说一句”会在每个模型返回后先执行安全检查，再检测明显失控的输出：至少 32 个非空行中有 80% 是不超过 4 字的碎片、同一行至少重复 12 次且占 70%，或短文本连续重复至少 12 次且覆盖至少 96 个字符。Markdown 围栏代码不参与检测，正常长回复不因长度被此规则拦截。这类结果即使 HTTP 成功也视为模型生成失败，未发送即按上述流水线重试，全部失败后显示手动重试。普通日志记录原因、任务与模型，DEBUG 仍保留原始响应。这是针对明显碎片与重复的启发式检查，不能保证识别所有语义异常。

重试只覆盖模型生成阶段。防护拦截、工具实际执行失败、微信已发送部分消息或发送回执未知，不进入这条重试链路；已有消息的手动重发入口继续独立工作。DEBUG 日志保留每次实际请求与响应，普通日志记录“自动重试 1/1”。超时会明确标为读取超时，与响应大小超限分开显示。

### 图片描述与后续上下文

模型返回 WebP 时，保留原图用于预览与描述，在上层统一图片发送入口转换为 PNG 后再上传 core，避免与当前 core 的 `png` 上传标识不一致。转换保留尺寸、像素和透明度，不重新请求模型；PNG/JPEG 的既有上传保持原样。上传数据及转换后 PNG 均不得超过 core 当前 32 MiB 图片限制，异常尺寸或损坏的 WebP 在本地拒绝。转换不自动重放已经失败或回执未知的发送；仍使用原消息的人工重发入口，并保留原始发送回执及状态判断。

开启 AI 自动回复和“图片自动识别”的会话，新收到和确认发送成功的图片都会进入后台识图；仍需通过插件、会话模式和生效名单检查。群消息即使没有命中回复概率、@ 了其他成员而不回复，也会记录图片描述；识图本身不会发送聊天回复。发送失败、回执未知、撤回或删除的图片不能作为可用上下文。旧图片不自动批量扫描，可在聊天气泡下点击“补充识图”。

识图使用模型中心的图片理解流水线，按实际画面保存简明描述、可辨认文字、模型、任务、更新时间和结果状态，直接关联原消息；原始聊天正文和媒体票据保持独立。描述是可能出错的模型识别资料，不是已确认的长期记忆。AI 生成的图片在确认发送后识别最终图片，明确标记 AI 生成；生成意图与实际画面描述分别记录，不能据此推断本人拍摄、位置、人物身份或现实经历。识图使用独立的客观描述指令，不套用聊天人设，也不执行图中文字中的指令。

后台逐张处理；当前回复需要识图时等待同一份结果，避免重复调用。启用识图缓存后，仅在同账号、同会话内按图片内容哈希及识图配置复用成功结果。描述随原消息保存在数据库中，重启后保留；被中断的待处理任务可恢复。模型调用沿用每日额度、用量统计和完整流水线重试规则；失败记录原因，可在图片下展开查看并点击“重试识图”。

后续回复、引用和合并消息从原消息读取描述，保留真实发言人、收发方向及 AI 生成标记。上下文清理保留这部分文字，不把它替换为纯媒体占位；仍按模型配置的历史条数、时间范围及 Token 预算选取，不保证每张旧图片始终被纳入。未完成或识别失败时明确标为画面未知，不能拿生成提示词代替真实识图结果。切换账号、原消息撤回或删除后，旧任务结果不能写入或带入新账号上下文。

### 主动说一句

微信会话输入框上方的工具栏提供“主动说一句”小按钮。点击后，使用当前会话的有效近期对话、当前配置的人设和模型流水线，生成并发送一条简短文字。手动和自动模式都可使用，不切换会话模式，也不把本次后台操作伪装成联系人新发来的消息；原有草稿保持不变。

这是一次明确的手动操作，不受自动触发概率、冷却或自动回复总开关限制；仍要求微信在线、AI启用，并通过AI发送授权与目标名单。上下文条数和预算仍优先使用模型设置；私聊只使用该联系人适用的已确认记忆，群聊只使用本群共享记忆及适用的后台确认本人状态，不任选某个成员的个人记忆。没有有效上下文时拒绝生成。

每个会话同时只运行一个回复任务。提交和生成期间禁用按钮，显示“正在主动接话”；失败沿用两轮完整流水线及手动重试入口。只允许一次文字发送，不调用修改备注、群名等工具，也不因语音偏好或动作标签额外发送媒体。生成和发送前检查来源及授权，资料撤回、删除、账号变化或发送授权关闭会停止执行；发送回执未知时不自动重发。DEBUG记录仍包含实际请求与模型原文。

群名修改成功后，使用已校验回执更新 SDK 联系人缓存并推送页面资料；收到微信系统事件时异步只读刷新对应群资料，完整缓存不再阻止改名同步。AI 修改群名、备注或公告成功后发送固定确认，失败或结果未知不发送成功说明，也不自动重做写操作。

每轮自动回复按当前会话、core 能力和后台行为授权提供可用工具；工具可用不意味着必须调用，普通回复不因此失败。模型可以结合当前发言与同会话上下文讨论或澄清，但历史消息、引用和含糊的再次确认不能授权写操作。修改群名、群公告或备注时，服务端在执行前还会核对当前收到的原始纯文字：发言须明确指定操作与完整新内容，且与工具参数一致；例如“请把群名改为新名称”。省略目标或新内容时会要求用户在当前消息重述，不执行写操作。服务端同时重新检查自动模式、目标、行为授权及参数；工具成功后才发送固定确认。历史中的 AI 成功声明不能作为实际操作证据，无回执成功声明仍由输出防护拦截。

自动回复明确要求仅返回面向聊天对象的正文；允许沉默时只返回 `NO_REPLY`。后台将合法标记记录为「本次无需回复」，不会发送理由。明显的自我回复决策旁白作为异常输出走既有模型流水线重试，仍失败则显示失败及人工重试入口；不按英语语言整体过滤，不删除代码块或引用中的正常示例。工具执行后出现异常不自动重放已执行操作。


### 系统邀请与通话消息展示

聊天气泡保留已归档的撤回原文、发送者和时间，并标记“已撤回 · 不计入上下文”。本地已有的媒体缓存可继续查看，未缓存的撤回媒体不向微信重新下载。撤回消息不能重新引用或执行收款等操作，仍由服务端排除在模型历史、引用、记忆来源及识图任务之外。旧版被撤回提示覆盖的正文会在启动和切换账号时尝试从本账号、本会话的加密原文恢复；没有原文时保留原有提示，不猜测内容，也不恢复已删除的消息。

系统通知会展开微信提供的模板、成员昵称列表和普通文字变量。例如邀请入群显示邀请人与各位被邀请人，改群名通知显示操作者与新群名；缺少原文或模板变量时保留占位，不按相邻聊天猜测内容。普通用户粘贴同样的 XML 仍作为文字处理。

SDK 标记的 VoIP 通话消息使用独立气泡展示电话图标和原始可读状态，如“对方已取消”“通话时长 00:30”。`room_type=1` 显示为语音通话，其余未知类型保守显示通话。房间号、roomkey、身份标识及其他控制字段不进入气泡展示字段；通话记录不触发普通 AI 自动回复，也不提供未接通的回拨、引用或撤回入口。

启动及切换账号时，会利用本账号已保存的加密原文恢复旧系统占位和误标为文字的通话。旧通话还必须通过 SDK 原始消息类型校验；保留原消息 ID、时间、撤回状态与加密原文，不重放欢迎消息或其他操作。无法恢复的记录继续保留。

### 群聊回复纠正与沉默

模型输出中明显对本人昵称说“你……”的身份串用、未开放的图片／语音标签会在发送前拦截，沿用完整模型流水线最多重试一次；纠正请求只允许文字或沉默，不执行新的操作。尚无任何写入或待确认操作时，工具引用无效可反馈同一模型纠正一次；保留工具错误回执，必要时裁剪较早聊天，为纠正留出上下文。已执行、待确认或状态未知的操作不会重放，权限和安全拒绝不自动放宽。沉默任务在任务结果和 INFO 日志中标明“无需回复”，技术失败保留独立错误原因。

历史按真实角色发送：群友记录为 `user`，本人已发送正文为 `assistant`，引用和记忆继续作为资料。群友正文里的“某某：”不会改变真实发言人；称呼按最新已知姓名展示，多行正文保持缩进。每条记录中的“我”属于该条实际发言人，“你”结合其 @、引用与正文称呼确定，不默认都指向本人。

后一批来信可能早于前一批回复送达，构造上下文时保留来信后实际发送的本人回复，并提醒模型核对已回应内容；后续尚未处理的群友来信留给下一批。近期历史条数和预算继续使用模型设置。普通群聊单条文字在发送前对照三分钟内最近八条本人已发文字，拦截明确重复或高度相似的复读，并记录来源与“重复拦截”原因；短答复、数字或否定变化不做近似拦截。直接 @、引用、主动发言和工具结果不受此项拦截。

自动回复生成后仍按草稿处理。群聊与私聊在生成期间收下的新一批来信，会与尚未发送的原批次合并，作废旧草稿，按最新发言重新生成；原始消息仍逐条归档，操作授权绑定合并后的末条真实消息。补充沿用停顿 7 秒、最多等待 15 秒的合并规则，已收下的补充不因前一轮刚结束的冷却而丢弃。每个任务最多刷新两次，持续有补充则移交下一批等待，日志记录作废、合并或延后原因。发送前再次检查；如果一部分已经发送，收到补充后停止后续段落，已发部分不自动重放。已经进入工具执行的任务不因新来信重新生成或重跑操作，后续消息另行处理。本机制不识别固定的接龙年份或句式；轮次和补完含义由模型根据实际发言判断，不能保证不同机器人之间严格轮流。

### 不回复原因日志

自动回复的规则跳过、合并等待、模型主动沉默、撤回／人工接管／账号切换取消及生成或发送失败，均关联会话、消息 ID 和任务 ID 写入日志；普通决定为 INFO，失败为 WARN／ERROR，无需开启 DEBUG。日志页可按会话、消息 ID 或任务 ID 搜索。模型沉默可返回 `NO_REPLY: 非本人对话`，原因只选「非本人对话、重复附和、话题已结束、已有人回答、无需补充、信息不足」之一；程序只写日志，不发送控制标记和原因到微信。兼容不带原因的旧标记，无法识别原因时如实记录「模型未提供具体原因」，不推测或保存推理过程。INFO 判定采用独立的日志增量事务，不重复复制、遍历或保存聊天归档；数据库写入失败时不发布虚假成功记录。

未开启智能回复（总开关／AI 插件关闭、会话处于人工或暂停模式、未通过名单或关闭私聊触发）的消息不记录例行判定日志；日志页及状态摘要也隐藏旧版已产生的对应跳过记录，不删除原始日志。已经开始的回复任务因接管而取消、模型沉默或执行失败，继续保留结果及原因。

### 业务插件群聊触发与宽松点歌

点歌、新闻、统计、词云、摘要、表情、吃什么及摸鱼日报等关键词插件，默认开启“群聊触发必须 @ 本人”，各插件可独立关闭。游戏插件同样提供此开关，仅限制开局或重新触发，局内参与操作保留既有规则；海龟汤沿用原“群聊开局必须 @ 本人”配置。私聊、工作台、定时任务、系统入群欢迎和好友申请不受此项影响。只核验协议中的当前账号 ID；手写 @ 昵称、@ 他人或 @所有人不能替代。未满足要求的口令保留归档并记录原因，不执行插件，也不交给普通聊天 AI 兜底。

点歌接受逗号、冒号、空格分隔，支持歌手加歌名。明确点歌时不再将“故事”“秘密”等合法歌名当作普通聊天排除；自然句式仍避开语音、故事等非音乐意图。风格、心情或随机选曲使用模型中心对话流水线，选出具体歌曲后再从真实音源搜索，只发送第一首可播放结果。详见[音乐插件](音乐插件.md)。

朋友圈消息列表只展示互动提醒，不批量展开动态，也不因打开列表而清除未读。点击具体提醒后按当前账号的通知编号加载唯一关联动态；读取成功后仅将该条标记为本地已读，并同步入口角标。动态读取失败保留未读；其他提醒和后来到达的通知不受影响。

朋友圈顶部提供“随机点赞”和“随机评论”，仅管理员点击后执行，后台按发布时间从新到旧分页读取微信可见动态。模型中心 → 全局对话设置 → 朋友圈随机互动中可配置：点赞概率默认 80%，评论及后续回应概率默认 50%，追溯时间默认 24 小时，评论间隔默认随机 15–30 秒。概率为每条独立判断，不保证一批数量严格等于百分比；0% 不互动，100% 仍跳过本人动态和已完成的互动。追溯按发布时间计算，任务启动后的新动态留给下次点击。

随机评论复用 AI 留言资料与模型流水线：读取文字、缩略图、作者昵称、全部可见评论及适用记忆，不给模型操作工具；生成合格文字后直接发送。本人已点赞不会取消或再次点赞，本人已有任何评论则不再追加普通评论；写入前在实际详情中再次校验账号和已有互动。后台进度显示已检查、成功和跳过，可停止；关闭页面不停止，服务重启不自动续发。提交前记录按账号加密的操作意图，未知回执停止任务且不自动重发。

“对方回复后按概率回应”默认开启，可单独关闭。后台每分钟检查真实 SNS 回复通知，只处理功能启用后对本人评论的明确回复；每条通知只判定一次，未命中概率也不因再次轮询重抽。命中时使用对应评论编号定向回复，沿用评论间隔；只支持当前 core 可确认的 32 位评论编号，编号或回复对象缺失时不猜测、不降级为普通留言。已有同一条定向回复则跳过。不会因浏览或回复将通知自动标为已读，仍遵循用户点击提醒后的逐条已读规则。

通讯录新增“好友申请”页签，管理员可以搜索、按状态筛选，查看完整附言、申请人昵称与微信 ID、头像、来源场景、收到时间及微信返回的所有非凭据字段。验证票据只在服务端按账号加密保存，不返回页面，不进入普通聊天归档或日志；附言保留换行，不截断。旧版申请只能显示当时已经保存的资料，缺失的历史附加字段不猜测。

页内支持手动通过及“自动通过设置”，与 `auto_accept` 插件共用开关、名单、关键词、来源场景和延迟；不创建另一套配置。延迟默认沿用 10 秒，可设置整数 0–86400 秒。只有新收到且命中规则的申请才安排自动通过，启用开关不批量处理历史待办。等待期间可手动通过，到期重新核实申请状态、账号代次及当前规则；关闭自动通过或切换账号后不执行旧任务。服务重启不自动恢复等待申请，列表保留待处理提示。

手动、自动和 AI 通过共用一次性处理凭据，防止同一申请重复提交；申请已通过仍保留历史，不删除申请记录。通过回执未知时显示“结果待核对”并保留原因，不自动重试。申请详情接口仅管理员可用，网页只能提交本账号保存的申请编号，不能指定票据、来源场景或另一个账号。

好友申请卡片右上角提供“×”关闭本地待办，适用于已经在手机处理的申请。关闭后从默认列表隐藏，不计入待处理数；申请记录保留，可在“已关闭”筛选中查看及恢复，也可立即撤销关闭。关闭会取消尚未提交的自动通过，恢复显示不会重新安排自动通过；未知结果的原状态仍保留。正在提交验证时不能关闭，同一凭据的重复通知不会复活已关闭申请。
